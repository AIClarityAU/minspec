# DR-087: Integrity words are claims, and three of them are forbidden

## Context

An adversarial analysis of append-only log integrity was run to answer one question:
if MinSpec kept a Karpathy-style `log.md`, how strong an integrity guarantee could it
actually carry? Three
candidate designs were built and each was handed to an independent red team whose
findings overrode the designs' own self-assessments. The full working is at
`docs/research/log-integrity-2026-08-23.md`.

The engineering answer was "no, and here is the line". The more durable result was
about **vocabulary**, and it applies whether or not a log is ever built.

Three things were demonstrated rather than argued:

**A signature binds content to whoever holds the key.** A three-commit SSH-signed
history was rewritten with a re-signing commit filter. Every commit still verified
as a good signature. Separately, a key was loaded into an agent, the private key
file was deleted from disk, and the agent signed attacker-chosen content anyway,
verifying cleanly. A key the writing process can *use* is a key the adversary has,
so non-extractable is not unforgeable.

**The strong property is structurally unavailable locally.** A self-contained log is
a function of its own bytes and verification is a rule applied to those bytes, so
whoever holds both can rewrite the log and recompute every hash, or replace the rule
with "always pass". The strongest honest local property is *tamper-evident below an
independently held mark*, and even that is blind to an entry that was never written.

**An absent witness is not a pass.** Measured breaks included a verifier that printed
success with no witness present and one that exited zero on a truncated tail. Each
converts a gate into a green light over a forged artifact, which is
`.minspec/constitution.md` invariant 2.

This repo has already made this exact error once, in the opposite direction: a
`bodyHash` was believed to resist forgery on a public repo, and the root cause
recorded then was that **a hash binds content, never authorship**. That finding was
left as prose. Prose is model-trusted and drifts, which is the failure mode the
constitution names.

## Decision

**MinSpec does not get a wiki-style `log.md`.** The approval sidecars under
`.minspec/approvals/**` are committed, content-addressed, recoverable from git
history, and held back from agent auto-merge so a forged one still needs a human
merge keystroke. That is a stronger record of the same events than a markdown log
would produce, and two sources of truth about approvals is worse than one.

**Three words are forbidden in MinSpec artifacts:** `tamper-proof`,
`non-forgeable`, `non-repudiable`. In a product whose entire pitch is that the
signpost never lies, a false claim of a property is the defect, not a marketing
imprecision. Where an integrity property must be described, describe what enforces
it and what defeats it in the same sentence.

**A hash binds content, never authorship.** Any artifact, prose or code comment that
presents a hash or a signature as attribution is wrong and should be corrected on
sight. Attribution requires an identity the writer cannot mint, which in a local
offline tool does not exist and in a hosted system comes from the identity provider.

**If an integrity verifier is ever built, three rules bind it.** An absent witness
reports its own absence and is never a pass. A verifier never stops at the first
failure, because a single early break hides every later one. No gate keys on a
verdict string alone.

## Consequences

Artifacts gain a small vocabulary constraint and lose the ability to describe
integrity work in the terms the wider field uses, which will occasionally read as
pedantic to an outside reader. That is the intended trade: the words are load-bearing
here in a way they are not elsewhere.

The decision not to build a log costs the greppable narrative record the pattern was
meant to provide. The mitigation is that a legitimate append touches zero existing
lines, so `git diff -U0 <file> | grep '^-'` returning anything at all is a
deterministic signal that something other than an append happened. That is one line
in a hook, it is chain-independent, and it survives most of the attacks the red teams
found.

This DR is prose enforcing prose, which is precisely the failure mode
`.minspec/constitution.md` warns about. It is therefore incomplete until the grep
gate in the follow-ups below exists. Until then, treat it as a convention that will
drift.

## Follow-ups (tracked)

- Grep-level check rejecting the three forbidden words in `specs/**`, `docs/**` and
  harness templates, wired as a numbered rule in `scripts/validate-frontmatter.ts` so
  the convention can actually fail: **#1683**
- Enable `non_fast_forward` and `deletion` on the default-branch ruleset, which is
  the only measure on the analysed ladder that protects anything today and is
  currently absent: **#1683**
- The four untracked `.minspec/*.log` and `.jsonl` files have no tamper-evidence at
  all. Chaining them buys integrity against accident and non-adaptive bugs, and
  nothing against the process that writes them. Deliberately **not** filed as work:
  recorded here so a future reader knows it was considered and priced.
