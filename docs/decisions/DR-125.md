# MinSpec's automation no longer targets AIClarityAU/scroogellm

> **Born `proposed` per DR-029.** Acceptance is a separate human act (*MinSpec: Accept
> ADR*). This record writes down a decision the founder already gave verbally and that
> #2064 already acted on. It changes no code. Until it is accepted, the only evidence for
> the decision is the founder's words as quoted in #2064's commit body; no human has
> signed this text.
>
> **On ids in the prose.** Record ids at or above one hundred appear only in the
> frontmatter, because the parent-register gate reads them in prose as parent-register
> references (#2148), the same workaround the other recent records use.

## In plain terms

On 2026-09-22 the founder told the agents to stop building ScroogeLLM and to take it out
of the drain. #2064 did that in code: the tooling radar no longer files issues into
`AIClarityAU/scroogellm`, and the primaries-clean staleness report no longer inspects that
checkout. Four code comments explain the removal, but each one only states the date.
This record is the one place those comments can point to.

## Context

On 2026-09-22 the founder told the agents, verbally, to stop building ScroogeLLM and to
remove it from the drain. #2064 acted on that: the tooling radar no longer files into
`AIClarityAU/scroogellm`, and the primaries-clean report no longer inspects its checkout.
The instruction left no committed record, so four code comments carry the date with
nothing to cite. This record is that citation. It changes no code.

- **What was already decided elsewhere.** DR-027 moved ScroogeLLM into its own private
  repo with its own register. DR-075 (accepted 2026-08-01) closed portfolio monetization
  and notes that ScroogeLLM is shelved *as a product* by its own register's DR-021
  (cross-project: `SCR/DR21`, scroogellm#122). That shelving kept the measurement
  instruments (tee proxy, shadow classifier, safe-cut, scrooge-delegate) live, so it did
  **not** stop work in the repo. Nothing in this repo's register records the later step.
- **The later step.** On 2026-09-22 the founder said, verbatim per #2064's commit body
  (645b68e2f): "stop building scroogellm", "remove scrooge from the drain". The
  instruction was verbal, so it left no committed record.
- **What acted on it.** #2064 (merged 2026-09-22 20:43 UTC, 645b68e2f):
  - `scripts/tooling-radar/file-findings.mjs` - removed the `scrooge` row from
    `CATEGORY_REPO`. An unmapped category makes `planFinding` throw, which aborts the run
    before anything is filed (fails closed and visibly, invariant 2).
  - `scripts/tooling-radar/radar-prompt.md` and `scripts/tooling-radar/README.md` - the
    category is no longer offered, and the closed enum is `minspec` / `sealbox`.
  - `scripts/check-primaries-clean.sh` - dropped `$CODE_ROOT/scroogellm` from `REPOS`.
    The script only produces a diagnostic report, and no gate reads it.
- **The gap this closes.** The architect voter on #2064 flagged (non-blocking, `low`) that
  the four comments state a date and a decision with no linkable source. A decision that
  exists only as repeated prose drifts, and a later reader cannot tell a recorded
  decision from a remembered one (traceability convention; DR-023 "prose-only
  consequences are a leak").

## Decision

1. **No MinSpec automation targets `AIClarityAU/scroogellm`.** No issue filing, drain
   routing, or staleness report in this repo points at that repo or its checkout. This
   covers the paths #2064 changed, and any new automation surface added later.
2. **Cost and measurement findings stay actionable, filed under `minspec`.** The founder's
   core-tenets review (2026-10-17) made "minimise tokens" a core tenet, so a token or cost
   finding from the tooling radar is filed under category `minspec` and may carry
   `act: true`. That reverses the watch-only treatment #2064 first gave such findings.
   This record does not change the reversal. It only records that the repo is not a
   filing target, whatever the finding is about.
3. **Restarting is a new decision, not a repair.** Adding back the `scrooge` row, the
   prompt category, or the `REPOS` entry means restarting work on that repo. It needs a
   record that supersedes this one. A stale radar scan that still emits `scrooge` failing
   the run is the designed behaviour, and the fix is to correct the scan, not the routing
   table.
4. **Scope.** This record is about *MinSpec's automation*. It does not decide anything
   inside the scroogellm repo, whose own register governs it (DR-027). Hand-run work
   there, such as the live measurement instruments, is unaffected. The CLAUDE.md
   pointers that tell a session to do scrooge work in that repo stay as they are.

## Rejected alternative

- **A pinned GitHub issue as the canonical home.** Cheaper and faster. Rejected because
  issues record what needs doing, not why a choice was made. The rationale would sit in
  the wrong register, and someone reading the decision history would be less likely to
  find it. (Issue #2065 marked the decision-record option as the recommended one.)
- **Leave the comments as they are.** Costs nothing now, but keeps the defect #2065
  names: four copies of an uncited claim that can drift apart independently.

## Cost and risk

- It spends a record number and a few minutes of founder review on a one-line policy.
- If scroogellm work resumes, this record has to be superseded (Decision item 3) rather
  than a comment simply deleted. That is intended: restarting is a decision.
- Until it is accepted, the record repeats the verbal instruction rather than ratifying
  it. A reader should treat #2064's commit body as the primary evidence.

## Rollback

Set this record `superseded` (or delete it while it is still `proposed`), and revert the
comment edits that cite it. No code behaviour depends on this record, so rollback takes
under a day.
