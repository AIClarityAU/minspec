# DR-082: One code licence, MIT — supersedes DR-018's multi-licence scheme

## Context

[DR-018](DR-018.md) split the repo three ways: **MPL-2.0** for `packages/shared`,
**MIT** for the extensions and tooling, **CC-BY-4.0** for prose. The split existed to
protect one thing, and DR-018 says so plainly: `packages/shared` is *"the project's core
IP (the classifier is the differentiator over GitHub Spec Kit)"*, and file-level copyleft
was chosen so *"forking the classifier into a proprietary product now requires publishing
changes to the shared source files"*.

Three things have since made that premise false, and the pre-public sweep for
[#1171](https://github.com/AIClarityAU/minspec/issues/1171) forced the question by
surfacing the repo stating two different licences for the same code.

**1. The protected asset is not in the protected package.** DR-018 licensed
`packages/shared` to guard the classifier engine. The classifier engine is not there. It
lives at `packages/minspec/src/lib/classifier.ts`, under **MIT**, and has since DR-014's
move to `shared` was recorded as `proposed` and never executed (tracked: #54). What
`packages/shared` actually contains today is contract types, `canonical.ts`, `next-task.ts`,
`project-prefix.ts`, `review-signals.ts`, `rework.ts` and `trust-model.ts`. The copyleft
has been guarding the wrong directory for over two months. Anyone wanting to fork the
classifier could already do so under MIT without publishing a line.

**2. The classifier is not the differentiator DR-018 priced it as.** [DR-021](DR-021.md)
— titled *"Classifier is a ceremony floor, not a difficulty detector"* — records the
DR-009/SPEC-004 validation outcome: *"cognitive difficulty is orthogonal to diff size"*,
and a tier *"measures mechanical scope — not difficulty"*. Its Decision 5 deleted the
scoring thresholds outright because SWE-bench validation (n=120, κ=0.80) showed tuning
size thresholds was *"the wrong axis"*. DR-018 wrote its copyleft around an engine it
called the differentiator over Spec Kit; DR-021 establishes that the engine measures
something narrower and more mechanical than that framing assumed. A ceremony floor is
useful. It is not an asset warranting a bespoke licence scheme.

**3. Solo mode reframed the goal from protection to gift.** [DR-075](DR-075.md) and
[DR-076](DR-076.md) (accepted 2026-08-01) settled that MinSpec is a solo-first personal
tool, open-sourced **as a gift, with no publish deadline and no commercial position to
defend**. DR-018's negative case against MIT — *"leaves the classifier (core IP)
unprotected against closed forks that give nothing back"* — presupposes a competitive
posture the project has explicitly abandoned. There is no revenue line, no adopter
funnel, and no rival whose free-riding costs anything.

The immediate trigger is narrower and mechanical. The #1171 sweep changed the root
`LICENSE` to MIT while `packages/shared` stayed MPL-2.0, producing a repository that
states two contradictory licences for the same source. **A repo that cannot say what
licence it is under must not be published** — for a project whose entire positioning is
that its artifacts do not lie, an ambiguous licence is the defect, not the inconvenience.
The contradiction is resolvable in either direction; this DR records which one, and why.

## Decision

**All code in this repository is MIT.** `packages/shared` is relicensed from MPL-2.0 to
MIT. The root `LICENSE` carries the MIT text directly rather than a multi-licence map.

| Artifact | Licence | Change |
|---|---|---|
| `packages/shared` | **MIT** | **was MPL-2.0** |
| `packages/minspec` | MIT | unchanged |
| `packages/extension-pack` | MIT | unchanged |
| `scripts/`, root tooling | MIT | unchanged |
| `docs/`, `sites/` copy, whitepaper | **CC-BY-4.0** | **unchanged — see below** |

SPDX `license` fields: `packages/shared` → `MIT` (was `MPL-2.0`), root `package.json` →
`MIT` (was `SEE LICENSE IN LICENSE`, which pointed at a map that no longer exists).

### Prose stays CC-BY-4.0, deliberately

`LICENSE-CONTENT` is untouched. "All code is MIT" is not "everything is MIT" — a code
licence and a content licence coexisting is ordinary practice, not a contradiction, and
CC-BY-4.0 remains the right instrument for prose. DR-018's reasoning on that row was
never in dispute and is inherited intact. Only the MPL-2.0 row is reversed.

### The MPL consumer apparatus is removed, not left dangling

Relicensing `shared` makes an entire scaffold obsolete, and leaving any of it in place
would be a licence claim the repo no longer means:

- `packages/minspec/LICENSE-THIRD-PARTY-MPL-2.0.txt` (the bundled MPL text) — **deleted**.
- `packages/minspec/THIRD-PARTY-NOTICES.md` — its `@aiclarity/shared — Mozilla Public
  License 2.0` section, including the MPL §3.2 source-availability offer, is removed.
- `README.md`, `packages/minspec/README.md`, `docs/epics/EPIC-006-*.md` licence tables and
  paragraphs — updated.

## Consequences

**Positive:**

- One licence for all code. A consumer reads one file and is done; there is no dependency
  edge to reason about and no §3.3 "Larger Work" analysis for anyone bundling the packages.
- The `LICENSE-THIRD-PARTY-MPL-2.0.txt` + `THIRD-PARTY-NOTICES.md` apparatus, and the MPL
  §3.2 obligation to keep source available for the bundled files, both disappear from the
  shipped `.vsix`.
- The repo stops contradicting itself, which is the precondition for #1171 going public.
- MIT matches the ecosystem MinSpec sits in — spec-kit, OpenSpec and OmniRoute are all MIT
  — so the gift arrives with the friction its recipients expect.

**Negative:**

- **This is one-way and this DR is the point of no return.** MIT cannot be tightened back
  to MPL-2.0 for any version already published. If `@aiclarity/shared` later grows into
  something genuinely worth protecting, the protection is no longer available for the code
  released under this decision — only for future files, and only with a further DR. DR-018
  called the MPL choice *"effectively permanent once npm publish happens"*; the reverse
  move is permanent from the moment this lands, publish or not, because the grant is in
  the repo.
- Improvements to `packages/shared` made in a downstream fork can now stay closed. Given
  points 1-3 above the practical loss is close to zero, but it is a real right being given
  away, not merely a formality being tidied.
- DR-018's package-licence lint follow-up (never built) is now moot rather than done. If a
  future package wants a non-MIT licence, nothing mechanical will catch it — the rule is
  prose again, which the constitution's *"enforce, don't trust the model"* warns will drift.

**Neutral:**

- No published artifact is affected, verified rather than assumed:
  `packages/shared/package.json` carries `"private": true`,
  `registry.npmjs.org/@aiclarity/shared` returns **404**, and the Marketplace listing for
  `aiclarity.minspec` returns **404** (checked 2026-08-12). There is no shipped version
  whose terms change under a consumer. The one-way door is being walked through before
  anyone is standing on the other side, which is the cheapest possible moment for it.

## Alternatives considered

- **Keep the multi-licence scheme; revert the root `LICENSE` to the map.** Also resolves
  the contradiction, and cheaper. Rejected because it preserves ceremony for a benefit that
  reasons 1-3 show does not exist: copyleft on a package that does not contain the asset,
  guarding a differentiator that measurement refuted, for a commercial position solo mode
  abandoned. It would leave the MPL third-party notices shipping inside a `.vsix` for a
  dependency nobody needs to be warned about.
- **Move the classifier into `packages/shared` first, then keep MPL-2.0.** Makes DR-018's
  premise true rather than abandoning it. Rejected on reason 2 — the engine being moved is
  the one the validation study found measures the wrong axis — and reason 3: it protects
  a market position the project does not want.
- **Apache-2.0 everywhere.** Permissive with an explicit patent grant, a genuine upgrade
  over MIT on that one axis. Rejected for ecosystem fit: every comparable SDD tool is MIT,
  and there are no patents to grant.

## Risks & Mitigations

| Risk | Mechanism / anchor | Mitigation |
|---|---|---|
| A stale MPL claim survives somewhere and the repo still contradicts itself | The MPL scaffold spans a licence file, a notices doc, two READMEs, an epic, a test fixture list and a source comment | Every occurrence was enumerated with `git grep 'MPL-2\.0\|Mozilla Public'` before the edit and re-run after it. The remaining hits are all deliberate: DR-018 and this DR (the historical record), the notices doc and `packages/minspec/README.md` (which explain what lapsed), `EPIC-006`/`INDEX.md` (DR-018's title, now carrying a superseded pointer), and `package-lock.json` (third-party dependency metadata, correctly untouched). **Zero remaining hits assert a live MPL licence on MinSpec code** — that is the property checked, not the raw count |
| The relicense is treated as reversible later | MIT→MPL cannot be applied retroactively to a released grant | Recorded explicitly in Consequences (Negative) and in this row, so a future reader meets the one-way property before proposing the reverse |
| Prose silently drifts to MIT because "everything is MIT now" | `LICENSE-CONTENT` (CC-BY-4.0) is unchanged, but the shorthand invites the error | The Decision table keeps the content row visible and states the distinction; DR-018's content reasoning is inherited rather than deleted |
| DR-018 is read as still in force | It is `status: accepted` and cited from `INDEX.md`, `EPIC-006` and two READMEs | DR-018 flipped to `status: superseded` with a pointer blockquote in the same commit as the file changes, so the register and the tree land together |

## Costly to Refactor

**One-way for the code released under it.** Everything mechanical here is a <1-day edit
— SPDX fields, `LICENSE` files, the notices doc, the README tables. The grant is not.
Once this lands on `main`, every commit reachable from it carries an MIT licence for
`packages/shared`, and a later DR could only apply MPL-2.0 to files written after it.
Per the ADR filter this is firmly DR-warranting: the edit is undoable, the grant is not.

The mitigating fact is timing — nothing is published yet (see Consequences, Neutral) —
which is precisely why the decision is being taken now rather than deferred.
