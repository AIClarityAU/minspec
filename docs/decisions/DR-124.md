## In plain terms

When you approve a spec, or accept a decision record or epic (Alt+A), MinSpec now makes
a git commit holding the flipped document and its approval record, and nothing else. It
never pushes. If you do not want that, turn off `minspec.commitOnApprove`.

## Context

SPEC-022 FR-1 (`specs/minspec/SPEC-022-approval-foundation/requirements.md:77`) says
approval ground truth is **committed** to the repo. Before #576 the approval record was
only git-*tracked*: written to disk and left in the working tree. Nothing committed it.
So an approval could sit uncommitted indefinitely, be lost to a checkout or a reset, or
be swept into an unrelated commit by another session. "Committed ground truth" was a
claim the code did not keep.

## Decision

1. **Approve commits.** Approving or accepting writes the status flip and the approval
   record, then commits exactly those files in one dedicated commit
   (`packages/minspec/src/lib/approve-commit.ts`, called through
   `packages/minspec/src/commands/commit-on-approve.ts`).
2. **Default on.** The setting `minspec.commitOnApprove` defaults to `true`
   (`packages/minspec/package.json`, `minspec.commitOnApprove`). Reasons: the approval
   is the one artifact whose whole value is that it is durable and attributable, so
   leaving it uncommitted defeats it; the commit touches only the approval's own files,
   so it surprises nobody's other work; and a default-off setting would leave the
   failure silent for exactly the users who never find the setting (tenet 1, make the
   founder's job smaller: no manual commit step after every approval).
3. **The setting is the opt-out.** Turning it off leaves approvals written and staged
   for the user to commit by hand. Nothing else disables the behaviour.
4. **Commit only, never push.** The commit is local. Invariant 1 (no network call
   without consent) means getting it to a remote is a separate, consented step governed
   by `minspec.pushOnApprove` (default `prompt`), not part of this decision.

## Never-wrong constraints

These are the conditions under which a commit would be wrong, and each is enforced in
`approve-commit.ts` rather than trusted to the caller.

- **Pathspec safety.** The commit is `git commit -- <exact paths>` with
  `GIT_LITERAL_PATHSPECS=1`. A bare `git commit` would bundle whatever another
  concurrent session had pre-staged in the shared index; a path with a glob character
  (`[ ] * ?`) would otherwise match a foreign sibling file. `git add -A` and a bare
  commit are forbidden here.
- **Detached HEAD refused.** A commit on a detached HEAD is unreferenced, and a later
  checkout silently discards it, losing the approval. The helper returns
  `detached-head` and never reports `committed`.
- **Unstage on failure.** `git add` touches the shared index. If the commit then fails
  (for example a pre-commit hook rejects it), the helper resets those exact paths so a
  failed approval does not leave files pre-staged for another session's commit to sweep
  up.
- **Destination resolved before writing.** On the push-protected default branch the
  helper refuses up front with `protected-branch` and stages nothing (#1064), because
  that commit could never be pushed. Unknown destinations fail open, not closed.
- **Mid-merge or cherry-pick is reported, not hidden.** Git itself refuses a partial
  commit then, so the helper returns the distinct `merge-in-progress` outcome (#1112).
- **Never rejects, never claims falsely.** Every failure degrades to a typed outcome the
  command layer shows in the same toast as the approval. The record is already on disk,
  so a failed commit means the user commits it, never that the approval is lost.

## Alternatives rejected

- **Leave approvals uncommitted (status quo).** Fails SPEC-022 FR-1's committed ground
  truth and strands approvals.
- **Default off, opt-in.** Reproduces the status quo for everyone who does not find the
  setting.
- **Commit with a bare `git commit` or `git add -A`.** Sweeps in other sessions' staged
  work.
- **Commit and push together.** Violates invariant 1 without a consent click.

## Cost accepted

An approval now creates a commit the user did not type, and the commit runs their git
hooks (a slow or rejecting hook can fail it; the failure is surfaced, not hidden). A
user who wants full manual control must turn the setting off.
