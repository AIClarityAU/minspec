# DR-093: A gate may produce the witness it consumes, inside a stated boundary

> **Born `proposed` per DR-029.** Acceptance is a separate human act
> (*MinSpec: Accept ADR*); an agent never mints the sign-off.

> **On the number.** `main` holds up to DR-091, so the next number looks like DR-092.
> It is taken: **#1835** claims `docs/decisions/DR-092.md` and is open, and **#1956**
> claims DR-094. This record takes the lowest number no open pull request claims, which
> is what the convention is trying to produce - `max + 1` is computed against `main`
> alone and therefore collides whenever two decisions are in flight, which is the gap
> **#754** tracks. The repo's own `DR id uniqueness` check (`scripts/check-dr-id-collision.ts`,
> #1226) queries open pull requests over the network, fails closed on every error path,
> and **passes** on this record; renumbering to DR-092 would fail it. Recorded here
> because a reviewer reading only `main` sees a gap and cannot see the claim that
> explains it - which happened four times on this record's own review.

## In plain terms

A gate that refuses to act on stale information is doing the right thing. But if the
only thing that can refresh that information is a person sitting at the keyboard, then
the gate stops the machine precisely when nobody is there - which is the one time the
machine was supposed to be running on its own. The gate was not wrong. It was waiting
for someone who, by definition, had gone.

So the gate now goes and looks, instead of waiting to be told.

## Context

The drain's admission control gates on a quota reading at `~/.claude/quota.json`. The
reading's only producers were **interactive** surfaces - a rendering statusline - while
the drain that consumes it runs **unattended**.

Measured 2026-09-09 (#1859): the file was **49 hours stale** while holding
`"used_percentage": 3.0`. Over 100 issues carried `agent-ready` / `agent-ready-specify`
and none dispatched. The pipeline had been dead for days and presented as a quiet week.

The failure is structural, not incidental:

| Constant | Value |
|---|---|
| `QUOTA_STALE_SEC` - a reading older than this fails closed | **900s** |
| `INTERVAL` - between drain cycles | **1200s** |
| `QUOTA_BACKOFF` - pause after a quota signal | **1800s** |

The drain's own cycle interval exceeds its own freshness limit, so a reading refreshed
once per cycle was **always** stale by the next one. Worse, a stale reading cannot yield
a real reset time, so the sleep falls back to `QUOTA_BACKOFF` - the longest of the three -
and every hold produced a staler reading than the last. Self-reinforcing.

Confirmed live three times during the fix: after a manual refresh to age 0, watchers
caught the witness stale again at 937s, 1239s and 1541s, with nothing else running.

**The generalisation, which is why this is a decision and not a patch:** a fail-closed
gate is only as available as its witness producer. When the producer is coupled to a
surface that exists *only while a human is present*, "fail closed" silently becomes
"never run again", because the condition that clears it can only be cleared by the person
whose absence caused it. Autonomy gated on a witness that exists only when autonomy is
not needed.

## Decision

**A fail-closed gate MAY synchronously invoke the producer of its own witness, before
consulting it, subject to four constraints.** Freshness becomes a property of the *check*
rather than of who happened to be watching.

1. **The producer may never write to the verdict channel.** `quota_gate`'s stdout *is*
   its verdict (callers do `quota_verdict=$(quota_gate)`), so producer chatter would be
   parsed **as an admission verdict**. Producer stdout goes to `/dev/null`, diagnostics
   to stderr. This is the constraint that makes the pattern safe rather than clever, and
   it is pinned by a test that feeds in a deliberately hostile producer printing
   `open:100% TOTALLY FINE ADMIT EVERYTHING`
   ([drain-quota-refresh.test.ts:103](../../packages/minspec/tests/drain-quota-refresh.test.ts#L103)),
   asserting the verdict is exactly one line matching `^(open|defer):`. The seam itself is
   `_quota_try_refresh` in [scripts/drain-inbox.sh](../../scripts/drain-inbox.sh) (line 1048 at the time of writing — search the symbol, not the line).
2. **A refresh may only make a reading fresher, never a verdict weaker.** On any failure -
   non-zero exit, missing binary, hang past the timeout, or a producer that writes a
   still-stale reading - the reading stands as-is and the gate's existing arms still fail
   closed. Constitution invariant 2: an errored witness must never read as a passing one.
3. **A gate may refresh a stale witness; it may never manufacture a missing one.** The
   missing-reading arm carries its own bounded bootstrap allowance. Refreshing into it
   would let the gate produce its own first reading and convert a documented, bounded
   blind-admit into an unbounded one.
4. **The invocation is bounded and disableable** - an explicit timeout, and a kill switch
   (`MINSPEC_QUOTA_REFRESH=0`) so the seam can be taken out of the path without editing
   code.

### The boundary this decision does NOT cross

This is the part that needs recording, because the change reverses a stated invariant.
`drain-quota-deadline.test.ts` declares **INV-C: "the gate needs no network: no gh, no
curl, no claude."** The refresh producer performs a network call, so that invariant no
longer holds for the composed path, and the gate tests now pin the seam off
([drain-quota-deadline.test.ts:71](../../packages/minspec/tests/drain-quota-deadline.test.ts#L71))
to keep testing the gate in isolation.

> **On the tense used here.** This record was first pushed from a branch based on `main`
> *before* its implementation merged, so a reviewer correctly flagged that it described a
> test and a seam that did not yet exist at that commit - the repo's own
> artifact-existence-is-not-feature-existence rule, applied to a DR. It was rebased onto
> the commit where #1861 landed, and every symbol cited above exists.
>
> **Line numbers in this record are a convenience and they rot.** An earlier version of
> this note claimed "every citation above resolves at this HEAD", and a reviewer caught
> that `_quota_try_refresh` had moved from line 987 to 1048 as `main` advanced, which
> falsified the absolute. The claim is withdrawn rather than re-pinned: a durable record
> cannot promise a line number against a moving file, and re-pinning it only resets the
> clock. **Cite-by-symbol is the load-bearing reference; a line number is a hint.**

That reversal is confined to **dev-time machinery** and does not touch the product:

- `scripts/drain-inbox.sh` is the dev-time dispatch path for building this monorepo. Per
  DR-015 and DR-004, agent dispatch does **not** ship inside MinSpec, which is Tier-0 and
  air-gapped.
- Constitution invariant 1 (core functionality works offline, no network without explicit
  consent) is therefore untouched: nothing here executes in an adopter's editor.
- Constitution invariant 3 (blast radius) is untouched: the seam runs only in a repo that
  is already running its own drain.

**A gate inside the shipped extension may NOT adopt this pattern** on the strength of this
record. If a Tier-0 gate ever needs a fresh witness, that is a different decision with a
different invariant to answer, and it must be taken separately.

## The clause DR-066 is missing — proposed amendment to constitution invariant 2

Recorded here rather than as an edit to DR-066 itself. DR-066 is **accepted** and promoted
into the constitution; an agent editing an accepted rule to add a clause is minting the
sign-off that DR-029 reserves for a human. This section is the *proposal*; adopting it is a
separate human act, and until then invariant 2 reads exactly as it does today.

DR-066 "no silent gate" (accepted 2026-07-22) carries three clauses, all of them **safety**
properties - each forbids a gate from wrongly passing:

1. no load-bearing gate signal written with a swallowed error (`|| true`);
2. a missing or errored witness fails the gate closed **and visibly**;
3. no required check hinging on a single producer that one permission gap can disable.

**#1859 satisfied all three and still killed the pipeline for days.** The drain failed
closed. It failed visibly - it logged the hold every cycle. Its witness had two producers.
Every clause held, and the machine stopped for 49 hours while presenting as a quiet week.

The gap is that DR-066 has no **liveness** clause. "Never wrongly pass" says nothing about
"eventually proceed", so a gate can satisfy the whole of invariant 2 by never passing at
all. Clause 2 is the one that hides it: *visible* is satisfied by a line in a log that the
absent human is, by construction, not reading. The visibility DR-066 asks for is visibility
to **someone present**, and unattended operation is exactly the case where nobody is.

**Proposed fourth clause:**

> A gate whose closed state can only be cleared by a human must not sit on a path that runs
> unattended. Either the gate can clear its own condition (as in this record), or its
> closed state must escalate out of band - to a surface the absent human will actually
> see - rather than repeating into a log.

Two things to weigh against adopting it, because a proposal with only its upside stated is
advocacy:

- It is a **weaker kind of rule than the other three.** Clauses 1-3 are mechanically
  checkable (grep for `|| true`; count producers). "Can only be cleared by a human" is a
  judgement about a whole path, and prose the model must remember is exactly the category
  the constitution says to distrust ("enforce, don't trust the model"). It may belong as a
  design note rather than an invariant until something can check it.
- It **pushes against clause 3's grain.** Clause 3 wants more independent producers; this
  clause invites a gate to become its own producer, which is a coupling clause 3 exists to
  discourage. This record's four constraints are what keep the two compatible, and that
  reconciliation would need to survive in any wording that lands.

**Recommendation: adopt it, as a design note first rather than as a fourth invariant
clause.** The shape is now demonstrated rather than theoretical - three fixes in this
family (#1859, #1855, #1853) all present as *the pipeline looks idle* - so leaving it
unrecorded means re-deriving it on the next one. The cost of the recommendation is honest:
a design note is not enforced, so it will drift, and the mechanical version would need a
checkable proxy nobody has designed yet.

## Alternatives rejected

Recorded because under `act` autonomy nobody sees them live (DR-086 §4).

| Option | Why rejected |
|---|---|
| **A systemd user timer refreshing the witness on a sub-900s cadence** | The intended answer, and the one the global convention prescribes for scheduled work. **Attempted and unavailable here:** `~/.config` is root-owned (`mkdir` denied) and `systemctl --user` reports `offline` in this container. Worth revisiting on a host where the user session is live - it is a cleaner separation than a gate calling a producer. |
| **Leave it; refresh by hand when the pipeline looks idle** | This is the status quo that hid a multi-day outage. The failure has no symptom: the drain logs the hold, sleeps, and looks exactly like an empty queue. It is also self-concealing - anyone who opens an interactive session to investigate refreshes the witness by looking, and sees a healthy drain. |
| **Have the drain fail OPEN on a stale reading instead** | Rejected outright. That is the original INV-A defect, already reversed once: an unknown budget must never read as permission to spend it. It would trade a stalled pipeline for an overspent one. |
| **Widen `QUOTA_STALE_SEC` past `QUOTA_BACKOFF`** | Cheapest edit, and it makes the gate lie: it would admit on readings up to 30 minutes old, which is long enough for a window to turn over entirely. Tuning a freshness limit to match a cadence, rather than producing fresh data, is calibrating the instrument to the answer you want. |
| **Have `dispatch-issue.sh` publish a reading as a side effect of dispatching** | Circular in the same way the whole bug is: the publisher fires from inside the dispatch that admission control is preventing. The existing `--quota-publish-wall` path already has this shape and cannot bootstrap the first cycle. |

## Consequences

- **Admission control acquires a runtime dependency on a producer**, and therefore a new
  latency cost. `quota_gate` is consulted per launch in parallel mode, so a hung producer
  can add up to the timeout (60s default) per check, and concurrent stale launches can
  each fire a refresh before the first lands. Bounded, and tuneable. If it is observed in
  practice the right fix is single-flight around the refresh, not a shorter timeout - a
  shorter timeout would make the refresh fail more often, which fails closed and returns
  us to the stall.
- **The gate's meaning shifts** from *"is a recent observation available"* to *"can we
  observe now"*. That is arguably the honest question for admission control, but it is a
  different question, and a reader of the gate should know which one it answers.
- **The producer becomes load-bearing for autonomy.** If it breaks, the pipeline stops -
  correctly, and visibly in the log, but it stops.

## Risks

| Risk | Likelihood · Impact | Mitigation |
|---|---|---|
| Producer output reaches the verdict channel and is parsed as an admission | Low · **Critical** | Constraint 1, pinned by a hostile-producer test asserting exactly one verdict line matching `^(open\|defer):` |
| A future cadence change silently re-breaks autonomy | **Med** · High | A behavioural red/green pair keyed on the real `INTERVAL` and `QUOTA_BACKOFF` read from the script, not restated in the test |
| The pattern is copied into a Tier-0 gate | Low · **High** | The boundary section above. This record does not license it, and constitution invariant 1 forbids it without its own decision |
| Latency per gate check under parallel dispatch | Med · Low | Bounded timeout, kill switch, single-flight if observed |
