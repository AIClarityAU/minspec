# DR-072: Writing into a config file MinSpec does not own

> **Born `proposed` per DR-029** — acceptance is a separate human act
> (*MinSpec: Accept ADR*). This record's live status is its frontmatter `status:`
> field, not this note.

## In plain terms — what this changes for you

**What happens today.** When you initialize or refresh a MinSpec project, MinSpec writes
files it owns: `CLAUDE.md`, the CI workflows, the git hooks, the slash-command shims. Each
one carries MinSpec's markers, so a refresh can update MinSpec's part and leave your edits
alone. Nothing MinSpec writes has ever landed inside a file belonging to another tool.

**What this DR decides.** MinSpec may now add **one line of wiring** to Claude Code's
`.claude/settings.json` — the entry that makes the scaffolded session-title hook actually
run. Without it the hook is a file that sits there doing nothing.

**Why it needs a decision.** That file is Claude Code's, not MinSpec's, and it is JSON —
which has no comments, so MinSpec's usual "here is my region, everything else is yours"
markers cannot be written into it. A different promise has to take their place.

**The promise**, so this cannot grow into MinSpec rewriting your editor config:

1. **Additive only.** MinSpec appends its own entry. It never removes, reorders, or
   rewrites one of yours.
2. **Idempotent.** Refresh twice, ten times — you get one entry, never a pile.
3. **It never clobbers what it cannot read.** Unparseable JSON, or a shape MinSpec does
   not recognize, means MinSpec leaves the file completely alone and the hook simply
   stays unregistered.
4. **No write unless something changed.** A no-op refresh does not touch the file, so it
   does not show up as a dirty file in source control (G-8).
5. **Narrow scope.** This authorises registering MinSpec's own scaffolded hooks. It is
   not a general licence to manage settings, permissions, or any other key.

**What you get:** the session title in the prompt box, the `/resume` picker, and the
terminal tab names the approvables the session is working on — `Migrate the approval
store — SPEC-019 DR-071` — in every MinSpec project, not just this one.

**If you reject this:** the hook still scaffolds, but every project has to wire it up by
hand, and most never will — the same "ships in one repo only" outcome #1093 was filed to
end.

## Context

Constitution invariant: MinSpec is the **signpost**, and a signpost that is wrong is worse
than no signpost. #1090 built a `UserPromptSubmit` hook that appends the approvable IDs a
session is working on to the Claude Code session title, so the tab, the prompt box, and the
`/resume` picker all name what is under work. It landed as `scripts/hooks/session-title.*`
plus an entry in this repo's own `.claude/settings.json` — a MinSpecPro-local script.

#1093 asked for the obvious follow-through: ship it in the vsix, so every MinSpec-managed
project gets it. That runs into two facts about the harness:

1. **Every managed harness file MinSpec writes is marker-bounded.** `# >>> minspec:managed:
   <name> >>>` … `# <<< minspec:managed:<name> <<<` is what makes Refresh safe: MinSpec
   overwrites only its region and preserves everything outside it verbatim (#249, DR-037).
   The hook **scripts** fit that model exactly — they are shell and Python, both `#`-comment
   languages.
2. **The registration does not.** Claude Code only runs a hook that is listed under its
   event in `.claude/settings.json`. That file is JSON: no comment syntax, therefore no
   markers, therefore no marker-based merge. And it is not a MinSpec file — a project may
   already have its own hooks in it (this repo has five).

So scaffolding the scripts is settled practice; the registration needs a rule.

## Decision

**1. Claude Code hooks scaffold like any other managed harness file, tool-gated.**
`.claude/hooks/session-title.{sh,py}` are managed-region templates (`hash` comment style,
executable, shebang preamble), gated on `tools.claude` exactly like the `.claude/commands/`
slash-command shims. They live under `.claude/hooks/`, beside those shims — deliberately
**not** under `.minspec/hooks/`, which is git's `core.hooksPath` (DR-037), where every file
is a git hook by name.

**2. The embedded copies are generated from this repo's own working hooks.** Like the #564
CI-review stack, `hook-templates.ts` base64-embeds the byte-exact bodies of the files
minspec itself runs, generated by `scripts/gen-ci-templates.mjs` and staleness-gated by
`npm run validate`. A scaffolded project gets exactly the hook this repo runs — never a
hand-transcribed copy that can drift. base64 rather than a TS template literal because the
wrapper is full of `${VAR}` shell expansions a template literal would eat as interpolations.

**3. MinSpec may write into a config file it does not own, under a four-part contract.**
Registering the hook in `.claude/settings.json` is permitted, bounded by exactly the
promises marker-merge makes structurally:

- **Additive.** Append MinSpec's own hook group. Never remove, reorder, rewrite, or
  reformat a foreign entry; never edit inside someone else's group.
- **Idempotent.** Recognize an existing registration by the hook script's **filename**, not
  by MinSpec's path — a project that deliberately relocated the hook is registered, and is
  left as it is rather than "corrected". The file can never accumulate duplicates.
- **Fail-safe, never clobber.** Unreadable file, invalid JSON, or a shape that is not the
  documented hooks schema ⇒ skip and report; MinSpec would rather leave the hook
  unregistered than overwrite settings it cannot safely parse.
- **Write only on change.** No change ⇒ no write, so mtime and `git status` stay quiet.

The whole call is best-effort at the scaffold seam: a cosmetic session title must never
fail an init or a refresh.

**4. Scope is the hooks MinSpec itself scaffolds.** This authorises registering MinSpec's
own hook files. It is not a licence to manage `permissions`, `env`, `model`, or any other
key in that file, and not a licence to write into other tools' config files by analogy —
each would need its own decision.

**5. Refresh re-asserts the registration.** A removed registration is restored on the next
*Refresh Harness Files*, the same as any deleted managed file. The supported per-session
opt-out is the hook's own kill switch, `MINSPEC_SESSION_TITLE_OFF=1`; the supported
permanent opt-out is deleting the scaffolded scripts, which leaves a registration that
fails open (the wrapper exits 0 when it cannot run).

## Consequences

- Every MinSpec-managed Claude Code project gets the session-title signpost at init, and
  every existing one gets it at the next refresh — the #1093 outcome.
- This repo's copy moves `scripts/hooks/session-title.*` → `.claude/hooks/session-title.*`,
  making minspec's own working file the canonical source AND the scaffold output path (the
  same self-hosting the CI stack uses). The files join `SELF_HOSTED_TEMPLATE_NAMES`, so the
  marker-presence gate skips this repo's markerless originals.
- MinSpec now has a second merge mechanism to maintain: marker-based for text, key-scoped
  structural for JSON. The contract above is the thing that keeps them equivalent in
  promise; `claude-settings.test.ts` is where that contract is asserted.
- A project whose `.claude/settings.json` is unparseable silently gets no session titles.
  That is the intended trade (never clobber), and it is a cosmetic feature — but it is a
  silent skip, so the result is *reported* by the function rather than swallowed.

## Alternatives considered

- **Scaffold the scripts, let the user wire them up.** Rejected: it is the status quo that
  #1093 was filed to end. An inert file nobody registers is not a shipped feature.
- **Put the hooks in `.minspec/hooks/`.** Rejected: that directory is `core.hooksPath`, so
  every file in it reads as a git hook. A Claude Code hook there is a filing error that
  invites confusion the first time someone looks for `pre-commit`.
- **Write `.claude/settings.json` wholesale from a template.** Rejected outright: it would
  destroy the project's own hooks. This is exactly the clobber the contract forbids.
- **Ask the user before registering.** Rejected for now: init already writes `CLAUDE.md`,
  git hooks, CI workflows, and slash-command shims without per-file consent, and this is a
  strictly smaller, cosmetic, kill-switchable change. A one-time prompt remains available
  if the visible-surface concern in #1093 proves real in use.
- **Install the hook globally in `~/.claude/settings.json`.** Rejected by the maintainer:
  a per-project harness must not reach into the user's machine-wide config.

## Costly to Refactor

Moderate. The scripts and the merge module are small and reversible. What is costly to undo
is the **precedent**: once MinSpec writes into a foreign tool's config file, "MinSpec can
manage that key too" becomes an easy argument for the next key and the next tool. Decision
point 4 (scope) is the load-bearing clause; loosening it is a new DR, not a patch.
