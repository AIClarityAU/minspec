## In plain terms - what this changes for you

The review panel was going to drop to one voter for documentation. You objected for
specs, and the numbers back you: on spec PRs, nearly every block came from one voter that
the others missed. So specs get **more** review than today, not less. Only plain prose
(README, guides, comments) drops to one voter. This costs about 18% more review calls
overall, not fewer, because specs are most of what gets reviewed.

## Context

The core-tenets review proposed one voter for docs and T1, and four for machinery and
T3/T4 (DR-033 §6, DR-047), to save tokens under core tenet 2. The founder accepted
it with an amendment: specs are "the pointy end, where you have to get it right, as
everything downstream depends on it". The recommendation also said to measure voter
disagreement before landing it.

### The measurement (2026-10-17)

301 review runs on the 200 newest reviewed PRs (#2522 to #2849, 2026-10-03 to
2026-10-17). Full tables and caveats:
[`docs/research/ai-review-panel-disagreement-2026-10-17.md`](../research/ai-review-panel-disagreement-2026-10-17.md).

| Class | Runs | Voters today | Not-pass runs | Blocked by exactly one voter | Reviewer alone would miss |
|---|---|---|---|---|---|
| spec | 210 | 3 (security skipped on all-Markdown) | 25 | 21 (84%) | 15 (60%) |
| machinery | 57 | 4 | 12 | 8 (67%) | 5 (42%) |
| docs (non-spec Markdown) | 10 | 3 | 5 | 1 (20%) | 0 |
| code | 24 | 4 | 1 | 1 | 1 |

- **Every voter earns its seat on specs.** The sole spec blockers were the Architect 9
  times, the Reviewer 7 and the Skeptic 5. The best single voter on specs (the Architect)
  would still have missed 56%.
- **Non-spec prose is rare and cheap to fix.** It is 10 of 301 runs (3%). The Reviewer
  missed none of its 5 blocks, though 5 is too few to prove much.
- Caveats from the evidence file: the denominators are small, the voters see the same
  diff and may be correlated, and the run level mixes first reviews with re-reviews.

## Decision

### 1. Specs get at least the machinery voter count

Any PR touching `specs/` runs at least as many voters as a machinery PR (4 today). The
security voter is no longer skipped on an all-Markdown spec diff. It reviews the spec for
security-relevant requirements (trust boundaries, secrets, consent, network calls) rather
than for code.

### 2. One voter only for non-spec prose

The one-voter tier applies only when every changed file is Markdown **outside** `specs/`,
`docs/decisions/` and `.minspec/`, and is none of the governance files (`CLAUDE.md`,
`AGENTS.md`, `constitution.md`, `.cursorrules`). The one voter is the Reviewer, the best
single voter on docs and at PR level in the sample. A mixed diff never gets this tier.
Decision records keep today's panel; under the direction-vs-engineering record an engineering record is accepted on
this panel's verdict, so it is not prose.

### 3. Everything else is unchanged

Machinery and code keep today's 4-voter panel. The carry-forward of a pass across a
no-op push is unaffected.

## Cost

Measured base: 996 voter calls over the 301 runs (208 three-voter runs and 93 four-voter
runs). Of the 210 spec runs, 12 already had four voters because an earlier push touched
code, so adding the security voter to the other 198 adds about 198 calls. Dropping two voters on the 10 prose runs saves
about 20. Net: about +178 calls, roughly **+18%** of review voter calls. That is a token
increase. core tenet 2 counts rework, though: a spec defect propagates into every
plan, task and line built from it, and since the delegated-approval record the panel's verdict is what a
delegated spec approval rests on. The share of the weekly quota cap is not measured here.
#2857 measures it before and after.

## Rejected alternatives (DR-086 §4)

- **One voter for all docs, specs included (the original recommendation).** Rejected by
  the founder, and refuted by the measurement: a Reviewer-only panel would have missed 15
  of 25 spec blocks.
- **Keep specs at 3 voters.** Rejected: the founder asked for at least the machinery
  count, and 84% of spec blocks were single-voter catches. Each added voter has caught
  blocks the others missed.
- **Drop the one-voter prose tier as not worth building (it saves about 2%).** Considered.
  It was kept because the founder's amendment allows it for non-spec prose, and a missed
  README defect is cheap to fix. If building it costs more than it saves, it can be
  dropped at implementation without amending this record's spec rule.
- **Choose the one voter per class (the Architect for specs).** Moot: specs are no longer
  a one-voter class.

## Consequences

- Spec review gets stronger, and review cost rises by about 18% of voter calls.
- **Accepted risk:** one-voter prose review misses more than three voters would. The
  exposure is small: 3% of runs, and cheap to fix.
