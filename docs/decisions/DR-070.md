# DR-070: Standing dispatch policy (relaxing the pre-dispatch gate, narrowly)

> **Born `proposed` per DR-029** — acceptance is a separate human act
> (*MinSpec: Accept ADR*). Nothing in §2–§5 ships enabled; the setting's default is
> `human` (today's behaviour) and §6 lists **blocking preconditions** that must land
> before the policy may be turned on in this repo at all.

## Context

### The two gates (never conflate them)

- **Pre-dispatch gate** — issue label `needs-review` → `agent-ready`. *"Should an agent start
  building this?"* Owned by `scripts/triage-decide.sh` (deterministic shell over an LLM triage
  verdict), applied by `scripts/triage-inbox.sh`, consumed by `scripts/drain-inbox.sh`.
- **Post-build gate** — PR label `awaiting-approval` (DR-063): AI review passed, a human
  keystroke is the only thing left. Already shipped, with the 4-voter panel, the provenance
  guard, SPEC-024's blast classifier and DR-058's affirmative low-blast rule behind it.

This DR touches **only the pre-dispatch gate.** Relaxing it does not remove human work; it
**moves** work downstream. Every design in this space must account for where the moved work lands.

### The complaint is real, and it is a flow problem

287 open `needs-review` (verified live 2026-07-26; 72% of 398 open issues). The maintainer
cannot process that queue, and #783 already records that inflow outruns resolution — the panel's
14-day re-measurement put creation at ~13/day against ~6/day closed, i.e. a **net +7/day**. A
one-time purge does not fix a rate problem, so any answer has to be a standing rule, not a sweep.

### But the evidence says the auto-buildable set is small — and the naive relaxation is unsafe

Four findings, all measured, all of which constrain the design more than the complaint does:

1. **63% of the backlog is human-decide.** A 278-issue classification produced: human-decide 175,
   auto-dispatch 52, human-only 24, close-stale 16, machinery-p1 10. Independently, `role:architect`
   is 182/287 and `feat` is 154/287 of the current queue.
2. **A hand-picked "verified-safe" wave of five was wrong 5/5 — and the gate that knew it was bypassed.**
   #118, #299, #326, #357, #440 were flipped to `agent-ready` **by hand**. Triage had *already* held every
   one, for the reasons quoted below. But a hand-applied `agent-ready` is **never re-checked against that
   verdict** — `dispatch-ready-check.sh` re-validates only *state* (closed / label removed / human-gate
   added), explicitly **not** the triage verdict (#983). So all five **dispatched**, burned build-agent
   tokens, and were caught only by the *weaker* DR-355 (parent register) backstop: the build agents self-escalated.
   **Two lessons, and the second is the load-bearing one:** (a) a curated "obviously safe" set was 5/5
   wrong, so the auto-buildable set is far smaller than a classification suggests; and (b) **the correct
   verdict already existed and was simply not consulted** — an LLM self-assessment mid-build stood in for
   a deterministic gate. That is precisely the "enforce, don't trust the model" failure this DR must not
   institutionalise. **Read the reasons, not the count** — four of five bounced on the *tier* arm, and three
   of those bounced explicitly for needing a decision: #299 *"needs design choice between three
   proposed options"*, #357 *"three alternative fix approaches … require human design choice before
   dispatch"*, #440 *"bug type, but asks a design decision … on approval-integrity surface"*, #118
   *"needs plan/design review before dispatch"*. Only #326 was human-only-type (UI copy).
   **Consequence: "tier-complexity" is not a synonym for "just big". The gate has no separate
   design-decision arm, so design-decision refusals land in the tier bucket** — the exact bucket a
   naive relaxation opens. Any policy of the shape *"lift the tier hold"* re-admits, by construction,
   the non-negotiable class it claims to exclude.
3. **The hold reason is not recorded anywhere.** `triage-decide.sh` computes `human_only`, `tier`
   and `decision`, then prints one label and **discards all three**. `triage-inbox.sh` posts only
   `**Triage:** <label> · role:<role>` plus a best-effort LLM-authored `rationale:` prose line. So
   `needs-review` is byte-identical whether the bounce was human-only, T3/T4 tier, `needs-info`, or
   the fail-closed default. **The relaxable subset is not machine-addressable today.** This is the
   repo's recurring validator-asymmetry class in a new place: the gate checks a value and never
   records the reason.
4. **LLM staleness guesses are ~56% wrong** (16 issues called stale; 7 confirmed). Anything that
   would let an LLM *grant* dispatch permission is disqualified on this evidence alone.

### Two live holes make "just relax it" strictly unsafe today

- **#981 — `sites/**` can native-auto-merge to a public deploy.**
  `dispatch-issue.sh --paths-have-approvable-doc` prints `arm` for `sites/minspec.dev/index.html`;
  `.github/workflows/deploy-sites.yml` deploys on push to `main` under `sites/**`; `.minspec/config.json`
  has `autoMerge.native: true`. A code-only agent PR touching only `sites/**` with a genuine
  `ai-review:pass` publishes to the public internet with **zero human keystrokes**, right now, with
  no policy change at all. The "no published sites" rule exists only in an LLM triage prompt, not in code.
- **The docs/copy class has an affirmative auto-pass.** `detectLowBlastDocsTest`
  (`scripts/auto-merge-gate.ts:712`) certifies a diff **low-blast** when every path matches
  `DOCS_EXT_RE` and none is a boundary path; `.github/workflows/docs-lane.yml` independently enables
  auto-merge for docs-only PRs. Marketing, positioning, legal and README copy are `.md`. So the one
  category the brief marks non-negotiable is the *only* category with an affirmative low-blast
  certification. Worked example, using a real parked issue: **#645** (`docs: re-state network posture
  off "air-gapped" → data-sovereignty + BYO-LLM`) cites accepted DR-054, is held on tier, names only
  `.md` paths — a naive tier-lift dispatches it, the diff certifies low-blast, and native auto-merge
  lands a rewrite of the product's public network claims with no human in the loop. The panel found
  36 similarly-shaped issues, including #505 (marketing positioning), #954 (a UX pick), #967 (PO-facing copy).

- **#983 — a hand-applied `agent-ready` dispatches unchecked.** `dispatch-ready-check.sh` validates
  state and countermanding labels, never the verdict (its own SCOPE comment says so). The five issues in
  finding 2 would have been **built** had the drain not happened to re-triage them. A policy that
  writes `agent-ready` from outside the gate inherits this hole.

### What this DR is therefore trying to be

Not "turn the gate off". The honest framing: **`needs-review` is four collapsed outcomes wearing one
label; separate them, keep the human-decide majority exactly where it is, and let a deny-by-default
predicate lift the one arm that is genuinely about size — and only for work that is hash-bound to an
approved spec, provably decision-free, inward-facing, and merge-gated by a human anyway.**

## Decision

### 1. Split the collapsed hold reason (ships first, ships alone, ships regardless)

`triage-decide.sh` gains a **third stdout token**: `<label> <role> <hold>` where
`hold ∈ {human, tier, info, none, unknown}` — computed from the branch that already fired, ~4 lines
of shell in an existing pure, unit-tested script. `unknown` is the fail-closed no-verdict path.

`triage-inbox.sh` then:

- applies `hold:human` / `hold:tier` / `hold:info` / `hold:unknown` alongside `needs-review`; and
- persists the **full machine-readable verdict** (`decision`, `role`, `tier`, `human_only`,
  `decision_required`, `bodyHash`, `verdictAt`, gate version) as a delimited block in the bot triage
  comment. The comment is the durable store — GitHub-side, shared, auditable, survives a fresh clone.

This is valuable **as measurement, independent of any relaxation**: it is the only way to size a
future policy honestly, to answer "why is this parked?" after the fact, and to stop a human-only veto
from being unrecoverable. It is a prerequisite for §2, and it is the piece to ship first.

The `bodyHash` doubles as a **verdict cache**: a recorded verdict is reused while the body is
unchanged, and re-triage is forced on edit. This removes the run-to-run tier flap (no seed, no cache
today) at the cost of a *sticky* verdict — mitigated by (a) forced re-verdict on body edit, and
(b) the verdict's age being displayed everywhere the verdict is used. We accept sticky-but-visible
over flapping-and-presented-as-fact; a never-wrong signpost cannot render an unstable number as a count.

### 2. The safe-class predicate — `scripts/auto-dispatch-check.sh`

A new **pure, deterministic, unit-tested** script in the house style of `triage-decide.sh` /
`dispatch-ready-check.sh`: no `gh`, no `git`, no network, prints one token, **fails closed on every
unknown**. It never holds credentials; the parent applies labels. It **does not write `agent-ready`
itself** — see §3.

All conjuncts must hold. Any missing, duplicated, garbled or errored input ⇒ **deny**.

**P0 — policy on.** `.minspec/config.json` → `dispatch.preApproval` equals the exact token
`"standing"`, resolved exact-token with no fail-open path (same shape as `resolveMode()` in
`auto-merge-gate.ts`), AND the machine-local marker `.minspec/auto-dispatch` exists (§3).

**P1 — dispatch-readiness holds.** `dispatch-ready-check.sh` returns `ready` (OPEN; none of
`needs-info`, `needs-human-review`, `agent-quarantined`).

**P2 — the hold is `tier`, and nothing else.** `hold:tier` present; `hold:human`, `hold:info`,
`hold:unknown` are **never** liftable by any configuration value. A `hold:human` verdict is permanent.

**P3 — no decision is being asked for.** This is the conjunct that answers finding 2, and it has two
independent arms, both deny-side:

- **P3a (deterministic, no LLM):** deny on decision-menu body shape — an enumerated options list
  (`^\s*\d+\.` runs of ≥2 under an "option(s)/approach(es)/alternative(s)" heading), or the tokens
  `which of`, `either … or`, `A vs B`, `needs a decision`, `pick one`, `open question`. Deliberately
  over-broad; a false deny costs nothing but the status quo. Measured leak this closes: **#877**,
  which carries a literal *"Fix options for triage: 1. … 2. …"* menu that no label predicate can see.
- **P3b (LLM, veto-only):** a new REQUIRED triage verdict field `decision_required: yes|no`.
  `yes` ⇒ deny. `no` ⇒ **does not grant** — it merely fails to deny, and the rest of the conjunction
  still has to hold. Missing/garbled ⇒ deny.

**P4 — type and role.** Exactly one type label, from `{bug, refactor}`. `feat`, `idea`, `enhancement`
and — deliberately — `documentation` are excluded (a label cannot separate docs-the-chore from
copy-the-judgement; #967 carries `documentation` and is copywriting). Role exactly `role:dev`.

**P5 — hash-bound governance, NOT a citation check.** The naive form of this clause is worthless and
we are recording why: **256 of 287 parked issues already cite a SPEC or DR (89%), and 167 (58%) cite
an *accepted* DR** — because this repo's own traceability convention *requires* the citation. Bare
citation filters nothing and fails in the dangerous direction.

Coverage therefore means, for the spec the issue names:

- an approval record exists under `.minspec/approvals/**` for **every document present in that spec's
  directory** (not "any one of them" — approve-any is trivially gamed by approving `requirements.md`
  and building against an unapproved `design.md`);
- **every** such record's stored `specHash` still matches the file on disk (content-bound: any edit
  silently de-classes every derived issue, reusing DR-062's staleness rather than reinventing it);
- `approvedBy` is a human identity (all 37 current records read `github@harvest316.com`, already
  reconciled — but the check stays, and agent identities never satisfy it); and
- the spec declares non-empty SPEC-038 `implements:`/`affects:` globs.

**A DR citation alone NEVER satisfies P5 in v1.** There are **zero** approval sidecars for decisions —
all 37 tracked records are `specs/…` — and DR acceptance is frontmatter + INDEX only, via a flow with
a known live parity defect (#943/#968). We will not hang agent autonomy on that.

**P6 — inward-facing, non-boundary scope.** The union of the spec's `implements:`/`affects:` globs
must be disjoint from the deny set, and the deny set is **imported, not re-listed**: promote
`isBoundaryPath`, `MANIFEST_BASENAMES`, `BOUNDARY_ROOT_BASENAMES`, `BOUNDARY_CONFIG_BASENAMES` from
`scripts/auto-merge-gate.ts` into `@aiclarity/shared`, with a test asserting the pre-gate and the
post-gate agree byte-for-byte on "boundary". Added on top, explicitly: `sites/**`, `README.md` and any
`packages/*/README.md` (they ship in the `.vsix` and render on the Marketplace listing),
`docs/decisions/**`, `.minspec/constitution.md`, `.github/**`, `scripts/**`, `.githooks/**`.

`.github/**` and `scripts/**` are excluded for a **throughput** reason as well as a safety one: the
machinery self-edit guard means such a PR can never obtain a valid `ai-review:pass`, so it lands at
`machinery-review-required` needing `--admin` break-glass. Auto-dispatching machinery work (e.g. #968,
#839, #366) produces a PR that costs the human *more* attention than the issue did. **Negative throughput.**

**P7 — bounded unit of work.** Deny if the body has >3 unchecked `- [ ]` items, or the title matches
`bug-hunt|remaining|sweep|roster|backlog|audit`. Measured leak this closes: **#153**
(*"bug-hunt: remaining confirmed bugs — parser, validator, multi-root, misc"*) — an unbounded bundle
is an unbounded diff, which is the one blast dimension the post-build gate handles worst.

**P8 — one auto-attempt per issue, ever.** No prior `auto-dispatched` marker. An auto-dispatched issue
that escalates leaves the class permanently.

**P9 — backpressure, on dispatch and not merely on the offer.** All must hold, counted live, **deny on
any count error**: open `awaiting-approval` PRs < `maxOpenAwaitingApproval` (default 5); auto-dispatches
in the trailing 24 h < `dailyCap` (default 4); auto-dispatches this drain cycle < `maxPerCycle`
(default 2). Never open the upstream valve while the downstream tank is full.

**P10 — escalation governor.** Rolling 7-day escalation rate **of auto-dispatched issues only**. Above
`escalationCeiling` over a minimum sample of 10, the policy **self-suspends to `human`**, files an issue
explaining why, and requires a human edit to re-enable. **The ceiling is 0.15, deliberately below the
measured baseline** — the pipeline currently runs ~29% escalation (63 open `agent-escalated`, verified
live; the 12 most recent are 12/12 `role:dev`, i.e. exactly this policy's target population). A ceiling
set *at* the baseline is decorative: it only fires if the new lane is worse than an already-poor status quo.

**T0 acceptance test for the predicate:** the five issues of the 2026-07-26 wave — **#118, #299, #326,
#357, #440** — must every one be **DENIED**. #326 by P4 (type) and P2 (`hold:human`); #118/#299/#357/#440
by P3. If any of them passes, the predicate is wrong and this DR is withdrawn, not tuned.

### 3. Composition with the existing gate — extend it, never bypass it

`triage-decide.sh` stays the **sole writer** of `agent-ready`. The standing policy changes an *input*
to that gate (which hold reasons are liftable when the predicate passes), and is evaluated **inside**
the drain's promotion step. There is no second admission lane and no path that writes `agent-ready`
around the gate.

Two honest statements about what that does and does not buy:

- **What it fixes.** #983 must land first (§6): dispatch must require a **fresh affirmative verdict**
  with a liftable hold, not merely the absence of a countermanding label. A standing policy layered on
  today's absence-based check would be a silent gate (DR-066).
- **What it does NOT fix, and we are not pretending otherwise.** The base gate's own auto path
  (`tier ∈ {T1,T2} ∧ decision == agent-ready`) already depends on an LLM boolean. That is the **status
  quo**, not something this DR introduces — and this DR's rule is that it must not be *widened*: every
  new conjunct in §2 is deny-side, and the only new LLM field (`decision_required`) can subtract
  permission and never grant it. Two grant-side joints remain agent-writable (`role:dev`, the type
  label) and we name them as the predicate's weakest link, bounded by §4's merge-gate conservation and
  by P5/P6.

### 4. Merge-gate conservation — one human keystroke per unit of work, relocated not deleted

An auto-dispatched issue is stamped `auto-dispatched`; `dispatch-issue.sh` propagates
`human-merge-required` to the resulting PR, which **suppresses native auto-merge arming** and joins the
withhold decision as a label conjunct (fail-closed on any label-read error). The PR lands at
`awaiting-approval` (DR-063) for a human merge keystroke.

The keystroke moves from the **evidence-poor** moment (an issue title plus an LLM tier guess — and this
repo has measured that tier tracks diff size, not difficulty, n=120, κ=0.80) to the **evidence-rich**
moment (a real diff, measured blast, the 4-voter panel, a red/green proof). **No unit of work ever has
zero human keystrokes.** A first relaxation does not relax two gates at once.

### 5. What can NEVER auto-dispatch (absolute; no configuration value reaches these)

1. Anything with `hold:human`, `hold:info`, or `hold:unknown`.
2. Marketing, positioning, copywriting, legal, monetization/billing, pricing, public-posture claims —
   whatever label they wear. (`documentation` is excluded wholesale for this reason.)
3. Anything asking for a product or architecture **decision** (P3, both arms).
4. Irreversible or outward-facing actions: publishing, deploys, account creation, outbound email,
   anything under `sites/**` or shipped in the `.vsix`.
5. Acceptance of a constitution amendment, DR, or spec — human keystroke only, always.
6. Boundary/governance/machinery paths: `.github/**`, `scripts/**`, `.githooks/**`, `docs/decisions/**`,
   `.minspec/constitution.md`, CODEOWNERS, manifests, lockfiles.
7. `T4`, clamped **in code** — `maxTier` parses to at most `T3`, and an out-of-range value coerces down
   and warns (SPEC-046 FR-1's rule).

### 6. The setting

Repo-scoped and **committed**, in `.minspec/config.json` — the same shape SPEC-046/DR-068 already
accepted for standing auto-approval, so this is one policy model, not a second:

```jsonc
"dispatch": {
  "preApproval": "human",            // "human" (DEFAULT) | "standing"
  "maxTier": "T2",                   // "T2" (DEFAULT) | "T3"  — T4 clamped in code
  "requireApprovedGovernor": true,   // P5; may never be set false while preApproval=="standing"
  "maxPerCycle": 2,
  "dailyCap": 4,
  "maxOpenAwaitingApproval": 5,
  "escalationCeiling": 0.15,
  "mergeGate": "human",              // ONLY legal value in v1
  "noticeThreshold": 50,
  "enabledBy": "",                   // git config user.email at enable time (DR-056 identity source)
  "enabledAt": "",
  "policyVersion": 1,
  "policyRef": "DR-070"
}
```

**Default `human`, and the defence is threefold.** (a) It is byte-identical to today's behaviour, so
accepting this DR ships zero behavioural change until a human commits the flip. (b) Deny-by-default is
this repo's established stance for the sibling gate (DR-033, SPEC-024, DR-058); a pre-gate looser than
the post-gate would be incoherent. (c) MinSpec ships to strangers' repos — a default-on relaxation
would dispatch agents into someone else's codebase on install, which is DR-066's invariant at its
widest reading. It is also the only default under which a config **parse failure** is safe.

**Why `.minspec/` and nowhere else:** `.minspec/**` is already inside the auto-merge withhold set, so
**an agent cannot widen its own permission via a PR that auto-merges.** The dial governing agent
autonomy sits in the one directory an agent's PR can never land unattended. VS Code `settings.json`
(per-machine, unreviewable, no diff) is disqualified for exactly that reason.

**Two-key opt-in**, copied from the proven `.minspec/auto-drain` marker: repo policy says *what class
is admissible* (a team decision, visible in a diff, reviewable in a PR); a gitignored, machine-local
`.minspec/auto-dispatch` marker says *this machine's session and quota may be spent on it*. Both
required. Composition rule for any future per-dev layer: **AND on enable, `min()` on caps — a local
file may only narrow, never widen.**

**Kill switches, monotonic toward safe:** `MINSPEC_DISPATCH_PREAPPROVAL=human` forces the strict path
regardless of config; deleting the marker stops it at the next drain cycle. No env var can loosen.

**Enabling is enforced as a human act, not trusted as one:** the ext command writes `enabledBy` from
`git config user.email` and opens the diff for the human to save and commit; `.githooks/pre-commit`
rejects any commit that sets `preApproval: "standing"`, raises `maxTier`, clears
`requireApprovedGovernor`, or raises a cap when the committer is an agent identity. *"Don't hope an LLM
will follow rules — enforce it via code"*, applied to the setting that governs the LLMs.

### 7. The threshold notification

**Producer/consumer split, so the ext stays Tier-0.** The drain already runs `gh issue list`; it writes
`.minspec/queue-stats.json` (gitignored, machine-local): `{measuredAt, holdTier, holdHuman, holdInfo,
holdUnknown, eligible, agentReady, awaitingApprovalPrs}`. The ext reads the **file** — no new network
surface, no new consent, silent offline.

**Trigger — all four must hold:**

1. `holdTier >= noticeThreshold` (default 50) — **the tier-held count, not raw `needs-review`.** A toast
   promising relief over 287 issues when ~63% are human-decide would be a promise the predicate cannot
   keep, and the human would correctly learn to discount it.
2. `eligible >= 5` — **the offer must be non-empty.** A notification that cannot change an outcome is
   noise by definition. If the predicate admits nothing, the toast correctly never fires.
3. `dispatch.preApproval == "human"`.
4. `awaitingApprovalPrs < maxOpenAwaitingApproval` — the **anti-rubber-stamp interlock**. Never offer to
   open the upstream valve while the human is already behind downstream; that is precisely how
   click-through is trained.

**Copy** — one line, non-modal, never focus-stealing, no badge, no count-as-urgency, both numbers always:

> **MinSpec** — 287 issues are waiting on your go-ahead; **62** are held only because they're bigger
> than T2 (triaged 2026-07-14…26), and **9** of those clear the standing safe-class rule. The other 278
> still need you either way.
> `[Show me the 9 — Alt+R]` · `[Set up standing dispatch…]` · `[Not now]`

**Anti-rubber-stamp, structurally:** the **cheap, primary button is the evidence button.**
`Show me the 9` opens a generated read-only preview — each candidate, the anchoring approved spec, its
approval date and approver, the exact path globs, the conjuncts that admitted it, and the sentence
*"these PRs will still require your merge keystroke."* The consequential button ends in an ellipsis and
**enables nothing**: it opens the proposed `.minspec/config.json` diff, which the human saves and
commits themselves. **There is no one-click enable anywhere in the flow.** A toast that flips a standing
policy over all future dispatch is the rubber-stamp pattern in its purest form.

Note the preview is the real keystroke-removal idea and it **works standalone**: one read of a generated
list substituting for N per-issue adjudications delivers most of the stated benefit with none of the
risk — see Follow-ups.

**Anti-nag:** at most once per 7 days per workspace, and only when `holdTier` has grown ≥25% since the
last showing (state in the already-gitignored `.minspec/preferences.json`). `Not now` snoozes 30 days.
The **third** dismissal disables it permanently **and says so in that third toast** ("I'll stop offering
this — re-enable from the palette"). After enabling, it never fires again.

**Not a silent gate (DR-066):** suppression-by-cooldown is **state, not silence.** The Backlog view
header always carries a persistent, non-interrupting `287 awaiting your go · 62 tier-held ·
auto-dispatch: off`, and *MinSpec: Show SDD Status* always shows
`Standing dispatch: ON (≤T3, hash-bound governor) — enabled by <email> on <date>`. A permanently visible
status line is not a nag; a repeating toast is.

### 8. Blocking preconditions and the kill criterion

`dispatch.preApproval` **may not be set to `"standing"` in this repo** until all of the following land:

1. **#983** — dispatch demands a fresh affirmative verdict with a liftable hold; the gate is the sole
   writer of `agent-ready`.
2. **#981** — `sites/**` added to the auto-merge withhold set.
3. **The docs-class hole** — outward-facing `.md` (`sites/**`, `README.md`, `packages/*/README.md`,
   anything shipped in the `.vsix`) excluded from `detectLowBlastDocsTest`'s affirmative low-blast
   catalog and from `docs-lane.yml`'s auto-merge, the same way CODEOWNERS already is
   (*"governance is not documentation"* — marketing copy is not documentation either). Filed as **#1001**.
4. **§1** — hold-reason token, labels, and persisted verdict block shipped and backfilled.
5. **§2** — predicate implemented with its T0 suite, including the #118/#299/#326/#357/#440 denial test.

**Kill criterion, agreed before the policy ships, not after it hurts.** Run the eligibility dry run
(`drain-inbox.sh --dry-run`) **three times** and diff the eligible sets. If the sets **disagree**, the
eligibility signal is not stable enough to gate anything — stop. If the stable set is **under ~20**,
**this DR is WITHDRAWN, not tuned**: the honest reading would be that the work genuinely needs a human,
and the lever is elsewhere (see Consequences).

**Reversion tripwire after enabling:** if ≥2 of any trailing 10 `auto-dispatched` PRs are closed-unmerged
as wrong-thing-built, the policy reverts to `human` and says so in the next session's status line.

## Consequences

- **The honest yield is small, and we are recording that up front.** After P3 (decision-free), P4
  (bug/refactor + role:dev), P5 (hash-bound, spec-only governor) and P6 (inward-facing, non-boundary),
  the admitted set on today's 287 is expected in the **single digits to low teens** — roughly 1–2 days
  of inflow at ~13/day. **This is not a backlog fix.** Selling it as one would be exactly the false
  signpost this product exists to prevent.
- **The measured constraint is probably not the pre-gate.** The pipeline merged ~131 PRs in 14 days
  (peaking at 24 in one day) with only ~4 open at any time — but of 54 merges in the last 7 days, **47
  were merged by the human** and 7 by the bot. The post-build lane is not idle machinery; it is a person
  doing ~7 merge keystrokes a day and keeping up, barely. This DR routes its new volume straight at that
  person, which is why §2 P9's caps are small and §7's interlock gates the offer.
- **Dispatch is a source as well as a sink.** ~44% of recent inflow is follow-up-shaped, and the repo's
  own conventions (DR-023/DR-040, the prose-only-follow-up commit gate) *require* deferred work to be
  filed. Each dispatched issue yields a PR **and** roughly one new `needs-review` issue. At loop gain
  near 1 you cannot drain the queue by dispatching faster. **The higher-value levers are demand-side** —
  a filing gate ("does this issue name a decision? then it's a decision, not a build item"), a
  close-stale policy, and **batched architect adjudication** (one sitting answering 20 design questions
  from a generated decision-batch document, over the 182 `role:architect` issues that are 63% of the
  queue). Those remove more human keystrokes per hour than auto-dispatch ever will and they touch no
  safety gate. This DR should be ranked **below** them.
- **§1 is worth shipping even if §2 never enables.** The backlog becomes queryable by hold reason, the
  triage audit trail stops being LLM prose, and any future policy, batching tool, or backlog analytic
  becomes sizeable instead of guessed.
- **Two real, currently-live holes get closed as preconditions** (#981, the docs-class affirmative
  low-blast). Both exist today with no policy change and are the most valuable output of this work.
- **`needs-review` gains sibling labels**, and the ext's lifecycle model
  (`inbox → triaged → agent-ready → wip → done`) already does not know about `needs-review` at all.
  That divergence must be reconciled or the new labels will be a second quiet drift.
- **Ceremony cost:** one more script, one more config block, one more label family, one shared boundary
  module. All independently shippable, all reversible by a one-line commit.

## Alternatives considered

Three independent designs were produced and adversarially critiqued; **all three were rejected as
proposed**, and the panel's scores were: reuse-first 3/2/6 (safety/throughput/simplicity), risk-first
3/2/3, throughput-first 4/2/2. **Reuse-first is the spine of this DR** — it is the least new machinery
and the only one whose central move (split the hold reason the gate already computes) is measurement
rather than judgement. What was grafted, and what was discarded:

- **Reuse-first, as originally written — rejected on three fatal flaws, all addressed above.**
  (i) Its clause 6 was a *citation* check; measured, 89% of the backlog cites a SPEC/DR and 58% cite an
  accepted DR, so it filtered almost nothing and failed in the dangerous direction — replaced by P5's
  hash-bound, all-documents, human-approver, spec-only rule. (ii) It claimed no LLM sits in a
  dispatching path; the base gate's auto path already depends on an LLM boolean — §3 states this
  honestly and confines every new conjunct to the deny side. (iii) It assumed the post-build gate would
  hold the extra volume; for the docs/copy class the post-gate *affirmatively passes* it — §6 makes
  fixing that a blocking precondition, with #645/#505/#954/#967 as the worked leak.
- **Risk-first ("relax only the tier arm of `triage-decide.sh`; keep the human-only arm") — rejected.**
  Its safety conjunct was a **tautology**: rule 1 (`human_only`) evaluates *before* rule 3 (tier), so
  every issue in the relaxed population already has `human_only == no`. Re-asserting it filters zero
  issues. Worse, four of the five bounces it cited as evidence were **tier** bounces, three of them for
  needing a design choice — so its core mechanism re-admits the non-negotiable class. Its live
  counterexample (#440: `{bug, role:dev}`, bounced for *"asks a design decision on approval-integrity
  surface"*) passes its predicate end-to-end. **Grafted from it anyway, and load-bearing here:** the
  merge-gate conservation clause (§4), the downstream interlock (§7 trigger 4), the AND-on-enable /
  `min()`-on-caps composition rule, the "site the dial where agents cannot auto-merge" reasoning (§6),
  the one-legal-value key (`mergeGate`), and the discovery of #981.
- **Throughput-first ("derived-work" class: a machine-written anchor block binding an issue to an
  approved artifact hash) — rejected.** Its permanent-veto backstop was unimplementable (the verdict it
  vetoes on is not persisted — which is why §1 exists), its veto was scoped to `human_only` and so did
  not cover finding 2's tier bounces at all, its class was **empty on day one** (no tooling writes the
  anchor block; there is no `gh issue create` anywhere in `scripts/`), its clause E constrained a
  *declaration* no build is obliged to honour, its DR arm was unavailable (zero DR approval sidecars),
  and its escalation ceiling (0.30) sat *above* the measured ~29% baseline, i.e. decorative.
  **Grafted from it:** the reframe from *"is this safe to build?"* (unanswerable deterministically) to
  *"was the human keystroke already spent, content-bound?"* (a hash comparison) — which is P5;
  content-bound staleness as automatic de-classing; one-auto-attempt-per-issue-ever (P8); the
  import-don't-re-list boundary catalog (P6); the two-key opt-in; the non-empty-offer notification rule;
  and "suppression-by-cooldown is state, not silence".
- **Hand-flipping labels per wave (the status quo workaround) — rejected, and actively closed.**
  Finding 2 is usually read as *"the safe class is smaller than we hoped"*. It is also evidence that a
  human can today apply `agent-ready` and dispatch a human-only issue; the bounce only happened because
  those five were re-triaged. #983 makes the gate the sole writer. **The policy must tighten that path,
  not institutionalise it.**
- **Turning the pre-dispatch gate off wholesale (the literal request) — rejected.** 63% of the queue is
  human-decide; with #981 live and the docs class affirmatively auto-passing, "off" is a zero-keystroke
  path from an issue to a public deploy.
- **Relaxing the post-build gate instead (let this class native-auto-merge under SPEC-024's blast
  gate) — rejected for v1.** Defensible, and it is where the throughput ceiling actually is; but a first
  relaxation must not relax two gates simultaneously, and SPEC-024's consequence analyzers are not yet
  validated on a real index.
- **Fixing the tier classifier / adding a design-decision arm to triage instead — not rejected;
  ranked adjacent.** The same n=120/κ=0.80 evidence that says tier tracks diff size rather than
  difficulty argues that an unreliable signal which currently fails **safe** should be repaired, not
  switched off. P3 is the minimum version of that repair; the fuller version is a separate work item.

## Costly to Refactor

**Yes — that is why it is a DR.** Three parts are cheap and reversible: the config key (one-line
commit), the predicate script (pure, deleteable), the toast (feature-flagged). Two are not:

- **The hold-reason labels + persisted verdict block become a corpus.** Once ~300 issues carry
  `hold:*` and a machine verdict block, changing the vocabulary or the block schema means a backfill
  across every open issue and every consumer.
- **What a spec approval is taken to *mean* is a governance change, not a code change.** P5 widens
  "the human approved this spec" into "the human authorised derived build work under it". If that
  premise proves wrong — if derived issues routinely contain choices the spec did not settle — the
  correct response is to **withdraw** the policy, not tune its caps. Rewinding is one config edit;
  rewinding the *trust* is not.

Everything an enabled policy actually does is bounded and reversible by construction: `preApproval:
"human"` restores the status quo at the next drain cycle, in-flight work is still held by the post-build
gate, and no auto-dispatched PR can ever merge without a human keystroke (§4).
