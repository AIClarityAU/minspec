# DR-122: Agents may select a T3 spec's recommended Clarify answers, under the bot's own name

> **Born `proposed` per DR-029.** Acceptance is a separate human act (*MinSpec: Accept
> ADR*). This record is `kind: direction` and adds a delegated act, which DR-108 (the
> delegated-approval record) section 2 says no agent may do on its own ("Agents may tighten
> or suspend a delegation, but never widen one"). The pull request that carries it was
> drafted by the bot at the founder's request and is landed by the founder. Nothing here
> takes effect until he accepts this record: the new delegation entry names this record,
> and `evaluateDelegation` covers nothing under an entry whose record is not `accepted`.

> **On this record's number.** DR-121 is the highest id on `main` (`5c3a10a6`), and DR-120
> is held by open pull request #3497, read 2026-11-13. The collision gate re-checks it on
> this record's own pull request.

## In plain terms

You said yes on 2026-11-13 to agents picking the recommended answer for a T3 spec's
Clarify questions. With this record accepted, the bot may record those picks itself,
under its own name (`minspec-sdd[bot]`), never yours, after a second, independent AI
agrees. Three things stay yours whatever happens: SPEC-217, SPEC-227, and every T4 spec.
So do `--admin`, the constitution, the stop list, and this delegation itself.

The cost you accept: a Clarify answer the reviewer missed reaches a spec without a human
look. The spec approval that follows still has to pass its own review, so a wrong answer
is caught there or nowhere.

## Context

- **Why they wait.** DLG-001 (DR-108, the delegated-approval record) covers spec approval

  made none of the Clarify selections 24 specs attributed to it. Since then, delegated
  approval refuses a spec with an open Clarify question (#3059), and nothing may close
  one without the founder. So the drain stopped writing specs.
- **What the founder said.** Queue item cg1112, 2026-11-13, option g: yes to agent-picked

This record extends DLG-001's scope by a separate entry; it does not contradict SPEC-277.
SPEC-277 states DLG-001 covers approval only, and that stays true: DLG-001 is unchanged,
and the new act lives in a new entry, DLG-002.

## Decision

### 1. A new delegated act, `clarify-selection`

`clarify-selection` joins `spec-approval` and `engineering-dr-acceptance` as an act a
delegation may cover (`DelegatedAct` in `scripts/lib/autonomy.ts`). It means: select the
answer the spec already recommends for each open Clarify item, and record that the bot
selected it. It never means writing a new option, choosing a non-recommended option, or
approving the spec. Approval stays a separate act under DLG-001, judged on its own.

A new entry, DLG-002, in `.minspec/delegations.json` covers `clarify-selection` for
`AIClarityAU/minspec`, tier T3 only, gated on this record, review by 2027-02-13, with the
same 13% repeat-fix-share tripwire as DLG-001. DLG-001 is not edited.

### 2. The exclusion list, and how the code enforces it

| Excluded | Enforced by |
|---|---|
| SPEC-217 | `CLARIFY_SELECTION_EXCLUDED_SPECS`, matched by number, so `SPEC-0217` and `spec-217` are the same spec |
| SPEC-227 | the same list |
| every T4 spec | `CLARIFY_SELECTION_TIERS` admits T3 only, so T4 (and T1, T2) are refused |
| a spec whose tier cannot be read | refused: a missing, empty or unknown `tier:` is never read as T3 |

`clarifySelectionRefusal` runs inside `evaluateDelegation` for this act, before any
delegation entry is consulted, and fails closed at each step:

1. The request must name one spec as `SPEC-NNN`; an unreadable id is refused.
2. Every path the selection writes must belong to that spec; a path naming no spec or a
   different one is refused. An excluded spec named in any path is refused.
3. The tier must be readable as T1 to T4, and must be T3.

The list is code, not data. An entry in `.minspec/delegations.json` that lists T4, or
omits an exclusion, still meets these refusals. `scripts/lib/autonomy.ts` is a governance
path, so no delegated approval can edit the list, and `.minspec/delegations.json` is a
boundary path in the auto-merge gate, so no edit to it merges without the founder.

### 3. A second, independent AI gives the verdict, never the author

As for every delegated act (DR-108 section 2, item 3, and "Delegation is not
impersonation" in the global instructions), the request must carry an independent
verdict, and `evaluateDelegation` refuses when the verdict comes from the session that
wrote the spec or from the recorder. The selection is recorded under
`minspec-sdd[bot]`; a request naming any other actor is refused.

### 4. What it never covers

The same limits as DLG-001, held by construction, not by caller discipline:

- **`--admin` and every irreversible act.** `stopClassesAfterDelegation` removes only the
  `approval-or-acceptance` stop class, whatever act is covered.
- **The constitution, the stop list, and the delegation itself.** These are governance
  paths (`.minspec/constitution.md`, `scripts/lib/autonomy.*`, `.minspec/delegations.json`,
  `.minspec/config.json`, DR-086, DR-108, and this record), and any request touching one
  is refused. This record is added to that list by this change.
- **memory-fabric**, hard-coded as never delegated.

Constitution invariant 3 (blast radius) bounds the entry to this one repo; invariant 2
(no silent gate) is why every unreadable input refuses rather than passes.

## Rejected alternatives (DR-086 §4)

- **Widen DLG-001's `covers` to include Clarify.** Rejected: it would edit the founder's
  existing grant and contradict SPEC-277 and the correction note, which both say DLG-001
  covers approval only.
- **Put the exclusion list in `.minspec/delegations.json`.** Rejected: any future entry
  could omit it; in code it binds every entry.
- **Cover T4 too.** Rejected: the founder named T3, and T4 specs are the widest blast
  radius in the tier model.
- **Treat a missing tier as T3.** Rejected: a tier is never invented (the same rule
  delegated approval follows).
- **Let the selection count as the spec's approval.** Rejected: two acts, two judgements;
  the approval still needs its own pass under DLG-001.
- **Keep asking the founder for each spec's Clarify answers.** Rejected: 36 specs and the
  paused drain, against core tenet 1, on answers he has said he accepts.

## Consequences and cost

- **Founder time.** One read of this record and one landing keystroke, replacing a
  Clarify sign-off for each of the 36 specs now waiting and each future T3 spec.
- **Tokens.** Each selection rides the AI review the spec already gets, so the added cost
  is the selection write and its check, small next to the review panel. Not measured; no
  figure is claimed.
- **Accepted risk.** A wrong recommended answer is recorded without a human look. The
  review panel, the spec approval that follows, the ratio tripwire and the review-by date
  are what catch it.
- **Not yet consumed.** The code answers "does a live delegation cover this selection?";
  no writer asks it yet, so nothing changes until the writer below is built, even after
  acceptance.
- **The citation check over-flags until updated.** `scripts/lib/delegation-citation.ts`
  maps only the two older acts to words, so a spec saying a selection was made "under
  DLG-002" is flagged as wrong until that map learns `clarify-selection`. That errs on the
  safe side.
