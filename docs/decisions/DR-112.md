# The bot merges, by admin bypass where needed, under three conditions

> **Born `proposed` per DR-029.** Acceptance is a separate human act (*MinSpec: Accept
> ADR*), and DR-086 keeps DR acceptance on the stop list (section 2, class 2). This record
> is `kind: direction`, which no delegation covers. An agent never mints the sign-off.
> Nothing in it takes effect before the founder accepts it: the merge verb it relies on
> reads this file's `status:` on `main` and refuses every merge unless it reads `accepted`.

> **On this record's number.** It is one above the highest id on `main`, and the only open
> pull requests touching `docs/decisions/` carry DR-065 and an id below this one (read
> 2026-10-24). The collision gate (`scripts/check-dr-id-collision.ts`) re-checks it on this
> record's own pull request. Bodies here do not spell out local ids of 100 and above, per the
> parent-register reference gate (#2148), so records in that range are named by subject.

## In plain terms - what this changes for you

Today every merge waits for your keystroke, and every machinery merge waits for your
`--admin`. With this decision, once you accept it and run one ruleset command, the bot
(`minspec-sdd[bot]`) merges a pull request itself when CI is green, a second AI reviewer
that did not write the change agrees, and the merge is pinned to the exact commit that was
reviewed. For machinery pull requests, which can never go fully green because a gate cannot
certify a change to itself, the bot uses `--admin` past those self-certification gates and
nothing else. memory-fabric, `~/.claude` patches, and the few things on the stop list stay
yours. The cost you accepted: a machinery change that both AI reviewers miss lands with no
human look, and once the App can bypass the ruleset, the checks that keep that bypass narrow
are the bot's own helper, not GitHub.

## Context

The rule being lifted: on 2026-07-28 the founder made `--admin` human-only: "Never use
the App token to bypass branch protection or a required check. A PR that needs `--admin`
waits for the human merge keystroke." It is restated in `~/.claude/CLAUDE.md`, in DR-086
(section 2.1 and its Amendment A: "`--admin` remains human-only and no failing check may be
bypassed"), in DR-070 section 4 ("No unit of work ever has zero human keystrokes"), and in
the chief-of-staff-runner skill. GitHub enforces it today by configuration: the App is not a
bypass actor on `main`'s ruleset (the bot reads `current_user_can_bypass: never`).

What the keystroke has been catching: an audit of 391 commands queued for the founder
found 200 merges among them: 92 `--admin` merges of machinery pull requests, 95 plain or
auto merges, and 13 memory-fabric merges. He ran every one unchanged and never caught an
error. A human gate must name the error it catches that no machine check catches (core
tenet 1); on this record, the merge keystroke caught none, and it cost a queue item, a
copy-paste and a wait on every pull request.

Why machinery needs `--admin` at all: on a pull request touching `.github/`,
`scripts/` or `.githooks/`, `ai-review` concludes NEUTRAL ("machinery PR - exempt, human
review required"), `machinery-review-required` concludes ACTION_REQUIRED, and the
`ready-to-merge` and `ai-review/pass` commit statuses post FAILURE, by design (#596: a gate
cannot certify a change to itself). Measured on #3031: every other check SUCCESS, those
four red, label `ai-review:pass`, four-voter verdict comment all pass. `ready-to-merge` is a
required check, so no merge of such a pull request is possible without a bypass.

## Decision

### 1. When the bot merges

`minspec-sdd[bot]` merges a pull request in a repository under AIClarityAU, by squash, when
all three of the founder's conditions hold:

- **(a) CI is green.** Every latest check on the head commit has finished, and finished
  SUCCESS, SKIPPED or NEUTRAL. A pending check, a failing check, or zero checks refuses.
- **(b) A second, independent AI review agrees.** A verdict, separate from the review panel
  that `ai-review` runs, from a reviewer that is not the change's author, says `pass` on the
  exact head commit. On AIClarityAU/minspec the `ai-review` panel's own pass is required as
  well, by the ruleset.
- **(c) The merge is pinned to the reviewed commit.** `gh pr merge --match-head-commit
  <sha>`, with the full 40-character sha both reviews judged. A push after the review makes
  GitHub refuse the merge. Native auto-merge is never armed (it stays armed across later
  pushes; the approval-only self-merge record rejected it for the same reason).

### 2. What stays the founder's (never merged by the bot)

> **Amended by [DR-119](DR-119.md) (on acceptance; a local record, not a parent register one).** Staged
> while that record is `proposed`; it changes nothing until that record is accepted. From then on, a
> pull request that carries only one delegated spec approval and meets that record's section 1 is merged
> by the bot through that record's lane, although it touches `.minspec/approvals/`, which this section
> keeps from the bot. Condition (b) of section 1 here does not apply to it, and "approval is his act"
> does not reach a delegated approval. The helper in section 5 is unchanged and still refuses those pull
> requests. Everything else in this record stands.

- **AIClarityAU/memory-fabric**, every pull request.
- **`~/.claude` patches.** They are not pull requests on AIClarityAU at all; the helper's
  owner pin refuses any other owner.
- **Everything on the DR-086 stop list except the merge keystroke itself.** In merge terms:
  a pull request that touches the constitution, `.minspec/delegations.json`,
  `.minspec/config.json`, `.minspec/approvals/` (the founder's own approvals land through
  the approval-only self-merge record's lane instead), the autonomy mechanism, DR-086, or
  this record; one whose diff adds
  a `status: accepted` or `status: approved` line (acceptance and approval are his acts); and
  one whose merge deploys something (`sites/**`, `.github/workflows/deploy-sites.yml`),
  because the merge would then be an outward-facing act beyond itself.
- **Anything with a `hold:*` label**, a draft, or a pull request from a fork.

### 3. When the bot may use `--admin`

Only on AIClarityAU/minspec, and only when every one of these holds on the head commit:

1. The pull request is machinery: `machinery-review-required` ran on this head and concluded
   ACTION_REQUIRED.
2. The **only** checks that are not SUCCESS, SKIPPED or NEUTRAL are the self-certification
   gates, each in its by-design state: `ai-review` NEUTRAL, `machinery-review-required`
   ACTION_REQUIRED, `ready-to-merge` FAILURE, `ai-review/pass` FAILURE.
3. `ai-review:pass` is bound to the head: the label is present, an `ai-review` run exists on
   this head, and the last verdict comment from `minspec-sdd` has every voter at `pass`,
   blocking 0, and was posted no earlier than 120 seconds before that run (a verdict on an
   earlier head is older than the head's run, so it fails).
4. The second independent AI verdict of condition (b) passes on this sha.
5. The runner's existing predicate, `admin_mergeable()` in `~/.claude/scripts/cos.py`,
   agrees. It adds what it already checks: no autonomy-path files, every required check from
   the ruleset satisfied except the self-certification gates, those gates actually ran, the
   branch provably up to date, no conflicts.

### 4. What is never bypassed

- **Any failing required or non-required check** other than the four self-certification
  gates in their by-design states. A real failure is never merged past, with or without
  `--admin`.
- **Any missing check.** A required check that never ran on the head is a missing witness and
  fails closed (constitution invariant 2); the bot does not read "absent" as "passed".
- **The up-to-date requirement.** A branch behind `main` is updated and re-checked, never
  bypassed.
- **Force-push and deletion of `main`**, which stay blocked for the App: its bypass mode is
  `pull_request`, so it can bypass only when merging a pull request.

### 5. Where each condition is enforced

- **GitHub** enforces condition (c) (the merge is refused if the head moved) and, for every
  non-`--admin` merge, the whole ruleset.
- **The helper** `~/.claude/scripts/cos-runner/cos-runner-gh.sh` gains a `pr merge` verb, the
  runner's only merge path. It requires `--match-head-commit <40-hex sha>`, `--squash`,
  `--repo` and `--verdict-file`; refuses memory-fabric, any other owner, `--auto`,
  `--disable-auto`, `--merge`, `--rebase`, `--delete-branch` and inline merge text; reads this
  record's `status:` on `main` before every merge and refuses unless it reads `accepted`,
  failing closed if the read fails; and checks sections 1 to 4 above, each failing closed on
  an unreadable input. Staged with 69 tests (every refusal asserts no merge was recorded; the
  allow cases assert the exact merge command).
- **The ruleset** gains App 4212099 as a bypass actor (mode `pull_request`). Without it,
  `--admin` from the bot is refused by GitHub, so the change is inert until the founder runs
  it.

## Cost

- **The named risk, accepted by the founder:** a machinery change that both AI reviewers
  miss lands on `main` with no human look. Before this, that change still met the founder's
  keystroke, which on the audit never caught one.
- **The bypass is wider at GitHub than in this record.** Once App 4212099 is a bypass actor,
  GitHub lets the App merge *any* pull request on minspec past *any* rule, including a
  failing required check. The narrowing in sections 3 and 4 is enforced by the helper, which
  is the runner's path but not the only process that can mint the App token. A session that
  calls `gh` directly with a minted token could `--admin` past a red check, and GitHub would
  allow it. Today config enforces "human-only"; after this, convention plus the helper do.
  Bounded by: the `pull_request` bypass mode; the follow-up audit below, which flags any
  bot-merged pull request whose required checks were red outside the four by-design states;
  and the rollback, which restores enforcement by config in one command.
- **The second verdict's independence is process, not proof.** The helper checks the
  verdict's form (pass, same sha, reviewer differs from author). That the reviewer really was
  a fresh, independent agent is the runner's discipline.
- **The 120-second binding window.** The verdict comment and the `ai-review` run are posted
  by one workflow run within seconds of each other (#3031: one second apart). The window
  tolerates either order; a verdict on an earlier head would have to be posted within 120
  seconds of the new head's finished review to pass, and that review posts a newer comment
  of its own.

## Rejected alternatives (DR-086 §4)

- **Option 2 of merge-who: the bot merges, but never with `--admin`.** Rejected by the
  founder. It would leave every machinery pull request on his keystroke: 92 of the 200
  audited merges, the very class that queues longest.
- **Option 3: a daily batch the founder runs in one paste.** Rejected by the founder. It
  keeps a keystroke that caught no error, and adds up to a day of latency.
- **Option 4: as now.** Rejected by the founder for the same reason as option 3.
- **Bypass mode `always`.** Rejected: it would also let the App push straight to `main`;
  `pull_request` limits the bypass to merges.
- **Letting `ai-review` certify machinery so no bypass is needed.** Rejected: a gate that
  certifies a change to itself is the defect #596 exists to prevent.
- **Arming native auto-merge after the reviews.** Rejected as in the approval-only
  self-merge record: auto-merge stays
  armed across later pushes.

## Consequences

- Merges, including machinery `--admin` merges, stop appearing in the founder's queue once
  this record is accepted, the patch is installed and the ruleset command is run, in that
  order. Before all three, nothing changes: the helper refuses every merge while this record
  is `proposed`, and GitHub refuses the bot's `--admin` while the App is not a bypass actor.
- memory-fabric merges and the kept classes in section 2 still reach him, as queue items.
- The bot is now the actor on machinery merges, so the audit trail shows
  `minspec-sdd[bot]` as the merger, truthfully.

## Rollback

Remove App 4212099 from the ruleset's bypass actors (the exact command is staged with the
ruleset change). From that moment GitHub refuses every bot `--admin`, whatever the helper
says, and "human-only" is enforced by config again. Plain bot merges stop by moving this
record to `superseded` or `deprecated`: the helper refuses every merge unless it reads
`accepted`.
