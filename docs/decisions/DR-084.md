# DR-084: Direct HTTPS for the shadow-triage harness — designing the exfiltration hazard out rather than mitigating it

## Context

The GLM shadow-triage instrument (#1338) runs a second model alongside the live triage
agent on the same issue, pushes both outputs through the same deterministic gate, records
the agreement and discards the shadow verdict. It exists because the drain loop and the
required `ai-review` merge gate draw on one Anthropic subscription quota, so the queue
jams when that quota runs out (#1234) — and because GLM's fitness for *our* task shape was
unmeasured, which per this repo's evidence discipline makes the honest next step an
instrument rather than a switch.

The original transport was `claude -p` with `ANTHROPIC_BASE_URL` pointed at z.ai. That
put a third-party endpoint one environment variable away from the founder's subscription
credential, so the design carried an elaborate defence: `--bare` (whose documented
contract is that OAuth and the keychain are never read) plus a long `env -u` list
scrubbing every credential the process might have inherited.

**It did not work, and the way it failed is the point.** Measured on the operator box
2026-08-07, all three routes are dead:

| route | result |
|---|---|
| `--bare` + `ANTHROPIC_API_KEY=<z.ai key>` | `Invalid API key · Fix external API key` |
| `--bare` + `apiKeyHelper` via `--settings` | same |
| no `--bare`, Anthropic env scrubbed | **ignored `ANTHROPIC_BASE_URL`** and hit `api.anthropic.com` on the **stored** credential |

The likely cause of the first two is shape: a z.ai key is 49 characters and carries no
`sk-ant-` prefix. But the third row is the one that matters for this decision. With the
environment scrubbed exactly as designed, the CLI reached past the scrub, ignored the
base URL it was given, and authenticated to Anthropic on a credential the scrub could not
touch. That is not a bug to be patched — it is the enumeration strategy failing in
practice, on the very run that was supposed to demonstrate it working.

## Decision

**The shadow transport is a direct HTTPS POST to `/v1/messages`, issued with `curl`.**
`scripts/lib/shadow-triage.sh` builds the request; `scripts/shadow-triage.sh` sends it.

### 1. Read the removal of the scrub as a strengthening, not a weakening

This is the part most likely to be misread by a future reader, so it is recorded
explicitly. The diff deletes `--bare` and a ten-entry `env -u` list. That looks like
security being removed. It is the opposite.

The old apparatus existed for exactly one reason: **a CLI resolves credentials by
itself.** It reads `~/.claude/.credentials.json`, the OS keychain, `ANTHROPIC_AUTH_TOKEN`,
a custom header bag, Bedrock and Vertex switches. The scrub was a running attempt to
enumerate and close every one of those doors, and it could only ever be as complete as
the enumeration — which the third row above shows it was not.

`curl` resolves nothing. It sends the bytes it is given. The request carries exactly one
credential header, and there is no code path by which an Anthropic credential could join
it:

- **not from the environment** — curl does not read `ANTHROPIC_*` at all;
- **not from disk** — `--disable` (required to be curl's *first* argument) makes it ignore
  `~/.curlrc`, which could otherwise inject an `Authorization` header;
- **not from a redirect** — `--location` is deliberately never passed, so the credential
  header cannot be replayed to whatever host a `302` names.

The hazard is not mitigated here. It is **structurally absent**. A defence that must
enumerate its attack surface is strictly weaker than one where the surface does not exist,
even when the enumeration is currently complete — because completeness is a property that
decays silently with every upstream release.

### 2. The credential never enters argv

`/proc/<pid>/cmdline` is world-readable, so `-H "x-api-key: $KEY"` publishes the key to
every local user for the life of the request. This is not hypothetical: the security
reviewer flagged exactly that shape as `low` on the model-resolution change that first
introduced a curl call into this harness.

Headers are therefore written to curl's **stdin** via `curl --config -`, emitted by bash's
`printf` **builtin** — a builtin forks no process and so never acquires a cmdline of its
own. There is deliberately **no debug seam that prints the request headers**; the absence
of one is a design element, not an omission.

### 3. The instrument no longer spends the quota it exists to relieve

A quieter consequence, but a real one: the shadow path no longer runs `claude` at all, so
it cannot consume the Anthropic quota (#1234) whose exhaustion motivated the pilot. Under
the old transport the measurement competed with the thing being measured.

### 4. Purity boundary: builders in the lib, sending in the runner

`scripts/lib/shadow-triage.sh` keeps its "nothing touches the network" contract. It holds
request *builders* (`shadow_curl_config`, `shadow_curl_argv`, `shadow_request_body`,
`shadow_endpoint_url`) which emit bytes and never send them. The two functions that
actually reach the network — `shadow_http` and `shadow_resolve_model` — live in the impure
runner. "Pure" here means referentially transparent, not process-free: several builders
shell out to `jq` and `python3` to parse.

This boundary was reasserted deliberately. An earlier draft moved the network functions
into the lib and relaxed its header comment to match; the reviewed contract won instead,
because a file whose stated contract drifts to fit its contents stops being a contract.

### 5. Failure modes are typed, and fail *safe* rather than *closed*

`shadow_classify_error` gives an endpoint error a machine-stable reason rather than
letting it reach the gate as a malformed verdict. This matters for measurement integrity,
not just tidiness: `error` means no usable response came back (infrastructure), while
`conformant:false` means a response came back and did not match the schema — the metric
#1338 actually asked for, and the one its 2% malformed-rate rollback trigger reads.
Collapsing the two would let a z.ai outage masquerade as a GLM schema failure.

Model resolution fails **safe, not closed**, and the asymmetry with [DR-066](DR-066.md) is
intentional: DR-066 forbids swallowing a load-bearing **gate** signal, and this is a
measurement instrument that changes no outcome. If the model listing cannot be fetched the
run is skipped, never run against a guessed id — a row labelled with the wrong model is
worse than no row.

## Alternatives considered

**Keep `claude -p` and harden the scrub further.** Rejected on evidence, not taste: the
measured failure was the CLI ignoring `ANTHROPIC_BASE_URL` and using a stored credential,
which no addition to an `env -u` list can reach. Continuing would have meant extending an
enumeration that had just been shown to be incomplete.

**Route through the scrooge tee-proxy.** Rejected. It would put a third party inside the
path of a credential the standing rule says must never traverse one, and it makes the
instrument depend on the proxy's availability for a measurement about a different system.

**Use an SDK client instead of curl.** Rejected for this use. An SDK is a credential
resolver by design — the exact property being removed — and it would add a dependency to
a Tier-0 shell harness that currently has none.

**Do nothing; wait for the CLI to support the endpoint.** Rejected. The pilot cannot start
without a transport, and the quota jam it addresses is present now.

## Consequences

**Good.** The exfiltration class is designed out rather than defended against. The key is
absent from `ps` and `/proc`. The shadow path costs no Anthropic quota. Error and
truncation cases are typed and excluded from the malformed-rate metric, so the pilot's
headline figure means what it says.

**Costs, stated plainly.** The harness now owns request construction, response parsing
and error classification that the CLI used to own — more code in a shell script, and a
schema this repo must keep in step with the Anthropic-compatible API by hand. `--bare`
was also a *setting-source* guarantee, not only a credential one, so its removal is
recorded in `agent-context-slim.test.ts`: no launcher uses that spelling today, and the
shadow path no longer enters that gate's scan at all because it is not a `claude -p` call.

**Tests.** Each load-bearing security assertion is mutation-checked rather than merely
written — key restored to argv, `--location` added, `--disable` displaced from first
position, and untrusted prompt text interpolated instead of `jq --rawfile` each redden
their intended case. The `/proc` assertion is hermetic and offline: a local TCP listener
accepts and never answers, so a real curl hangs long enough to be read out of `/proc`
without a packet leaving the machine.
