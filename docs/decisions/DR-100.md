## In plain terms - what this changes for you

MinSpec goes on the VS Code Marketplace, marked as a preview, before the work the
constitution says must come first is finished. It happens once, for one reason: you need
it on a Windows work PC and a public registry is how it gets there. Nothing else that
was waiting for "public-ready" comes along with it, publishing is still something only
you do, and the list of things that must be true first is written below so the date
cannot quietly outrun them.

## Context

The founder needs MinSpec on a Windows work PC that runs Microsoft's VS Code, and asked on
2026-10-01 for the extension to be published just before the visualiser work, about a week
out. The constitution puts a Marketplace publish in Phase 2 and says Phase 2 work may not
displace unfinished Phase 1 work, so publishing now needs a recorded exception, with its
scope and preconditions stated.

**The request.** Founder, 2026-10-01, as relayed in the dispatch brief this record was
written from: *"work pc is windows with MS vscode. publish vsix just before
visualiser"*. The brief adds a target of about a week, and that the visualiser work
follows the publish.

**What the standing decisions say.**

- The constitution splits delivery in two. *"Phase-1 work always outranks Phase-2
  work"* until the Phase 1 line is met (`.minspec/constitution.md:71-74`). It names
  *"Marketplace publish, public onboarding"* as *"Explicitly out of Phase 1"*
  (`:100-102`), places the *"Marketplace listing + onboarding"* in Phase 2, and allows
  Phase 2 polish only *"as long as no Phase-2 item displaces an unmet Phase-1 item"*
  (`:104-108`). All six Phase 1 boxes are unticked (`:88-98`).
- DR-075 made MinSpec a solo-first personal tool, open-sourced as a gift: repositories
  go public *"with no publish deadline and no share-of-voice urgency. Marketplace
  publishing remains a separate, founder-approved act"* (`docs/decisions/DR-075.md:61-64`),
  and it rejected *"Publish immediately for share of voice"* (`:87-88`).
- DR-076 kept *"Irreversible or outward-facing acts. Marketplace publish, repo
  visibility flips, deletes, anything leaving the machine"* as one of the two moments
  that stay human (`docs/decisions/DR-076.md:84-85`).

So a publish now is not forbidden by DR-075, which leaves the timing to the founder. It
does cut across the constitution: a Phase 2 item moves ahead of unmet Phase 1 items, and
the work it drags with it displaces Phase 1 work for about a week. That is what needs a
record.

**The state of the listing today** (measured 2026-10-01 from the Marketplace gallery API
and `open-vsx.org`):

- `aiclarity.minspec` exists on the VS Code Marketplace and is flagged `unpublished`. It
  holds seventeen versions, 0.1.0 (2026-05-27) to 0.1.16 (2026-05-29), and reports 206
  downloads and one install. So this is a re-publish of an existing listing, not a first
  appearance.
- Open VSX answers 404 for `aiclarity.minspec`.
- The manifest is at 0.1.26 with `"preview": false` (`packages/minspec/package.json:5`,
  `:21`). Versions 0.1.17 to 0.1.26 were local builds. The version has not moved since
  2026-07-31 while two months of changes merged, so "0.1.26" names more than one build.
- The "MinSpec Pro" extension pack cannot ship: its manifest lists the unpublished
  `aiclarity.scroogellm` (`packages/extension-pack/package.json:28-31`), is marked
  `private` (`:6`), and its `package` script prints a refusal and exits non-zero (`:33`).
  ScroogeLLM is shelved (constitution G-5, `.minspec/constitution.md:48-52`).

**What a read-only readiness pass found.** Three blockers (#2328 against invariant 3,
#2329 against invariant 1, and #2205, a prompt promoting a shelved product), four more
found while fixing them (#2355, #2364, #2365, #2356), listing text five months out of
date (#2393), and, from a Windows audit that ran nothing on Windows, eight hazards of
which four were reproduced on Linux by imitating Windows (#2397 to #2404). CI has never
run the extension on Windows: every job in `.github/workflows/ci.yml` is
`runs-on: ubuntu-latest`.

## Decision

1. **Publish `aiclarity.minspec` to the VS Code Marketplace as a preview, ahead of the
   Phase 1 line, as a one-time bounded exception to the constitution's phase order.**
   The reason is distribution to one machine, not audience. It is not the "share of
   voice" publish DR-075 rejected, and it sets no precedent for other Phase 2 items.

2. **Scope.**
   - The MinSpec extension only, with `"preview": true` in the manifest.
   - The "MinSpec Pro" extension pack is not published.
   - Open VSX is optional and not part of this decision. It can follow under the same
     preconditions.
   - The exception covers the work listed under Preconditions and nothing else. Public
     onboarding, site and marketing copy, and the other items the constitution lists as
     out of Phase 1 stay where they are.

3. **Preconditions.** Every one must be true of the commit the release is built from.
   The date is a target; an unmet precondition moves the date, never the other way.

4. **What this does not change.**
   - The Phase 1 exit criteria (`.minspec/constitution.md:86-98`) are untouched. Publishing
     does not tick any of them, and Phase 1 work outranks Phase 2 work again as soon as
     the publish is done.
   - Publishing stays a human act (DR-075, DR-076). No agent runs `vsce` or `ovsx`, and
     no agent holds a Marketplace token.
   - Invariants 1, 2 and 3 are not relaxed for the preview. The preconditions exist
     because of them.
   - DR-075's "no publish deadline" stands. This record adds a reason to publish, not a
     date that must be met.

## Alternatives rejected

- **A private `.vsix` file carried to the work PC.** Ruled out by the founder. The
  brief's premise is that only a public registry reaches that machine. Why a file cannot
  be installed there was not recorded, so that premise is taken as given here
  (inferred, unverified).
- **Open VSX only.** The work PC runs Microsoft's VS Code, which installs from the
  Visual Studio Marketplace and does not read Open VSX by default (inferred,
  unverified: general knowledge about the product, not checked in this repository).
- **Wait for Phase 1.** It leaves no path to the work PC in the meantime, and Phase 1
  has no date.
- **Publish as it stands.** The readiness pass found the extension creating its opt-in
  marker in folders that never opted in and contacting GitHub without asking. Shipping
  that to strangers breaks invariants 1 and 3 on their machines, and the listing would
  state the opposite of what the code does.

## Costly to Refactor

1. **A version cannot be withdrawn and reused.** The Marketplace still holds all
   seventeen versions of the unpublished listing, and the history records a version slot
   being lost that way (commit `2646e9569`, "0.1.8 slot already taken on marketplace").
   Check: P7 before the build.
2. **Installed copies cannot be recalled.** Unpublishing stops new installs; it does not
   remove the extension from machines that have it (inferred, unverified: general
   Marketplace behaviour). What a preview does on first activation and on Initialize is
   therefore the hard part to take back. Check: P1, P2 and P5.
3. **Files Initialize writes into a stranger's repository stay there.** Forty files,
   among them six workflows and the git hooks, and a changed `core.hooksPath`
   (measured, recorded in #2393). Check: the listing says so (P4); #2406 and #2407 track
   the two sharpest edges.
4. **Low: the decision itself.** The listing has been unpublished before, so the act
   can be undone for anyone who has not installed yet.

## Consequences

- For about a week the work in the preconditions takes priority over Phase 1 work. That
  is the displacement the constitution forbids by default and this record permits once.
- Strangers can install MinSpec. The repository is already public (DR-076, 2026-08-21
  note), so this adds users, not readers. Their first experience includes two things
  not fixed by any precondition: a failing `ready-to-merge` status on every pull request
  until a reviewer is configured (#2407), and listing screenshots that show an older
  interface (#2394).
- The root README says nothing is published and must change in the release commit
  (#2409).
- The exception is closed by the publish. A second Phase 2 item wanting to jump the
  line needs its own record.
