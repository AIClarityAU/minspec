# DR-014: Shared-code boundary and co-existence rules for MinSpec + ScroogeLLM

## Context

MinSpec (`aiclarity.minspec`) and ScroogeLLM (`aiclarity.scroogellm`) are two
independent VS Code extensions in one monorepo. They can be installed **together**
— either separately, or via the MinSpec Pro pack (`aiclarity.minspec-pro`), which
is byte-identical at runtime to installing both (the pack only references them).
So "both installed" is the case that must be safe; the pack is not a safeguard.

Two facts force a boundary decision now:

1. **The classifier is becoming a real second-consumer shared module.** ScroogeLLM's
   router will route cheap-model vs SOTA partly on the task **complexity tier**, so
   it needs the same tier vocabulary and scoring engine MinSpec uses. Until now the
   classifier lived in `packages/minspec/src/lib/classifier.ts` with one consumer;
   CLAUDE.md already (incorrectly) described `@aiclarity/shared` as "the shared
   classifier." It is time to make that true — correctly.

2. **DR-004 split the product into network/trust tiers.** `@aiclarity/shared` and
   `packages/minspec` are **Tier 0** (air-gapped: no `http`/`https`/`fetch`/`net`,
   no process spawn). That offline guarantee is MinSpec's marketplace selling point.
   Anything shared must not break it.

When two extensions touch the same project's `.minspec/` directory and each bundle
their own copy of shared code, three overlap hazards appear that the manifest layer
does **not** catch (commands/config/views are already namespaced `minspec.*` /
`scroogellm.*`):

- **Concurrent writers to a shared on-disk artifact** (e.g. `.minspec/calibration.json`)
  → race / corruption.
- **Version skew between the two bundled copies of `@aiclarity/shared`** → MinSpec
  classifies a task T3 while ScroogeLLM routes it as T2. No crash; silent disagreement.
- **Tier-0 contamination** — pulling Tier-1 logic (CLI delegation, process spawn)
  into `shared` to "reuse" it would void the air-gapped claim for both extensions.

## Decision

### 1. Tier → package map (canonical)

| Package | Tier | May contain | May NOT contain |
|---|---|---|---|
| `@aiclarity/shared` | **0** | Pure TS: contract types, classifier engine, pure logic, `fs`/`path` reads of `.minspec/` | `vscode`, `http`/`https`/`fetch`/`net`, child-process spawn |
| `packages/minspec` | **0–1** | Extension UI/commands, signal producers, MinSpec-owned writes | network code in Tier-0 paths |
| `packages/scroogellm` | **2** | Proxy, routing, network (localhost-default per INV-11) | writes to MinSpec-owned artifacts |
| Tier-1 agent runtime | **1** | CLI delegation, process spawn (see DR-015) | — must live **outside** `shared` |

Tier-1 process-spawn / CLI-delegation code is **never** added to `@aiclarity/shared`.
If shared between extensions it gets its own package (DR-015), preserving shared's
Tier-0 air-gapped guarantee.

### 2. Classifier split — engine to shared, signal producers stay local

Move to `@aiclarity/shared` (Tier 0, no vscode):

- `Tier` / `Phase` types, `ClassificationSignal` / `ClassificationResult` shapes.
- The scoring function (signals → tier), tier-compare, suggested-phase mapping.
- Calibration **read** (`.minspec/calibration.json`).

Stay in `packages/minspec`:

- **Signal producers** — `git-analyzer`, `ast-analyzer`. They measure a *code diff*.

ScroogeLLM produces its **own** signals from the prompt/request it is about to route,
then calls the shared scorer. Same engine, different signals in. This is the seam:
**share the engine + vocabulary, each extension brings its own signal producers.**

### 3. Single-writer per on-disk artifact

Every file under a shared location has exactly **one writer at any time**; all other
consumers are read-only.

| Artifact | Writer | Readers |
|---|---|---|
| `.minspec/calibration.json` | **MinSpec when present; ScroogeLLM when MinSpec absent** (elected — see below) | the non-writer (read-only, to route) |
| Conformance contract export | **MinSpec** (`bridge.ts`) | ScroogeLLM (read-only) — already the design |
| `.minspec/config.json`, specs, ADRs | **MinSpec** | ScroogeLLM read-only |

#### Calibration writer election (issue #53)

Calibration ownership is **conditional, not absolute** — ScroogeLLM is a standalone
product and must still self-calibrate when installed alone:

- **MinSpec present (installed + enabled) → MinSpec is sole writer.** ScroogeLLM
  read-only, consumes calibration to route.
- **MinSpec absent → ScroogeLLM is the writer.** Falls back to owning the file.

The check is **asymmetric, which removes any election race**: MinSpec writes
*unconditionally* (never checks for ScroogeLLM); only ScroogeLLM tests for MinSpec
(`vscode.extensions.getExtension('aiclarity.minspec')`) before taking the writer
role. So two writers can never coexist — MinSpec always wins by construction, no lock
or handshake needed. ScroogeLLM re-evaluates on `vscode.extensions.onDidChange` and
**drops** the writer role the moment MinSpec appears (and takes it when MinSpec is
removed/disabled).

Handoff is seamless because the **shared engine writes one identical schema**
(§2, §4): whichever extension owns the file, the format and semantics match, so the
other reads it without translation. Conformance/config/specs remain
MinSpec-only-writer regardless — no fallback, since they are MinSpec artifacts with no
meaning when MinSpec is absent.

Shared calibration also means a tier correction a user makes in MinSpec fixes
ScroogeLLM's routing for that project — a feature, not just a constraint (sell it; #55).

### 4. Version lockstep + detectable mismatch

Each `.vsix` bundles its own copy of `@aiclarity/shared` (esbuild). Two copies are
safe **only at the same version**.

- Both extensions pin and ship the **same `@aiclarity/shared` version**, bumped together.
- The Pro pack only ever ships **matched** versions; never publish one extension on a
  newer shared than the other.
- Stamp an **engine/contract version** in the artifacts that cross the boundary
  (`ConformanceContract.version` already exists; add an engine-version field to the
  calibration read path) so a skew is **detected and surfaced**, not silent.

### 5. Namespacing (already holding — keep it)

Commands, config keys, view IDs stay per-extension prefixed (`minspec.*` /
`scroogellm.*`). Never a shared key. The cross-extension upsell nudge is already
suppressed when the other extension is installed (`bridge.ts`); ScroogeLLM must
**mirror** this (no Pro upsell when MinSpec present).

## Costly to Refactor

- **The tier→package map** (what each package may / may not contain) — THE architectural boundary; changing it = re-layering imports across packages. *Check: `@aiclarity/shared` stays Tier-0 (no vscode/http/spawn).*
- **Single-writer-per-artifact + version lockstep** — relaxing either invites disk-artifact races / version skew, expensive to retrofit. *Check: one writer per `.minspec/` artifact; packages version in lockstep.*

## Consequences

**Positive:**

- Classifier engine + types relocate from `packages/minspec/src/lib/classifier.ts`
  to `@aiclarity/shared`; minspec imports them via the package name (never deep paths
  — see the `index.ts` barrel rationale). Signal producers stay put — so the Tier-0
  air-gapped guarantee (DR-004) holds for both extensions while the scoring engine is
  reused.
- The shared engine writes **one identical calibration schema** (§2, §4), so the
  MinSpec↔ScroogeLLM writer handoff (§3 election) is seamless with no translation
  layer — and a tier correction in MinSpec fixes ScroogeLLM's routing for that project
  (sold as a feature, #55).
- ScroogeLLM's Specify phase inherits these as hard constraints (read-only consumer,
  own signal producers, mirrored nudge), so its design starts from a settled boundary
  rather than re-litigating overlap hazards.

**Negative:**

- A single-writer rule must be enforced in review for every `.minspec/` artifact —
  ongoing reviewer burden, since the namespacing layer does not catch shared-disk
  races (Context, §3 table).
- CI/publish gate: a new check must assert both extensions resolve the **same**
  `@aiclarity/shared` version before packaging the pack (§4) — added pipeline
  machinery that can block a release on version skew.
- An engine-version field must be added to the calibration/contract read path (§4),
  touching `ConformanceContract.version` and the `.minspec/calibration.json` reader on
  both sides.
- ScroogeLLM cannot independently bump `@aiclarity/shared`; both `.vsix` versions are
  locked in lockstep (§4), so a shared-only fix forces a coordinated dual release.

## Alternatives considered

- **Leave classifier in minspec, have ScroogeLLM depend on the minspec package** —
  rejected: makes ScroogeLLM depend on a vscode-coupled extension package and its UI
  surface; the Tier-0 engine should not drag the extension with it.
- **Both extensions write calibration** — rejected: concurrent-writer race on a JSON
  file with no locking; corruption under normal use.
- **Allow independent shared versions per extension** — rejected: silent tier
  disagreement is the worst failure mode (no error, wrong routing/classification).
- **Fold the Tier-1 agent runtime into `shared` to reuse it** — rejected: voids the
  air-gapped Tier-0 marketplace claim for both extensions (DR-004).

## Risks & Mitigations

| Risk | Mechanism / anchor | Mitigation |
|---|---|---|
| **Election re-eval drops a write window.** ScroogeLLM is the writer (MinSpec absent), MinSpec gets enabled, and the `onDidChange` handler (§3) hasn't yet dropped ScroogeLLM's writer role → a brief two-writer overlap on `.minspec/calibration.json`. | §3 says the check is asymmetric (only ScroogeLLM tests `getExtension('aiclarity.minspec')`), but the transition is event-driven, not atomic. | Asymmetry already removes the *steady-state* race (MinSpec writes unconditionally, always wins). For the transition, MinSpec's unconditional write means its value is authoritative the instant it runs; ScroogeLLM's identical schema (§4) means a stale ScroogeLLM write is at worst overwritten, never corrupting (same fields). Surface as issue #53's test case. |
| **Version-lockstep gate is bypassable / unbuilt.** §4 mandates a CI/publish assert, but if the pack is published without it both `.vsix` could ship mismatched `@aiclarity/shared` → silent tier disagreement (the worst failure, per Alternatives). | The lockstep rule is currently prose in §4; no enforcing check exists yet. | The engine-version stamp in the calibration/contract read path (§4) makes skew **detected at runtime** even if the publish gate is skipped — defence in depth. Build the CI assert as a tracked issue (Status). |
| **Tier-0 contamination creeps in via a "small" shared helper.** A future PR adds `fetch`/spawn/`vscode` import to `@aiclarity/shared` to "reuse" something, voiding the air-gapped claim (DR-004) for both extensions. | The tier→package map (§1) is the only guard; nothing mechanically blocks the import today. | Map is "Costly to Refactor" and explicitly enumerates the forbidden imports per package (§1 table). Harden with a lint/import-boundary check on `@aiclarity/shared` as a follow-up (sibling to the DR-004 air-gap assertion). |
| **Signal-producer drift makes the shared scorer mis-fire.** ScroogeLLM builds its own signals (§2) from prompt/request; if its signal shape diverges from what the shared scorer expects, scoring is wrong with no crash. | §2 shares the engine + `ClassificationSignal` shape but lets each extension produce its own signals. | The `ClassificationSignal`/`ClassificationResult` **contract types** live in `@aiclarity/shared` (§2), so producer output is type-checked against the scorer's input at both call sites. T1 contract tests on the scorer's public surface. |

This DR bundles five decisions in materially different states. Recorded per clause so
ratifying it does not silently ratify a relocation that never happened, or a tier map naming
a package this repo no longer contains. Each row was verified against `main`, not inferred.

| # | Clause | State |
|---|---|---|
| 1 | Tier → package map | **Partly superseded.** The `@aiclarity/shared` (Tier 0) and `packages/minspec` rows hold — `packages/shared/src` has no `vscode`, `http`/`https` or `fetch` import. The `packages/scroogellm` row is moot: [DR-027](DR-027.md) (accepted) moved ScroogeLLM to its own private repo, and this monorepo contains only `extension-pack`, `minspec`, `shared`. |
| 2 | Classifier split — engine to `shared` | **Not executed.** The engine is still `packages/minspec/src/lib/classifier.ts`; `packages/shared/src/classifier.ts` does not exist. Tracked at [#54](https://github.com/AIClarityAU/minspec/issues/54). |
| 3 | Single-writer per on-disk artifact | **Premise changed, enforcement unverified.** The writer/reader table is written around both extensions sharing one checkout; after DR-027 they are separate repos. `bridge.ts` exists but contains no calibration handling, so the [#53](https://github.com/AIClarityAU/minspec/issues/53) writer election is not visible in this repo. Nothing enforces single-writer today. |
| 4 | Version lockstep + detectable mismatch | **Premise changed.** "Both extensions pin and ship the same `@aiclarity/shared` version, bumped together" assumed one monorepo; post-DR-027 this is a cross-repo release constraint with no mechanism here. |
| 5 | Namespacing | **Holding.** Verified: all 44 contributed commands and all 17 configuration keys in `packages/minspec/package.json` are `minspec.*`-prefixed; zero exceptions. |

**What is actually enforced today** is the one clause this DR did not spell out as a task:
`@aiclarity/shared` is consumed **barrel-only**, banned deep-import, at `error` — shipped by
[DR-064](DR-064.md) / SPEC-040 and live in CI. DR-064 §Decision describes it as enforcing
DR-014's boundary "finally … not merely documented".

That ordering is worth noticing: **an accepted DR (064) enforces a clause of a DR that was
never ratified.** Same missing coupling recorded in DR-064 and DR-069 §Implementation, one
level up — nothing links "a DR's rule is now enforced in CI" back to "ratify that DR". Tracked
at [#1081](https://github.com/AIClarityAU/minspec/issues/1081).

**Ratification note.** The former body `## Status` section (which read "Proposed.") is removed
deliberately rather than updated. It duplicated the frontmatter `status:` field, and the two
are gated against each other by Rule-11 status parity (#626) at **error** severity
(`scripts/validate-frontmatter.ts:363` calls `fail`). Because *MinSpec: Accept ADR* writes the
frontmatter and INDEX row but **not** the body section ([#943](https://github.com/AIClarityAU/minspec/issues/943)),
accepting this DR with that section present would have produced `status: accepted` against a
body reading `Proposed` — a FATAL parity error blocking every commit repo-wide (the #680
class). DR-064 and DR-069 carry no body `## Status` section, which is why their accepts were
clean two-line changes.
