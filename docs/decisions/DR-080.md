# DR-080: Who owns recovery from a refused approval commit

> **Born `proposed` per DR-029** — acceptance is a separate human act
> (*MinSpec: Accept ADR*). This record's live status is its frontmatter `status:`
> field, not this note.

## In plain terms — what this changes for you

When you approve something while sitting on `main`, MinSpec now saves it on a
branch and pushes it for you, instead of leaving it in your working tree with a
warning. Nothing about *where you are standing* changes — your checkout is not
switched, moved, or rebased.

## Context

`commitApproval` refuses to commit an approval when HEAD is the push-protected
default branch ([#1064](https://github.com/AIClarityAU/minspec/issues/1064)); such
a commit could never be pushed, and the #1041 pre-commit hook rejects it. **That
refusal is correct and stays.** What was missing is what happens next.

The code recorded a deliberate decision to defer that "next" to SPEC-050:

> *"Deliberately NO auto-recovery here … Routing an approval to a docs-lane PR is
> precisely SPEC-050's scope … so the one-click recovery lands there, built once,
> rather than as a second half-correct copy here."*

**That deferral could not work, for a reason nobody had traced.** SPEC-050's FR-2
fires on `outcome: 'pushed-branch'`, which `pushApproval` produces — and
`pushApprovalIfEnabled` is called from exactly one place: the `committed` arm of
`commitApprovalIfEnabled`. When the destination guard refuses, the function
returns from the `protected-branch` arm *before* that. So on any repo whose
default branch is also its protected branch — the normal case, and every repo
MinSpec is installed in — **SPEC-050's payload was unreachable for precisely the
case it was designated to own.**

The cost was measured, not theorised. On 2026-08-05 six ratifications stranded in
one sitting (SPEC-045, SPEC-050, DR-061, DR-072, DR-078, and DR-078's own
acceptance), each recovered by a hand-driven branch, commit, push and PR, while
SPEC-050 was nominally "the fix". Goal **G-8 (git transparency)** says a
non-git-literate developer should never have to do that — and worse, they never
look at `git status`, so the stranding is invisible to exactly the audience the
guard is protecting.

## Decision

**1. Recovery is owned by the arm that triggers it.** The `protected-branch`
outcome is handled where it occurs, in `lib/approval-recover.ts` called from
`commit-on-approve.ts`. The prior comment's deferral is **superseded**.

**2. SPEC-050's scope is not overlapped — the two axes are complementary.** They
key on different outcomes and answer different questions:

| | trigger | question |
|---|---|---|
| **SPEC-050** | `pushed-branch` | the commit succeeded and was pushed to a side branch — *should a PR be opened?* |
| **DR-080** (this) | `protected-branch` | the commit was refused — *how does the approval reach a branch at all?* |

Nothing in SPEC-050's approved text covers the refusal case; its own Context is
explicit that FR-1..FR-7 concern only the *what-to-do-once-pushed* axis. So this
is not a re-scoping of SPEC-050 and needs no amendment to it — which matters,
because SPEC-050 is hash-locked and amending it costs a re-approval
([#1179](https://github.com/AIClarityAU/minspec/issues/1179)).

**3. Rule #8 / DR-051 §4a / DR-065 are honoured, not routed around.** The
deferral cited them for a real reason: committing onto a side branch must not move
the shared checkout's HEAD. Recovery satisfies that by construction — it commits in
a **throwaway worktree** off `origin/<default>` (a separate worktree with a
separate index), the `push-docs-lane` pattern. No `checkout`, `switch`, `merge`,
`rebase` or `reset` runs anywhere, and the primary's index is never staged into.
This is asserted against the **recorded runner argv**, so a future edit that adds
one fails a test rather than a user. DR-065's presence-gated fast-forward is not
invoked and not needed: nothing here moves an existing HEAD.

**4. Consent reuses `minspec.pushOnApprove`.** Recovery pushes, so it is gated on
the setting that already governs approval pushes — `never` reaches the module zero
times, `prompt` is one informed click naming the destination, `always` is the
consent. A second consent surface for one network act is how a user comes to
believe they have opted out when they have not (the same reasoning as
[DR-078](DR-078.md)).

**5. The duplicated push logic is a DATED LOAN, and this is the note.** The
architect's objection is correct on its face: `approval-recover.ts` carries a
third copy of the git-runner/error-classification/worktree-transport pattern
(`approve-push.ts`, `push-docs-lane.ts`). It is accepted **temporarily and
explicitly**, on these terms:

- SPEC-050's `approval-pr.ts` (#1224) is the designated seam and is an unmerged
  draft with known defects. Consolidating now means writing a fourth arrangement
  that #1224 then rewrites.
- The loan is repaid at a named event: when #1224 lands, `approval-recover.ts`
  moves onto that seam, and the `recovered` outcome becomes its PR-opening call
  site (#1115 requirement 2, still unbuilt and still owed).
- Until then the duplication is **bounded** — the copies are behaviourally
  independent and separately tested, so drift is visible as a test failure rather
  than a silent divergence.

Recording the debt is the point. An undocumented third copy is how "a second
half-correct copy" happens; a dated loan with a named repayment event is not the
same thing, and the difference is exactly this record.

## Consequences

- The stranding class this closes was the single most frequent manual chore in the
  corpus on 2026-08-05. It should go to zero for the `prompt`/`always` modes.
- `never` users keep today's behaviour exactly, including the honest warning.
- Three copies of push logic now exist. That is worse than two, and is only
  acceptable because §5's repayment event is named and tracked (#1224 / #1115).
- SPEC-050's in-code comment claiming ownership of recovery is now false; it is
  replaced by a pointer to this DR.

## Alternatives considered

- **Wait for #1224, then build recovery on its seam — rejected.** It is the
  tidiest end state and would have left the stranding in place for an unbounded
  period; #1224 is a draft with seven known defects and a governance dependency of
  its own. Six stranded ratifications in one day is too high a price for avoiding
  one temporary duplication.
- **Amend SPEC-050 to cover the refusal case — rejected.** SPEC-050 is hash-locked;
  amending it voids the founder's sign-off (#1179), and the two axes are genuinely
  different questions rather than one spec artificially split.
- **`git branch <new> HEAD` + index plumbing instead of a worktree — rejected.**
  It avoids the temp directory but requires writing a tree and commit by hand
  against the shared index, which is exactly the class of operation rule #8 exists
  to keep out of a shared checkout. The worktree cannot touch it by construction.
- **Give recovery its own consent setting — rejected.** See §4 and DR-078.

## Costly to Refactor

Cheap to reverse: one module and one arm, no schema, no stored state, no migration.
Recorded because it **supersedes a documented deferral that cited three DRs**, and
because §5 takes on a duplication debt that a future reader must be able to find
the terms of.
