# The ai-review check-run has a guard-free second producer and a guard-export preflight

> **Born `proposed` per DR-029.** Acceptance is a separate human act (*MinSpec: Accept
> ADR*). Nothing in this record takes effect before it is accepted, and nothing is built
> from SPEC-182 until that spec is approved.

> **Source.** Every requirement below is copied from SPEC-182
> (`specs/minspec/SPEC-182-ai-review-witness-never-absent/requirements.md`, FR-2, FR-5,
> FR-6 and its invariants section). This record adds no behaviour the spec does not
> describe; it fixes the two design choices so they outlive the spec.

## In plain terms - what this changes for you

The `ai-review` workflow ends by posting the `ai-review` check-run that branch protection
requires. Today, if the code that builds that check-run throws, the step warns and exits 0:
the job is green and the required check-run is simply missing. This record fixes two
choices. First, a second, simpler producer posts a red `ai-review` check-run whenever the
normal one cannot be built, using no guard code, so one fault in the guard cannot make the
witness disappear. Second, a preflight checks, before the review depends on it, that every
guard function the head workflow calls actually exists in the trusted base guard, so the
most likely cause of that fault is caught up front and named.

## Context

The step "Post honest `ai-review` verdict check-run" (`.github/workflows/ai-review.yml`)
treats the check-run as best-effort, yet the check-run is the required, server-attested
witness (#397). A required witness whose producer can disappear while the producer shows
green is a silent gate (constitution invariant 2, DR-066).

The failure is reachable because the guard (`.github/scripts/ai-review-guard.js`) is loaded
from the trusted base checkout while the step runs from the head, with no version handshake
(#1834). The live instance was #1839: the head workflow called `g.patchFingerprint` and
`g.renderPatchFingerprint`, the base guard exported neither, and run 34551496854 concluded
`success` with `TypeError: g.patchFingerprint is not a function`. The panel had passed 4/4;
the check-run was absent.

Main already feature-detects the three optional helpers that caused #1839. It does not
touch the path that swallows the fault: any other throw (`decideReviewCheck` missing or
throwing, the guard `require` failing, a `writeFileSync` error), and a failed
`gh api ... check-runs` POST, still become a green step with no check-run.

## Decision

### 1. A guard-free second witness (SPEC-182 FR-2)

If the body cannot be computed by the guard-based script, the step posts a minimal
check-run with `name: ai-review`, `conclusion: failure`, the head SHA, and a summary naming
the failure, built with **no `require` of the guard** (plain shell and `gh`, or a node
script that only uses core modules). It then exits non-zero.

- It is reachable **only** on failure to compute. When the body is computed, the conclusion
  is exactly what `decideReviewCheck` returns today (machinery to neutral, pass to success,
  changes to failure); no verdict logic changes (FR-3).
- On a machinery PR a compute failure yields `failure`, never `neutral`, so a broken witness
  cannot read as the normal machinery resting state (AC-6).
- Only trusted inputs reach the shell: the App token, the repo slug, GitHub-assigned SHAs
  and the gate's own outputs. No PR-controlled text goes into the fallback summary.

This is the "independent second witness" constitution invariant 2 asks for: the guard is
the single producer whose one fault could otherwise disable the required check, and the
fallback shares none of its code.

### 2. The preflight contract (SPEC-182 FR-5 and FR-6)

- **Export-compatibility preflight.** Before the verdict steps depend on the guard, a
  preflight enumerates the guard functions the head workflow calls and checks that each is
  exported by the base guard. A required function that is missing fails the job visibly
  with the function name. Optional, feature-detected helpers are listed separately and
  produce a notice, not a failure.
- **One source of truth for optional versus required.** The set of required and optional
  guard exports lives in one place that both the preflight and the step read, so the two
  cannot drift.

## Rejected alternatives (DR-086 §4)

- **Keep both choices spec-only (no record).** Rejected: the guard-free witness is the
  repo's answer to invariant 2's "independent second witness" for its most important
  required check, and the preflight contract is the first handshake on the head/base skew
  (#1834). Both outlive the spec that builds them, and a later change to the step needs to
  find why the second producer must stay guard-free.
- **Fold the preflight into the verdict step** (SPEC-182 Clarify D1, option b). Rejected in
  the spec's recommendation: no new step, but the failure arrives after the review spend.
- **Run the head guard instead of the base guard.** Out of scope: it is a trust-boundary
  change (#1834). This record only makes the skew loud and checkable.
- **Keep warn and exit 0** for the no-token case (SPEC-182 Clarify D2, option b). Rejected:
  it leaves the witness silently absent.

## Consequences

- A guard fault now turns the run red with a named cause instead of green with a missing
  check. The cost is a red run where today there is a green one, which is the point.
- The preflight adds one CI step and can fail a job that would otherwise have reviewed.
  If the optional/required split is mis-classified, an optional-only skew blocks the review;
  the single list in FR-6 is where that is corrected.
- Both `ai-review.yml` and `ai-review-guard.js` are managed templates
  (`scripts/gen-ci-templates.mjs` `SOURCES`, regenerated into
  `packages/minspec/src/lib/hook-templates.ts`), so the change reaches adopters on Refresh
  Harness Files. It stays inside the blast radius (constitution invariant 3) because
  adopters opt in via `.minspec/`.

## Rollback

Revert the workflow, guard and template change that implements SPEC-182. The record then
reads as a decision not yet built; nothing else depends on it.
