## In plain terms - what this changes for you

Your approval keystrokes stop being required where you were not actually reading.
The checks that catch a corner-cutting model - hashes, validators, tests, the
independent AI review, the root-cause gate - all stay and keep running without
you. Your attention gets reserved for the few moments it genuinely changes the
outcome: reading a T3/T4 spec before anything is built from it, and any
irreversible act.

## Context

This repo's governance was sized for a team: protected main, human-approved PRs,
bot-attributed writes, presence coordination, docs-lane, --admin ceremonies. The
founder built it for one stated purpose - "make sure the model didn't cut any
corners and thought through its work properly" - but the human half has degraded
to rubber-stamping: approvals granted without reading. A dead HITL layer is pure
tax: it costs a keystroke and an interruption, catches nothing, and (worse, per
the never-wrong invariant) records a human judgment that never happened. The tax
is concrete: landing a one-line .gitignore edit on this repo currently requires a
branch and a PR.

The sorting principle: every gate defends against someone. Classify each by WHO.

- **Model-defending gates** exist because the model cuts corners. They are
  deterministic or independently adversarial, and they work with zero human
  attention. These stay.
- **Human-coordination gates** exist because multiple humans (or one human's
  multiple concurrent sessions acting as strangers) must not trample or
  misattribute each other's work. With one human and a parked team mode
  (DR-075), most lose their subject.

## Decision

### Keep - model-defending (runs without human attention)

| Gate | Why it stays |
|---|---|
| Hash-locked approvals + staleness invalidation (DR-062 graph-aware) | The core mechanism; catches silent drift after a real approval |
| Deterministic tier classifier as upward-only floor | Stops the model under-ceremonying its own work |
| Validators, frontmatter gates, `npm run facts` | Deterministic; the enforce-don't-trust backbone |
| RCDD `Root cause:` commit-msg hook | Zero-cost thinking-forcing function; exactly the stated purpose |
| T0-first invariant tests, full suite in CI | Corner-cutting shows up as red |
| Independent AI review on PRs and approvables (DR-033/DR-047) | The anti-corner-cutting instrument that works while the human does not read; its verdict now gates MERGE, not a human keystroke |
| Secret/PII pre-commit hooks | Defends against everyone, costs nothing |

### Keep - genuinely human moments (the only HITL left)

- **T3/T4 spec approval.** Reading a spec before building from it is where one
  human-hour has the highest leverage. This one is real reading, or the tier is
  wrong.
- **Irreversible or outward-facing acts.** Marketplace publish, repo
  visibility flips, deletes, anything leaving the machine.

### Cut or park - human-coordination (subject has left)

| Gate | Disposition |
|---|---|
| Human PR approval on green+AI-passed PRs | CUT - auto-merge on green + ai-review pass becomes the default path (mechanism already exists; scope widens) |
| Branch-protection human-review requirement, --admin ceremonies | CUT - required checks stay, human-review requirement goes |
| Bot-attribution App-token path for routine writes | ~~PARK behind team profile~~ → **KEPT ACTIVE under `solo`** (amended 2026-08-21, see note below) |
| Docs-lane / presence-gated ff / session mailbox (DR-051/DR-065) | PARK behind team profile - worktree-per-concurrent-agent discipline stays (that one defends against agents, not humans) |
| awaiting-approval labels, drain-inbox HITL escalations sized for team throughput | SIMPLIFY to solo scale |

Parked means retained in source behind the future `mode: solo | team` profile
(DR-075 §4), not deleted - reviving team mode must not require archaeology.

### Amendment 2026-08-21 - bot attribution is NOT parked

The row above originally read *"misattribution is a team audit problem; solo commits
already carry Co-Authored-By"*. That premise is wrong for this repo, and the row is
amended (founder-confirmed 2026-08-21, via SPEC-065's Clarify pass, DQ-3):

- The repo is **public**. The audit trail is read by people who cannot know it is
  solo-operated, so "it is only me" is not visible to the reader it would need to be
  visible to.
- `Co-Authored-By` does not substitute. It records a co-author on a **commit**; it says
  nothing about who authored an **issue comment, label, or PR** - which is where the
  agent does most of its writing.
- DR-056's verdict-record provenance binds **content**, not authorship, so it is not a
  second source for identity either.
- The concrete harm: GitHub permanently subscribes the **author** of a thread. An agent
  write made as the human subscribes them to it forever, and the history then records a
  person as having done what an agent did - a false signpost in the product whose whole
  claim is that its signposts do not lie.

The general form: `solo` describes who must **consent**, not who **reads the record
later**. Gates cut by DR-076 are those whose subject has left; the reader of a public
history has not left. Parking this one saved nothing at solo scale (the token mint is
automated and free) while giving up a property that matters precisely because the repo
is public.

## Consequences

- The rubber-stamp keystroke disappears; the audit trail stops recording
  approvals that were not judgments (never-wrong upheld, not weakened).
- ai-review becomes more load-bearing (it is the only reader on most changes).
  Its no-silent-gate properties (constitution invariant 2) matter more, not less.
- Risk accepted: with no human reading routine PRs, a wrong-but-plausible change
  that passes tests + AI review lands. Mitigation is the layered deterministic
  gates plus the T3/T4 read - the same bet the whole product makes.
