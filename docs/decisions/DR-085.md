# DR-085: The human signpost carries only human-dischargeable acts

## Context

[DR-019](DR-019.md) established that next-task priority is a deterministic DAG, never
an LLM judgement, and [SPEC-012](../../specs/minspec/SPEC-012-next-task-resolver/requirements.md)
built it. That spec draws from five node kinds, and defines the set by *exclusion* of
the agent queue (FR-8, `INV - Two Queues`):

| Kind | SPEC-012's stated meaning |
|---|---|
| `spec-approve` | approve before implement (DR-012 gate) |
| `adr-accept` | proposed to accepted |
| `epic-promote` | proposed to active |
| `answer-OQ` | resolve an open question |
| `phase-action` | *"author the phase"* |

The premise defending `phase-action`'s place on that list is stated verbatim at
`packages/shared/src/next-task.ts:824`:

> *"The Two-Queues invariant holds: 'author the phase' is the human's own work, not the
> agent/dispatch queue."*

**That premise is false in this project, and has been for months.** Authoring is done by
an agent. `scripts/drain-inbox.sh` runs continuously off GitHub issue labels
(`agent-ready` / `agent-ready-specify`), dispatches through `scripts/dispatch-issue.sh`,
opens PRs and auto-merges them. [DR-057](DR-057.md) extends the same drain to generating
next-phase derivatives. The founder's own framing, which triggered this DR:

> *"isn't my job just to approve specs, and claude's job is to write then later implement them?"*

Three consequences followed from the mismatch, all observed rather than predicted.

**1. The top signpost item is not actionable.** Alt+N (`minspec.nextTask`) reveals the
target file and shows the imperative as a toast. For an approval that is enough - Alt+A
discharges it. For *"Implement SPEC-038"* there is no act at all, and deliberately so:
[DR-004](DR-004.md) and [DR-015](DR-015.md) keep dispatch out of the Tier-0 air-gapped
extension. So the signpost's highest-priority item was, structurally, a dead end.

**2. Authoring outranks approvals.** A `phase-action` under an active epic is classed
`blocked-ready`, the same class DR-019 gives an approval, so it wins on artifact-id
tie-break. Measured on the live corpus this session, six spec approvals and one DR sat
behind authoring nodes the human could not act on.

**3. A stale authoring node is invisible, and it poisons the whole surface.** Nothing
writes back to a spec's `tasks.md` when its code lands, so SPEC-038 - fully implemented
and merged on 2026-07-17 - kept an 11-of-11-open implement hole and held the top of the
signpost for **33 days** (#1595, data corrected in #1594). An approval node cannot go
stale that way: its input is the approval sidecar, which the approve command writes. The
node kind that broke the *never-wrong* promise is precisely the one whose completion
signal no code produces.

The failure is not that the ranking is wrong. It is that a queue mixing "acts you can
discharge" with "acts someone else performs" has no correct ordering - the two are not
comparable, and the human reading the bar cannot tell which kind they are looking at.

## Decision

**The next-task signpost carries only acts the human can discharge. Authoring work moves
to a separate surface.**

### 1. Membership test: dischargeable, not merely human-owned

A node belongs on the signpost if and only if the human can complete it **from the
editor, without delegating**. Concretely: `spec-approve`, `adr-accept`, `epic-promote`
and `answer-OQ` stay. `phase-action` leaves.

This *replaces* SPEC-012 FR-8's boundary. The old test was "not drawn from the agent
queue", which admitted `phase-action` on the (false) premise that authoring is human
work. The new test is a property of the node, not of its provenance, so it cannot drift
when who-does-the-work changes again.

### 2. `INV - Two Queues` is reaffirmed, and its boundary moves

The invariant survives; its line moves. The human queue is now defined *positively* -
dischargeable acts - rather than by excluding a dispatch source. SPEC-012's FR-8 test
("a fixture seeded with a dispatch item proves exclusion") is necessary but no longer
sufficient, and gains a second direction: **no node the human cannot discharge is
emitted**.

### 3. DR-019 is untouched

Severity classes, the deterministic DAG, and the DR-039 within-class dials all stand
unchanged. This decision changes *which nodes enter* the ranking, never how ranked nodes
are ordered.

### 4. The "clear" state must not lie, so the agent queue ships first

`$(check) MinSpec: clear` currently means "nothing pending". After this change it would
mean "nothing pending *for you*" while authoring work sits untouched - and a stalled spec
that no agent picked up would be invisible on the one surface the founder watches. That
is a worse failure than the one being fixed: a wrong signpost is at least noticed.

Therefore **the agent-queue surface is a precondition, not a follow-up.** The signpost
must be able to render, alongside the human item or the clear tick, a count of what is
queued elsewhere - *"clear · 4 with the agent"*. Removing `phase-action` before that
exists is not sanctioned by this DR.

### 5. A blocked approval stays on the human queue

An approval the gate would refuse (#1603 - a spec with no `implements:` declaration)
decomposes into authoring work plus an approval. The authoring half moves to the agent
surface under §1, but the **approval must remain visible as blocked**, with its blocker
named. It must not silently vanish from the human queue merely because its blocker is
someone else's job. This is the one place the two surfaces must cross-reference.

## Consequences

- The signpost stops advertising acts the human cannot perform. Its imperative becomes
  uniformly true: everything on it is dischargeable with a keystroke.
- Approvals stop queuing behind authoring. On today's corpus that promotes six specs and
  one DR to the head of the queue immediately.
- The `phase-action` node kind is not deleted - it moves. `resolvePipeline` keeps
  emitting it; the *status bar* stops consuming it, and the agent-queue surface starts.
  Consumers that want the whole picture (the planned DAG-viz) still get it.
- SPEC-012 needs amending, not superseding: FR-8, `INV - Two Queues`, the node-kind table
  at line 65, and the acceptance test at line 284. **DR amendments do not self-apply** -
  the amendment is tracked below and is not done because this DR says so.
- The phantom-hole class (#1595) becomes lower-severity but does **not** go away: a stale
  implement hole would still mis-render the agent queue. It stops being able to break the
  human signpost, which is the part that had to stop.

## Alternatives considered

**Rank every approval above every `phase-action`.** One comparator change, near-zero
risk. Rejected: it defers rather than answers. An implement item still has no action; it
simply waits until the approvals clear and then blocks the signpost again. It also leaves
the surface semantically mixed, so the reader still cannot tell from the bar whether the
item is theirs.

**Make Alt+N dispatch the authoring node.** The most complete answer - the human presses
one key and the work starts. Rejected *for now*, on tier grounds only: it makes the
Tier-0 air-gapped extension a dispatcher, which DR-004 and DR-015 forbid. It becomes
available once `aiclarity.agent-execute` owns the dispatch keystroke, at which point this
DR should be revisited rather than reversed - authoring would then be dischargeable by
the human, and §1's membership test would readmit it *by its own terms*. That is the test
working, not a loophole.

**Leave it and fix only the staleness.** Rejected: #1594 fixed exactly that for SPEC-038
and the head of the signpost immediately became another authoring node the human cannot
act on (SPEC-042). The staleness was the trigger, not the cause.

## Risks & Mitigations

| Risk | Likelihood · Impact | Mitigation |
|---|---|---|
| The clear tick becomes a lie - authoring work stalls invisibly | Med · **High** | §4 makes the agent-queue surface a precondition. Ship the count first, remove `phase-action` second. |
| A blocked approval disappears from both surfaces | Med · High | §5 - the approval stays on the human queue with its blocker named (#1603). |
| SPEC-012's amendment is recorded and never applied | **Med** · Med | Tracked below as an explicit issue, not as prose. This is the DR-amendment-gap class - three accepted DRs have already carried unapplied amendments. |
| The membership test is re-read as "human-owned" and `phase-action` creeps back | Low · Med | The test is written as a property (dischargeable from the editor) with a T0 test in both directions, not as a node-kind allowlist. |

## Costly to Refactor

Yes - this is why it is a DR rather than a patch. It changes what the product's central
never-wrong surface *is for*, and that meaning is quoted in SPEC-012, SPEC-010, DR-019's
framing, and the extension's user-facing copy. Reversing it later means re-teaching the
surface's meaning to every consumer, not flipping a boolean.

**Accepted** (2026-08-19, #1612). The *decision* was made by the founder on 2026-08-19 -

**MinSpec: Accept ADR**.

Fittingly, that act was exactly the kind this DR rules belongs on the signpost: it
surfaced as `Accept DR-085`, dischargeable with one keystroke.
