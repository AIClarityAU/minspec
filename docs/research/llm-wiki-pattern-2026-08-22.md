---

**Conclusion up front.** MinSpec is already a stricter instance of this pattern than five of the seven repos examined, and a different shape of it than the other two. atomicstrata and sdyckjq both ship blocking gates: `llmwiki lint` exits 1 on any error (`src/commands/lint.ts:64-66`), `llmwiki eval` exits 1 on a threshold violation (`src/commands/eval.ts:72`), husky pre-commit runs `fallow` plus `tsc --noEmit` and pre-push runs build plus test, CI runs on Node 24 with `fail-on-issues: true`, and the review config *throws* rather than silently disabling (`src/review/config.ts:56-64`); sdyckjq's `lint-runner.sh --strict` and `wiki-link-cli.js` both exit 2 on error severity under three real CI workflows. What MinSpec adds is a deny that fires **before** the edit (`spec-gate.py` as a PreToolUse hook) rather than after the write, on top of `scripts/validate-frontmatter.ts` (13 FATAL of 18 rules, unconditional in CI and at pre-commit as a baseline diff that blocks only newly introduced failures, `.githooks/pre-commit:219-296`), `spec-validator.ts` at approve time, and ai-review gating merge. Five of the seven ship no test gate on a pull request at all.

So the value here is not "adopt the pattern". It is a set of specific mechanisms these repos built that MinSpec has not, most of which target the gap between *an artifact was approved* and *the artifact is still true*: computed spec-to-code drift, bounded-patch editing of approved artifacts, lint-as-migration for schema change, citation fidelity (not just citation existence), a generated-with-preserved-curation index applied to the memory store, typed provenance on inferred edges, and authorship binding. Most of the rest is weaker than what MinSpec runs or is prose the repo's own code contradicts, with one exception worth naming here rather than burying it in a lesson: atomicstrata's authority and integrity layer (capability lattice, HMAC-signed run records, hash-chained event log, deny-versus-park) is genuinely ahead of MinSpec on the authorship-binding problem its own approval sidecars do not solve.

## What MinSpec has that none of them do

Worth enumerating before the deltas, because it sets which lessons are worth the ceremony. Across all seven repos (asserted from the seven line-by-line reads, not from an exhaustive search of every file in each):

- **Zero have any concept of an approvable** - an artifact a human signs off on, with the signature bound to a content hash. Provenance in the cohort answers "where did this text come from", never "who committed to it".
- **Zero prevent a write.** Every gate in the cohort is post-hoc: it reads what was written and reports or exits non-zero. `spec-gate.py`'s PreToolUse deny has no cohort analogue.
- **Zero have a rule that announces its own inertness.** MinSpec's Rules 16, 17 and 18 each wrap in try/catch and print that the rule "validated NOTHING this run; do not read the green as a clean register" (`validate-frontmatter.ts:311,349,395`). The cohort's signature failure is the exact inverse: SamurAI's `--validate-only` prints every broken link then unconditionally `sys.exit(0)` (`ingest.py:348`).
- **Zero gate a merge on an independent reviewer.**

The frame that makes this land: the whole cohort optimises **ingestion** (how does knowledge get in), while MinSpec optimises **commitment** (what does it mean for an artifact to be signed off and still true). That is why their hardest problem, merging a new source into an existing page without clobbering it, is one MinSpec does not have, and MinSpec's hardest problem, a signature that stays honest as the world moves, is one they have never posed.

## 1. What the pattern actually is

Karpathy published an idea file (gist `llm-wiki.md`) plus a short public note. It prescribes exactly five things: three layers (immutable `raw/`, LLM-owned `wiki/` markdown, a schema doc such as CLAUDE.md), three operations (ingest, query, lint), two special files (`index.md` read first, `log.md` append-only with a fixed prefix so `grep "^## \[" log.md` works), and a division of labour where the human curates sources and asks questions while the LLM does all bookkeeping. It is scale-bounded on purpose ("works surprisingly well at moderate scale (~100 sources, ~hundreds of pages)"), and it closes by saying it is "intentionally abstract. It describes the idea, not a specific implementation." The only copy of the gist inside the material read here is the one nashsu vendors verbatim at its repo root (`r0/llm-wiki.md:1-75`).

*Asserted, not verified in this pass* (these figures come from the primary sources, which were not re-measured here): the gist is ~1,928 words at one revision dated 2026-04-04, there are two accompanying tweets, four checks for a canonical Karpathy implementation repo came back negative, the phrase "knowledge compiler" appears zero times in either primary source, and the community has produced roughly fifteen instantiations. What *is* verifiable from the seven reads: those instantiations add MCP servers, vector search, daemons, eval harnesses and fixed directory schemas that the gist explicitly declines to specify, and they are being recirculated as if they were the specification. "Karpathy killed RAG" is a misread of a scale-bounded claim.

## 3. Transferable lessons, ranked by value to MinSpec

### L1. Spec-to-code drift as a computed signal, not a stored status

**Technique.** Two halves. (a) Ownership reverse index: atomicstrata builds concept-to-sources (`deps.ts:32-49`) so that editing source A pulls unchanged source B back into the batch when they share a page, with the reason written into the header: without it, "concept X would be regenerated using only source A's content, losing source B's contribution entirely" (`deps.ts:102-120`). Deleting a source *freezes* shared pages rather than regenerating from fewer contributors (`deps.ts:132-159`), unfrozen only when every current owner recompiles (`:196-204`). (b) Freshness computed, never persisted: `src/freshness/index.ts:1-7,38-53` derives fresh/stale/orphaned/unverified at read time from recorded hashes versus current file hashes, so no on-disk status field can lie.

Inkeep *describes* the incremental version with a git anchor but ships it as a skill procedure rather than code: `OVERVIEW.md` carries `source_commit` and the agent is instructed to run `git diff --stat <source_commit>..HEAD`, map changed paths to affected pages, update only those and re-stamp, with a full-regen fallback (`generate-and-refresh.md:114-124`, under `packages/server/assets/skills/`). No code runs that diff and nothing verifies the mapping happened; the adjacent freshness fields `supersedes:` and `stale_after` have zero enforcement anywhere in `packages/*/src`. The freshness anchor is the transferable idea; the execution is model-trusted, which is exactly the half MinSpec should not copy.

**MinSpec today.** The ownership map exists and is engaged: 29 requirements files declare `implements:` with real paths, 14 declare `affects:`, 11 use the `implements: none` escape, and `.minspec/config.json` sets `ownershipDeclaration: "error"` (Input B §5). Status is already derived, not trusted: `deriveStatus` (`lifecycle.ts:133`) with the literal `status:` line as a mirror and `status.mirror-drift` as a warning (`spec-validator.ts:979`). Approvals record `specHash`, `approvedAt`, and a `baselineBlob` of the spec **body** (`approval.ts:60-70`). `.minspec/traceability.json` is absent; the feature exists in code (`traceability.ts:1-18`) and is unused in this repo (Input B §4).

**The delta.** MinSpec computes spec-content staleness: any byte change that survives canonicalization stales the approval (`approval.ts:483`), where `canonicalizeSpec` (`canonical.ts:89`) is seven steps, stripping `status:`/`phases:`, normalising EOL, collapsing relative link URLs to `](RELLINK)` (`:115`), stripping per-line trailing whitespace and collapsing trailing newlines, so a directory renumbering that rewrites relative links, a CRLF conversion, or whitespace churn is deliberately invisible to it. But nothing computes the *other* direction: an approved spec whose owned code has moved underneath it stays `approved` forever. The ownership map is already a spec-to-file edge set; invert it and record the owned files' git blob shas at approve time alongside `baselineBlob`, then derive "spec is behind its code" at read time exactly as `freshness/index.ts:38-53` does. `scripts/facts.ts` is the natural surface (it already prints stored vs computed for `hash`).

**Cost and risk.** Recommended, and the primary downside is noise: `affects:` paths are broad, so a formatting-only commit to an affected file will mark specs drifted and train people to ignore the signal, which is exactly how nvk's linter degraded (its `run_lint` returns 1 on any *suggestion*, `llm-wiki:1651-1689`, and "raw source not referenced" is a suggestion at `:1312`, so a live wiki always exits non-zero). Mitigation: ship it read-only in `facts.ts` first and measure the false-positive rate over a week before it becomes a warning, and never a merge gate on the first cut.

### L2. Bounded-patch editing of approved artifacts

**Technique.** Three layers from nashsu, all reactions to measured failures. (a) Constrained edit: `enrich-wikilinks.ts:8-25` records that asking the model to return the complete page with links inserted made mid-size models rewrite and expand the page, destroying user content, and that "no prompt-level instruction reliably prevents this". The fix is a typed patch list (`{term, target}` JSON) applied in code, so "content is byte-identical outside the inserted brackets" and length grows by exactly 4 times the link count. (b) Locked fields: after an LLM merge, `type`, `title`, `created` are forced back from the on-disk version and array fields re-unioned against both sides (`page-merge.ts:29-53,94-201`). (c) Sanity rejection: unparseable frontmatter, or a merged body under 70% of the longer input, falls back to a non-LLM merge and snapshots the old file (`page-merge.ts:53,168-178`). Plus the inversion worth stealing: if a page's `sources` contains *only* the source being re-ingested, replace rather than merge, because merging "kept retracted wording alive indefinitely" (`ingest.ts:2030-2031,2073-2080`).

**The adjacent atomicity technique**, from sdyckjq: `create-source-page.sh:78-98` writes the page via tmpfile-plus-rename, then updates the cache ledger, and *deletes the just-written page* if the ledger update fails, so the state "artifact exists but is not registered" is unreachable. The same repo supplies the read-only proof technique: `tests/graph-warning-exit-codes.regression-1.sh:15-33` sha256s every markdown file before and after every check invocation and fails if any changed, so a reporting tool proves it is a reporting tool.

**MinSpec today.** Two states only, and the gate runs the opposite way round from how it is usually described. While a T3/T4 spec is **unapproved or stale**, `spec-gate.py` denies `Edit`/`Write`/`MultiEdit` to its owned file set (structured `implements:`/`affects:` paths, matched without an existence filter so creation is blocked too) before the permission system runs; a spec's own docs stay editable or approval would deadlock. Once approved, the owned code is editable and the only remaining coupling is that a spec edit re-stales the sign-off (`approval.ts:483`). There is nothing in between: no mechanism that lets an agent make a *bounded* edit to an approved artifact and prove the edit was bounded.

**The delta.** For agent edits to specs and DRs, assert post-conditions in code rather than trusting the diff: re-assert `id`, `epic`, `created`, `implements` from the prior version, and reject an edit that shrinks the Acceptance Criteria or Functional Requirements sections below a threshold. This is the machine version of the memory `f-revi-own-diff` finding (a review panel passed two defects the author introduced). Separately, bind the spec write and its approval sidecar into one operation with rollback, following `create-source-page.sh:78-98`: MinSpec writes them as separate operations today, and the memory store already records two failures in that family (a pathspec commit undoing a staged `git rm --cached`, and an approval judged against a stale worktree). And add the sha-before/sha-after assertion to `facts.ts`'s test suite so its "strictly read-only" docstring (`facts.ts:28-32`) is proved rather than asserted.

**Cost and risk.** Recommended for the autonomous drain path specifically, and the downside is that a legitimate scope reduction (deleting an FR on purpose) now needs an explicit override flag, which is one more thing that can be habitually passed. Keep the override loud and logged rather than silent.

### L3. Lint is the migration

**Technique.** nvk's rule (`references/linting.md:3-44`): never write migration code for a document corpus. Express every schema change as a new lint rule plus its auto-fix, so every existing corpus self-heals on the next `lint --fix`. "There is no `/wiki:migrate` command and there should never be one. Lint rules **are** the schema." Three sub-rules make it survivable: a renamed field appends to an alias table and old aliases are *never* removed; a changed enum adds a value alias and never removes one; a new required field ships with an inference rule (derive from body or filename) or a default, so existing documents never become retroactively invalid.

**MinSpec today.** 18 numbered corpus rules, a live `approved_by`/`approved-by` split, and `DR-011` carrying `status: active` outside the 82-accepted/3-superseded set (Input B §1, §7.5). That is precisely the situation this rule is designed for, and MinSpec currently has no migration story at all: schema changes land as ad-hoc data edits, which is the pattern `f-rcdd-mech-not` calls out as a tell for a missing gate.

**The delta.** Whenever a frontmatter field is renamed or an enum widens, the change ships as (a) a rule extension with an append-only alias table and (b) an autofix, never as a one-off script. Cost: the alias tables grow forever and are never pruned, which is the deliberate trade, and it means the rule set carries the corpus's whole schema history as dead weight. That is cheaper than a corpus that silently splits into two dialects, which is what the `approved_by`/`approved-by` pair already is.

### L4. Citation fidelity, not just citation existence

**Technique.** Astro-Han's `check_evidence.py` (431 lines) greps a deliberately closed candidate set back from each article into its declared raw files: quotes of 15+ characters, ISO dates, and "specific" numbers only (thousands-grouped, dotted, K/M/B/% suffixed, or 4+ digits, `keep_number()` :173-177), with boundary guards so `42K` does not pass on `142K` and `2026-03` does not pass on `2026-03-19` (`contains()` :270-279). Two design moves matter more than the regexes. First, the frozen contract: `:18-26` enumerates what is checkable and what is deliberately out of scope, with the rule "New prose forms extend this list in the docstring, not the regexes". Second, header scope is parsed, not grepped: metadata is only the contiguous blockquote after the first H1 outside a code fence (`:96-146`), so a template quoted inside the document is never validated as real metadata. atomicstrata does the complementary half: it shows the model right-aligned 1-indexed line numbers in the prompt (`prompt-budget.ts:82-91`) so its `^[file.md:42-58]` spans are mechanically checkable, then lints file existence and span-in-bounds against the real line count (`rules-citations.ts:100-135`), and repairs bare line markers deterministically, dropping them when multi-source makes them ambiguous (`citation-normalize.ts:81-109`).

**The general rule these are instances of**, which atomicstrata states outright: derive the metric from the artifact, never from the model's self-report. They deleted an LLM-supplied `inferredParagraphs` frontmatter field and replaced it with counting uncited prose paragraphs in the rendered body, because "that estimate was made before the page even existed and routinely disagreed with what the model actually produced. Counting uncited prose paragraphs in the rendered body matches what a reviewer would see and survives hand-edits" (`src/linter/rules.ts:306-315`). Its complement is nashsu's ground-truth post-filter (`lint.ts:73-80,330`): every model-generated `missing-page` finding is dropped if the page already exists, with the match exact-normalized rather than substring. Both are one-line policies for MinSpec's ai-review path, which currently accepts model findings unfiltered and has already produced at least one false block (#1029).

**MinSpec today.** `reference-checker.ts` extracts `SPEC|DR|EPIC-\d+` (`:65`), `path#Lnn` (`:87`) and `path:nn` (`:91`), and resolves each against a registry of real ids plus a `fileExists` probe (`:46-55`). It runs live in the editor (`diagnostics.ts:194`), in `npm run validate` (`validate-frontmatter.ts:423`), and at pre-commit (`.githooks/pre-commit:185-296`). Input B shows a file-existence probe; it does not show a line-range or content check, so **line-number rot is unverified as covered and should be treated as uncovered**. CLAUDE.md's Evidence Discipline section requires `file:line` citations for every mechanism claim, and the memory store records that codegraph line numbers rot between read and push (`f-code-summ-are.md`).

**The delta.** Extend `reference-checker.ts` with a fidelity tier: for a `path:NN` citation, assert the file has at least NN lines; where a backticked literal appears within plus or minus one line of the citation (the same proximity window `hasDanglingParkRef` already uses at `spec-validator.ts:648`), assert that literal appears in the cited file. Publish the frozen candidate set in the module docstring, Astro-Han style, so "the check passed" is a bounded claim.

**Cost and risk.** Highest leverage relative to MinSpec's never-wrong positioning, and the primary downside is false positives from renamed symbols and moved code, which in a 9,421-token reference corpus (Input B §2) could add hundreds of warnings on top of the existing 140. Ship it warning-tier and measure before promoting. Also inherit Astro-Han's blunt lesson: their checker skips Status blocks by design (`:225-233`), and the researcher's injected fabrications inside one returned zero findings. A checker that looks away from the region where corrections live is worse than no checker, so scope the exemptions deliberately and write them down.

### L5. Generated index with preserved curation, applied to the memory store

**Technique.** Machine-owned aggregates, plus a fixed point. nashsu forbids the model from writing `index.md` and rebuilds it from the frontmatter of pages actually written, into a bounded 200-entry section, with the reason stated in the prompt itself: so large wikis are never rewritten through model output (`ingest.ts:1514,1568-1600,2266`). Inkeep adds the guard that makes regeneration safe: `regenerate-index.ts:12-18` notes that "the returned `changed: false` is load-bearing, not an optimization", because writing the index triggers the same file-index and broadcast paths that trigger regeneration, and comparing bytes first turns that into a fixed point. nvk states the doctrine: "Indexes are a cache, not a source of truth" and are rebuilt on read when stale (`indexing.md:19`), which is also its answer to concurrency (see section 6).

**MinSpec today.** MinSpec already invented the strictly better version of this for `docs/decisions/INDEX.md`: a marker-fenced auto region (`adr-manager.ts:632`), per-entry fingerprints (`<!-- dr-summary:DR-001 auto=7711e5e752a3 -->`, `summaryFingerprint:739`), and re-derivation logic that keeps human-curated text and re-records the original fingerprint when the visible text no longer hashes to it (`renderDrEntry:794`, `:817-830`), so regeneration can never clobber curation with no second source of truth. A FATAL gate (Rule 8, `validateDrIndexStatus:1011`) asserts INDEX status equals frontmatter status in both directions.

**The memory store is the un-migrated case.** Measured (Input B §6): `MEMORY.md` is 15,321 chars and 142 lines, 61% of the 25,000-char cap and **71% of the 200-line cap** (lines are the binding constraint). 129 index entries against 183 topic pages, so 54 pages are on disk but not in the prompt. Truncation keeps the head and cuts the tail, with no error, and new entries append at the bottom. The `f-`/`p-`/`r-` convention holds cleanly (91 of 91 `f-` pages indexed, `p-`/`r-` selectively de-indexed), but three pages carry a prefix that disagrees with their `metadata.type` and nothing validates the pair. All 129 index links currently resolve, and no validator enforces that.

**The delta, three parts, all mechanical.** (a) Generate `MEMORY.md` from page frontmatter using the `adr-manager.ts` fingerprinted-region technique verbatim, so hand-tuned glosses survive regeneration and `f-` pages can never silently drop out of the index. (b) A budget check that fails at, say, 90% of either cap, printing char and line counts. This is constitution invariant 2 applied to the one gate that currently fails silently by design. (c) Assert prefix-to-`metadata.type` agreement, which closes the three known filing errors and prevents a passive-recall `f-` page from de-indexing without warning.

**Cost and risk.** Recommended, and the primary downside is a boundary one that must be respected: `~/.claude` is not a MinSpec-installed project, and MinSpec's constitution invariant 3 says nothing MinSpec ships may change behaviour in a repo that did not opt in. So this ships as a personal script under `~/.claude`, *reusing the technique*, not as an extension feature and not by pointing MinSpec's validator at the memory store. Note also that `~/.claude` auto-commits and pushes at session end with no review window (`r-glob-clau-md.md`), so a generator that rewrites `MEMORY.md` will push whatever it produced.

### L6. Prompt-corpus tests

**Technique.** Inkeep's `packages/server/src/skill-cross-refs.test.ts:7-24,60-129` walks the instruction corpus from disk and asserts every `/skill-name` reference resolves to a shipped skill, that the corpus has non-zero edges, and that a file linking a skill never also mentions it bare. The header names the failure that motivated it: before the suite, the whole corpus had zero edges because every sibling reference was authored bare, which is why a rename left prose pointing at names nothing answered to. sdyckjq does the cruder version that transfers even more directly: `tests/regression.sh:429-478` slices `SKILL.md` by workflow heading with `sed` and asserts the load-bearing instruction lines are still literally present, so a prompt edit that deletes a mandated step fails **when the script is run**, which nothing does: `tests/regression.sh` is wired into no workflow (`run-quality-and-tests.mjs:114-115` names only two regression scripts, and the three CI workflows call `npm run quality-and-tests` plus a fixed `node --test` list). Copy the technique and wire it, which is the step both repos skipped.

Two adjacent moves belong here. nvk's `validate_specialist_package` (`scripts/llm-wiki:2850-2924`) enforces required H1 sections **by name** (`Mandate`, `Non-claims`, `Use when`, `Do not use when`, `Output contract`, `Stop and escalation rules`, `Evaluation cases`, `Provenance and maintenance`), plus semver, an ISO reviewed-date, a risk tier, no symlinks, no executable bits, and a hard ban on `allowed-tools:` in frontmatter because "the llm-wiki orchestrator owns tool authority". From the same file, the fail-closed verification pattern: `retract --apply` re-scans after writing and reports `status: verified` only when the second scan finds zero remaining matches, with any scan error forcing `incomplete` (`:2432-2440`), a tool proving its own claim rather than asserting success. And nashsu's second test tier is worth the twenty lines: the same scenario objects that drive the fast mocked suite are replayed against a real model behind `RUN_LLM_TESTS=1` (`lint.real-llm.test.ts:1-32`), filtered to the scenarios that actually invoke the model, so the prompt gets a periodic regression check without slowing the gate.

**MinSpec today.** `CLAUDE.md`, `AGENTS.md` and `.cursorrules` are generated through a section-level 3-way merge (`merge-refresh.ts:1-16`) against hashes in `.minspec/template-baseline.json`, and those three files are explicitly **not** drift-gated: `merge-refresh.ts` preserves any `##` section the user modified and regenerates only unmodified ones, so drift there is a supported state. FATAL drift covers different files: Rule 12 covers the `gen-ci-templates.mjs` outputs (four CI workflows, `review-branch.sh`, `review-decide.sh`, `agent-context.sh`, `approval-provenance.py`, `canonical.py`, role prompts, `ai-review-guard.js`) and Rule 14 covers marker-fenced managed regions in `minspec-validate.yml` and `.minspec/hooks/*` (Input B §4). The harness prose is the un-gated surface, which is precisely why this lesson is worth doing. Input B verified once, by hand, that CLAUDE.md's three Invariants match `.minspec/constitution.md:7-9`. That is a measurement, not a test.

**The delta.** Assert in CI that each constitution invariant's lead sentence appears in the generated CLAUDE.md, that every `SPEC-NNN`/`DR-NNN` in CLAUDE.md resolves, and that a T3 spec carries the sections a T3 spec must have (today that is prose in a template with no checker, which is exactly the hole `validate_specialist_package` fills). This directly closes the hole CLAUDE.md names about itself ("this rule is itself prose, so it is model-trusted and will drift").

**Cost and risk.** See action 5 below: the invariant-text assertion collides with `merge-refresh.ts`'s deliberate preservation of user-modified sections, so it has to stay repo-local until that tension has a DR.

### L7. Typed provenance on inferred edges

**Technique.** SamurAI appears elsewhere in this document only as a source of failures, which loses its best idea: a two-pass graph with typed provenance on every edge. Pass 1 parses explicit `[[wikilinks]]` deterministically as `EXTRACTED` with `confidence: 1.0` (`build_graph.py:116-139`). Pass 2 asks a cheap model for relations the links missed, emitted as `INFERRED` (>=0.7) or `AMBIGUOUS` (<0.7), with the threshold both stated in the prompt and *recomputed defensively in the parser* (`:265,293`), so a model that self-labels wrong is corrected rather than trusted. Both edge classes live in one graph and stay distinguishable forever. Three smaller ones from the same repo: the free-versus-paid check boundary stated as a rule with a run order ("Run `health` first - linting an empty file wastes tokens", `CLAUDE.md:208`); phantom hubs as a *backlog* rather than an error (a dangling link referenced by two or more *distinct* pages is a ranked list of pages that should exist, `build_graph.py:374-402`, and note the same check done wrong by counting raw mentions sits 300 lines away at `lint.py:68-78`); and a JSONL checkpoint plus per-page content hash so an expensive semantic pass resumes instead of restarting (`build_graph.py:142-219`).

**The delta for MinSpec.** Explicit `implements:`/`epic:`/`relates_to:` refs are EXTRACTED; any model-suspected relation is INFERRED and never silently promoted to the same class. The checkpoint-plus-content-hash shape is exactly what a per-spec ai-review cache wants. Cost: a second edge class means every consumer (traceability, `next-task.ts`, the review webview) has to decide how to render it, and the honest default, showing inferred edges as suggestions the human confirms, adds a UI surface that does not exist today.

### L8. Authorship binding

**Technique.** atomicstrata is the only repo in the cohort that binds *who acted*, not just *what the content is*. Run records that authorize writes are HMAC-signed with a 32-byte project-local key at `.llmwiki/workflows/.runkey` (0600, gitignored, opened no-follow), computed over RFC-8785-canonicalized content minus the integrity field, compared with `timingSafeEqual` (`src/workflows/integrity.ts:130-153`), and the module header states the residual trust floor plainly: a local actor who can read the key can re-sign a forgery. Alongside it, the deny-versus-park split (`enforce-precondition.ts:27-59`): a *confirmed* precondition violation is a hard deny, an *unverifiable* witness (unreadable file, store fault) is still fail-closed but a different error type so the caller retries rather than terminally failing, and deny beats park when both occur. That is a refinement of MinSpec's invariant 2, not a contradiction of it. And the capability lattice: effective capability is the minimum of requested, granted, and a per-surface hard cap, with the gate predicate re-reading the hard cap directly rather than trusting the composed value (`workflows/authority.ts:45-126`).

**The delta.** This is the direct answer to the memory-store finding (`p-verd-reco`) that MinSpec's verdict records are forgeable in a public repo because `specHash` binds content and not authorship. A project-local signing key over the canonicalized approval record would bind the actor. Cost, and it is the reason this is a lesson rather than an action: a local key is exactly as strong as filesystem access, so it raises the bar against a careless agent and not against a determined one, and it adds a secret to a repo whose whole Tier-0 posture is "no secrets, works offline". Do not adopt it without a DR that states what threat it does and does not close.

### L9. Distribution: Agent Skill versus VS Code extension

Every one of the seven reaches agents without a VS Code extension: `claude plugin install` plus generated Codex and OpenCode mirrors with a sync-diff test (nvk `scripts/sync-codex-plugin.sh`, `tests/test-codex-sync.sh`); `bash install.sh --platform claude|codex|openclaw|hermes` with a post-copy verification loop that hard-fails if any manifest item did not land (sdyckjq `install.sh:305-317`); `npx add-skill` (Astro-Han); `npm i -g` plus an MCP stdio server (atomicstrata `src/mcp/server.ts:34-57`); `ok init` installing into whichever of eleven editors it detects, with a written rationale for deliberately *not* broadcasting into a shared skills root (inkeep `editors.ts:8-33,60-95`).

**MinSpec today** already does multi-host harness generation (CLAUDE.md, AGENTS.md, .cursorrules), though as L6 records those three files are preserved-on-edit rather than drift-gated. What is VS Code-bound is the human gate: approve, the review webview, diagnostics. What is *not* inherently VS Code-bound is the read-only oracle layer: `scripts/facts.ts` (five subcommands, documented strictly read-only at `facts.ts:28-32` because "the moment it can flip a status or mint an approval it becomes a forged-sign-off surface"), `validate-frontmatter.ts`, `reference-checker.ts`, `next-task.ts`, `canonical.ts` and its Python twin.

**Recommendation.** Keep approval in the extension, and extract the read-only oracles behind a stable, host-agnostic entry point so a Codex or Pi session gets the same answers a Claude Code session gets. The primary downside is direct and should not be glossed: CLAUDE.md today says MinSpec is a VS Code extension, not a CLI, and instructs never to write or suggest a `minspec` shell command. Extracting an oracle surface contradicts that rule, so it needs a DR that draws the line explicitly (read-only oracles portable, all mutation and all sign-off extension-only). atomicstrata's capability lattice (L8) is the model to copy for that line.

### L10. Ambiguous as a resolution state, for DR-053 v2 and #679

sdyckjq indexes pages by KB-relative **path**, not name, so two `Dupe.md` in different directories stay distinct, and a bare-name link to them resolves to status `ambiguous`, creates **no edge**, and reports every candidate rather than guessing (`wiki-link-index.js:30-48,128-137`). Severity policy is explicit: pending and non-canonical are warnings, broken/ambiguous/collision are errors (`:75-80`). It also has a typed "not yet written" link kind with a defined exit: `[to create: [[X]]]` parses as `pending`, and when the target appears the scan emits a `stale_pending_wrappers` entry naming the exact byte range to remove (`:342-347`).

**MinSpec today.** DR-053 v2 is accepted and unimplemented: `packages/shared/src/project-prefix.ts` implements v1 dash-joined refs only, has **zero non-test call sites**, and nothing loads `.minspec/project-prefixes.md` at runtime (Input B §2). Slash-form refs appear 14 times, only in the four files that specify the scheme. Meanwhile 59 live `ref-check` warnings include 14 pointing at global-register numbers (`DR-355`/`DR-359`/`DR-360`/`DR-362`) that do not exist in a local register stopping at DR-085, which is precisely the ambiguity DR-053 exists to fix. DR-053 already anticipated the prose-collision problem and refuses to auto-detect bare `FR3`/`R1` (`DR-053.md:154-176`, with `R1` measured 51 times and `M1` 82 times in prose).

**The delta.** Before #679 ships, fix `ambiguous` into the resolver contract as a first-class returned state that produces no edge and lists candidates, and adopt the fence-aware parsing sdyckjq uses (`wikilink-parser.js:35-98`) so a ref quoted inside a code fence is never treated as a real reference. That last point maps onto a known MinSpec failure: the guard that greps prose blocked git commands quoted inside issue bodies (`f-guar-grep.md`). Cost: it adds a state the UI has to render, and elided forms will hit it often enough to be visible, which is the correct outcome but will read as regression on first contact.

### L11. Golden corpus plus one generated defect fixture per rule

nvk's `tests/generate-defect-fixtures.sh:17-60` rsyncs a known-good 3-source wiki 17 times and applies one targeted `sed` mutation per lint rule, then asserts the golden corpus lints to zero findings *and* that each mutant trips its own rule. Inkeep does the corpus-versus-tool coupling version: `okf-conformance.test.ts` runs the real seed path into a temp dir and asserts conformance over the bytes actually written, for every starter pack. Astro-Han's `ExamplesSmokeTest` holds the shipped examples to the shipped linter. Two determinism primitives make date-dependent and clustering rules assertable at all: nvk's `LLM_WIKI_TODAY` env override for `today_date()`, with a hard `SystemExit` on a malformed value rather than a silent fallback (`scripts/llm-wiki:119-127`), and SamurAI's `louvain_communities(G, seed=42)` so a clustering result can be diffed across runs.

**MinSpec today** has 18 numbered corpus rules plus the `validateSpec` rule set, and is already ahead on one specific hole: Rules 16/17/18 each wrap in try/catch and print that the rule "validated NOTHING this run; do not read the green as a clean register" (`validate-frontmatter.ts:311,349,395`). The memory store also records both halves of the lesson: fixtures encode assumptions (a fixture faked `origin/HEAD` and left a guard inert), and coverage percentage hides decisions (99.29% statements with 22 uncovered decisions). The delta is one defect fixture per rule, asserting the rule fires. Cost: fixture maintenance, and the specific trap MinSpec already hit twice, so pair each fixture with an assertion that the *unmutated* corpus is clean, which is what catches an inert guard.

**One convergent design MinSpec already got right, worth noting as validation rather than a delta.** nvk requires `compiled-from: conversation` rather than an empty `sources:` list, so "this legitimately has no provenance" and "someone forgot" are distinguishable states and the linter refuses to guess between them (`linting.md:502`, which explicitly refuses to auto-add it because it is "a provenance claim that requires human judgment"). MinSpec's `implements: none` plus mandatory `implements_reason:` is the same design, in use on 11 specs, enforced as an error (`spec-validator.ts:784,812`).

## 4. Bounding context as the corpus grows

Four distinct mechanisms plus one measured failure mode, and MinSpec's exposure is the same shape.

**The strongest is atomicstrata's `src/context/budget.ts:1-33`:** a deterministic token estimator with a *documented trim order* (neighbors first, then source windows, then chunks, then content tiers, primary pages last), dropping whole array elements so the JSON stays valid, and returning a `trimmedSections` report so the consumer knows what was withheld rather than silently receiving less. That last property is the one that matters for a never-wrong product: an unreported trim is indistinguishable from an empty result.

**The cheaper versions.** sdyckjq does it at the prompt layer (`SKILL.md:408`: read ONLY the pages named in Step 1's `new_vs_existing.updates`; if a page exceeds 2000 characters, read only its frontmatter plus the sections you need). nashsu caps its generated index at a 200-entry recent section (`ingest.ts:1609-1623`). nvk ships `tests/budgets/token-budgets.json` plus `benchmark-token-efficiency static --check`, a free deterministic routing-cost gate and the only *measured* budget in the cohort.

**The negative controls are as useful:** sdyckjq's 49KB, 1136-line always-loaded `SKILL.md` with no progressive disclosure; inkeep's un-budgeted skill stack loading before every markdown operation; SamurAI pasting the entire node list into every per-page prompt (`build_graph.py:227`) for O(n²) cost.

**MinSpec's exposure**, already measured in Input B: `MEMORY.md` at 71% of its line cap, a 9,421-token reference corpus, and generated CLAUDE.md/AGENTS.md/.cursorrules that grow monotonically with no budget check anywhere. The cheap first move is nvk's: a checked-in budget file plus a static check, which costs nothing per run and turns a silent truncation into a red build. Downside: a budget file is another number that drifts, and setting it too tight converts every legitimate addition into a gate failure, so set it at the cap rather than at current usage.

## 5. Did anyone measure anything?

Nobody in the cohort measured *wiki quality*. Two measured their *checker*.

**atomicstrata is the only real harness:** `llmwiki eval` with seven CI-gateable thresholds, a 0-100 health score, and an LLM judge scoring citation support over a deterministic ~20-pair sample. Two techniques there are worth stealing outright: the judge cache key is `sha256(pairHash + sha256(JUDGE_SYSTEM + JSON.stringify(JUDGE_TOOL)) + model)`, so editing the judge prompt auto-invalidates every cached verdict, and previously-sampled claim hashes are retained so "score movement reflects quality change rather than sample turnover" (`citation-support.ts:60-79,160-188`). It has no human-labelled calibration set, so the judge's own accuracy is asserted, not measured.

**nvk's promptfoo suite** (28 behavioural cases with `llm-rubric` and per-case cost caps, roughly $2-5 per run) is the cohort's only behavioural eval, and it requires an API key, so in practice it never runs.

**The two genuine field measurements in the whole cohort are nashsu's:** roughly 45% of generated entity pages went to disk with unparseable frontmatter before boundary sanitization (`ingest.ts:1935-1938`), and the confirmed observation that mid-size models rewrite a page when asked to return it whole (`enrich-wikilinks.ts:8-25`). Both are the reason its bounded-patch design exists, which is why L2 is the lesson with the strongest empirical backing in this document.

**For MinSpec:** ai-review has the same unmeasured-judge problem, and the same fix is available for free. Key cached verdicts on a hash of the review prompt plus the model id, so a prompt edit invalidates the whole verdict corpus instead of leaving stale passes standing. Downside: it will invalidate a lot at once, and the first prompt edit after adoption re-runs every open PR's review, which costs real money on a day nobody planned for.

## 6. Human and agent co-authoring the same file

This axis matters more here than anywhere in the cohort: MinSpec's corpus is human-co-authored, the autonomous drain writes to it, and DR-051 puts approvables directly on main. Four answers on offer.

- **inkeep** makes every doc a live Yjs CRDT so human and agent edits converge, and mirrors writes to a shadow git repo with per-agent attribution. Highest fidelity, highest cost, and it requires a running server, which is disqualifying for a Tier-0 offline tool.
- **nashsu** forces locked scalars back after any LLM merge and rejects a body under 70% of the longer input (`page-merge.ts:29-53,168-178`). This is L2, and it is the one that fits a file-on-disk model.
- **nvk** is the cheapest and the best structural fit: "Indexes are a cache, not a source of truth ... rebuilt on read when stale. This makes the wiki concurrent-safe - multiple sessions can write simultaneously without locks" (`indexing.md:19`). Anything derived is never a write target, so there is nothing to contend over.
- **atomicstrata** has the worst and says so, regenerating whole pages and hoping human edits survive at the model's discretion.

**For MinSpec**, the nvk rule is the one to state explicitly, because the concurrency failures the memory store records are all writes to derived or shared state: many sessions on one checkout, and a written settings key vanishing minutes later (`p-conc-sess3`). Recommended framing: nothing derived is ever hand-edited or committed as a subset, and every derived artifact is rebuilt on read. Downside: rebuild-on-read costs latency in the editor path, and for anything expensive (a full corpus validate) it needs a staleness check rather than an unconditional rebuild, which reintroduces a cache with its own invalidation bug.

## 7. What not to copy

**The pattern's headline claim. Zero of seven implement contradiction handling in code.** This is not a matter of emphasis, it is measurable in each of the seven:

- nashsu: the ingest prompts are never given any existing page body. `buildAnalysisPrompt`/`buildGenerationPrompt` receive only schema.md, purpose.md, overview.md and index.md (`ingest.ts:1035,1067`), and index entries are `- [[slug]] - title` (`:1594`). The "Contradictions & Tensions" prompt section is the model comparing a source against a list of titles. The backstop semantic lint sees the first 500 characters of each page (`lint.ts:244`).
- inkeep: `supersedes:` / `superseded_by:` have **zero enforcement**; a grep across `packages/*/src` returns only unrelated UI code, and `superseded_by` appears in no TypeScript file. Two skills spend a full step on "both directions or the log lies from one side" and neither direction is verified. `stale_after` is documented as non-enforcing in its own schema (`schemas.ts:213`). The weekly contradiction lint is a prompt the user is told to type.
- nvk: the entire contradiction policy is one prose line, "**Honest disagreement**: When sources disagree, note the disagreement rather than picking a side" (`references/compilation.md:107`). The incremental-merge procedure is six prompt bullets (`:76-83`), and `/wiki:refresh`'s `skip|update|flag|retract` menu is wholly model-executed (`grep -n 'librarian\|audit' scripts/llm-wiki` returns only path-allowlist constants).
- SamurAI: contradictions are `print()`ed to the terminal (`ingest.py:272-277`) and never persisted. Its entity pages are regenerated by `path.write_text()` with no read-before-write (`_utils.py:38-42`), so "every new source makes the wiki richer" is clobber-and-hope.
- sdyckjq: `contradictions` is validated as an array (`validate-step1.sh:34`) and then the file is deleted (`SKILL.md:399-402`). Zero consumers.
- Astro-Han: the linter is coded to skip Status blocks (`check_evidence.py:225-233`), which is exactly where corrections live. The researcher injected a fabricated number and a fabricated quote inside one and got zero findings.
- atomicstrata: `contradicted_by` slugs are never validated to resolve to a real page (grepped across `src/`), so a hallucinated slug becomes permanent frontmatter and a permanent minus-2 health deduction with no rule that can say the target does not exist.

MinSpec's `status-claim.contradicted` rule (`spec-validator.ts:1493`, `validateStatusClaims:1468`) already does more than any of them: it checks a prose claim that SPEC-N is implemented against the referenced artifact's real status. **Do not build a semantic contradiction engine.** Extend the class of claims that can be cross-checked against a computable oracle instead, which is L4.

**What to build instead, composed from four real partials.** inkeep's `entity-vault` pack splits every page at an explicit `--- timeline ---` separator: above it is mutable synthesis you rewrite freely, below it are append-only dated bullets (`- **YYYY-MM-DD** | source | @author - evidence. Confidence: ...`) that are never edited, which buys incremental maintenance without either losing history or fossilizing the summary. Astro-Han encodes epistemic state inline as typed blocks under the affected claim (`> **Status: Outdated** (YYYY-MM-DD)`, `> **Status: Disputed**`, `references/article-template.md:17-21`) under the rule "keep the old claim for the record ... Never silently rewrite history" (`SKILL.md:96`). atomicstrata's merge reconciliation is three mechanical lines worth copying verbatim (`extraction-merge.ts:35-63`): confidence takes the *min* so the most pessimistic value wins, `provenanceState` becomes `merged` once two sources are involved, and `contradictedBy` unions by slug. Composed, those give MinSpec a cheap shape for the case it actually has, a spec whose owned code moved or a DR contradicted by a later one, with no semantic engine: an append-only dated section, a typed status block, and a min-rule on any confidence-like field. Downside: an append-only section grows without bound and nothing prunes it, so it needs an archive rule before it is worth adding to every spec.

**LLM-judged lint over truncated inputs.** nashsu at 500 chars per page, SamurAI at `pages[:20]` in arbitrary `rglob` order truncated to 1500 chars (`lint.py:274-278`). These cannot find a contradiction between page 5 and page 60 by construction.

**Star counts as an engineering signal.** nashsu has 16,621 stars on a repo that vendors Karpathy's gist verbatim at its root, and its README claims `overview.md` is "regenerated on every ingest" while the file is written exactly once as a stub at project creation (`src-tauri/src/commands/project.rs:183-194`) and no writer exists in TypeScript or Rust. Its 143 test files, property tests and scenario suites are gated by a CI that runs `vite build` and `cargo build` and nothing else (`.github/workflows/ci.yml:52-62`). SamurAI has 3,402 stars on one squashed commit, no tests, and a CI whose only job is regenerating a star-history chart. Astro-Han has 1,965 stars on 28 total commits, with the flagship feature landing in a single 3-hour session that included the commit "fix: make the evidence checker actually check"; its 765-line, 52-test suite is mentioned in neither README nor SKILL.md and runs in no CI.

**Reporting dressed as gating.** `check_evidence.py:28` states outright that "the exit code carries no information; the report is the interface". `write-advisory-links.ts:12` is explicit that a broken local target never blocks the write. SamurAI's `--validate-only` prints every broken link then unconditionally `sys.exit(0)` (`ingest.py:348`), the exact silent-gate anti-pattern constitution invariant 2 exists to forbid. nvk's linter exits 1 on any *suggestion* (`llm-wiki:1651-1689`), which trains users to ignore the exit code.

**Provenance edited by string similarity.** nvk's `resolve_source_ref` accepts an 8-character substring match (`llm-wiki:1230-1252`) and `fix_source_references` then rewrites the article's `sources:` frontmatter to that guess (`:1173-1211`). Under no circumstances should a MinSpec autofix rewrite an `implements:` or `relates_to:` value from a fuzzy match.

**Feature breadth.** atomicstrata ships Ed25519 template signing with rotation and revocation, OKF import/export, an event log, workflows, artifacts, and Configurable Lifecycle Profiles, from one maintainer (118 of ~143 commits), with `workflow-*` mutation kinds declared in the planner vocabulary and `not-implemented` in the executor (`planner.ts:14`, `executor.ts:84-204`). Declared surface already exceeds built surface. Inkeep ships eight starter packs of which two have conformance tests.

## 8. Licensing, because it constrains two recommendations above

Three of seven have a broken or absent grant. nashsu's README says GPL-3.0 while the GitHub API reports NOASSERTION and the bundled MCP server's `package.json` says MIT: three signals in one repo. sdyckjq's `SKILL.md` frontmatter says `license: MIT` and the README badges MIT linking to a root `LICENSE` that does not exist (the only one is `workbench/LICENSE`, "Copyright (c) 2026 Kiro"), with the API reporting `license: null`. inkeep is GPL-3.0-or-later, which rules out lifting its code into a permissively licensed extension at all. Both must be re-implemented from the described behaviour rather than copied, which is a real cost in hours and should be budgeted as such.

## 9. Could MinSpec's corpus be published as one of these?

The publishable artifact is not the corpus, it is the **gate set**. `validate-frontmatter.ts` (18 rules), `reference-checker.ts`, `canonical.ts` plus its Python twin, and `facts.ts` together constitute the only working corpus linter in this space with a merge gate behind it, and every one of the seven ships a weaker version of it.

The interop hook already exists. Google's Open Knowledge Format v0.2 is a real JSON Schema in inkeep (`okf-frontmatter/schemas.ts:4-19,59-216`) with `sources[]`, `generated: {by, at}` using a `<producer>/<version>` actor grammar, `verified[]`, and `status: draft|stable|deprecated`; atomicstrata ships OKF import/export. An OKF mapping for MinSpec spec and DR frontmatter would make the corpus consumable by that ecosystem with no MinSpec-side runtime and no network call.

**The honest blocker before recommending publication:** publishing the corpus means publishing the verdict records, and the memory store already records (`p-verd-reco`) that in a public repo those are forgeable, because `specHash` binds content and not authorship. That is the same gap L8 addresses. Recommended sequencing: publish the gate set and an OKF mapping, hold the verdict records back until authorship binding exists. Downside of publishing the gates alone is that the linter without the corpus is harder to evaluate, so adoption will be slower than a splashy corpus dump would be.

## 12. Concrete next actions

Each is independently shippable. Ordered by value per unit of work.

1. **Close the DR-side closed-set asymmetry.** `spec-validator.ts:527` (`CLOSED_SET_FIELDS`) asserts both directions (required implies present, present implies valid) for **specs only**. DR frontmatter has four rules over it (Rule 6 DR sequence non-fatal, Rule 8 `validateDrIndexStatus` INDEX-versus-frontmatter status in both directions FATAL, Rule 16 claims-to-amend-but-didn't FATAL, Rule 17 DR id collision FATAL) but no closed-set table, so `status:` is compared against the INDEX and never against a legal value set. That is why `DR-011` carries `status: active` outside the 82-accepted/3-superseded set, and why both `approved_by` and `approved-by` exist (Input B §1, §7.5). Add a DR closed-set table and wire it as a new numbered rule in `scripts/validate-frontmatter.ts`. **Recommended**; downside is that it will fail the corpus on day one, so land the data fix and the gate in one PR and follow L3's rule (`linting.md:3-44`): express the `approved-by` rename as an append-only alias in the rule, never as a one-off script.

2. **Record owned-file blob shas at approve time.** Extend `ApprovalRecord` (`approval.ts:60-70`) and `approveSpec` (`:517`) to snapshot the git blob sha of each path in the resolved `implements:` set, then add a `facts.ts drift <SPEC>` subcommand that prints stored versus current, following the `facts hash` pattern of showing what it ignored. **Recommended read-only first**; downside is a schema change to 57 committed sidecars, so make the field optional and treat its absence as "not measurable" rather than "no drift", which is the omit-to-skip discipline `validateSpec` already uses at `:694-727`.

3. **Add a citation-fidelity tier to `reference-checker.ts`.** Line-count bound for `path:NN`, and backticked-literal containment within the plus-or-minus-one-line window already used by `hasDanglingParkRef` (`spec-validator.ts:648`). Publish the frozen candidate set in the module docstring. **Recommended at warning severity**; downside is added noise on top of 140 existing warnings (59 of them ref-check), so pair it with a triage pass on the 14 global-register refs so the new warnings are not born into a red corpus.

4. **Regenerate `MEMORY.md` with fingerprinted curation regions, plus a cap gate.** Port `summaryFingerprint` / `renderDrEntry` / `mergeDrIndex` (`adr-manager.ts:739,794-830,883`) to a personal script under `~/.claude`; add a check that fails at 90% of 200 lines or 25,000 chars, and a prefix-to-`metadata.type` assertion that closes the three known filing errors. **Recommended**; downside is that this lives outside MinSpec's blast radius by constitution invariant 3, so it is personal tooling that reuses a MinSpec technique and must not be presented as, or grow into, a shipped feature.

5. **Prompt-corpus test for the generated harness.** Assert each `.minspec/constitution.md:7-9` invariant lead sentence survives into the generated CLAUDE.md Invariants section after `merge-refresh.ts`, and that every SPEC/DR reference inside CLAUDE.md resolves. **Recommended**; two downsides. It pins wording, so intentional rewordings become two-file changes.
