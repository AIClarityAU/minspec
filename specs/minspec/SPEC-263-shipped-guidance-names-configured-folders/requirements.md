# SPEC-263: Shipped agent instructions name the folders the project configured

> **This is a SPECIFICATION ONLY.** Written for issue #2682 (part of #2675, the RCDD on values baked into managed files). Nothing is built until a human reads it, resolves [Decisions needed (Clarify)](#decisions-needed-clarify), and approves it.

## In plain terms

A project can move its specs and decision records (`specsDir`, `decisionsDir` in `.minspec/config.json`). The instructions MinSpec ships to agents still say `specs/` and `docs/decisions/`. An agent that follows them opens a folder that does not exist in that project.

## Measured state (this base)

Read from the code, not inferred:

- `packages/minspec/src/lib/config.ts:152-153` defaults `specsDir: 'specs'`, `decisionsDir: 'docs/decisions'`; `:242-251` already lets callers override both. Config is available to the extension; it is simply not passed to the shim builders.
- `packages/minspec/src/lib/slash-commands.ts`: `COMMAND_GUIDANCE` is a module-level constant (`:116`). Its `constitution` body names `docs/decisions/` (`:123`), `specify` names "the project `specs/` directory" (`:131`), `plan` names `docs/decisions/` (`:152`). `buildCursorShim()` (`:225`) takes no argument.
- `packages/minspec/src/lib/template-registry.ts:977-982`: managed-region content is "NOT Handlebars-rendered - project-independent and pinned", so no project input reaches it.
- `scripts/roles/architect.md:18`, `:30-32` name `specs/` and `docs/decisions/`; `:39` names `packages/` and `tests/`; `:53` names `npm run validate`. These last two describe THIS repository's layout and scripts, which an adopter does not have (the #1522 class).

## Functional requirements

- **FR-1 Configured folders.** Every shipped agent instruction that refers to the specs folder or the decisions folder resolves it from the project's effective config (`specsDir`, `decisionsDir`) at write time, or names it by role (e.g. "the project's specs directory, per `.minspec/config.json`") so it is true for any config. Scope: the `constitution`, `specify`, `plan` slash-command bodies, the Cursor rules file, and any other generated shim found by the FR-4 sweep.
- **FR-2 Default unchanged.** With default config the generated bytes of every affected file are unchanged, or change only in a way FR-1 requires and the Plan lists. No adopter on defaults sees churn it did not need.
- **FR-3 Refresh follows config.** When `specsDir` or `decisionsDir` changes, the next harness refresh rewrites the affected managed regions/shim files, and the refresh manifest/consistency check treats a stale folder name as drift (not as "up to date").
- **FR-4 Sweep, not one-site fixes.** A deterministic check (test or validator rule) scans every shipped managed-region template, slash-command body, and shipped role prompt for the literal default folder names and for this-repository-only assumptions (`packages/`, `tests/`, `npm run validate`), and fails unless each occurrence is on an explicit allow-list with a reason. This fixes the property, not the three cited sites.
- **FR-5 Role prompts.** `scripts/roles/*.md` content shipped to adopters does not assert this repository's layout or scripts as fact. Per-role file allowlists and required-check commands are either generic by role, or sourced from project config, or marked as this-repo-only and not shipped. (Whether role prompts ship to adopters at all is Decision D2.)
- **FR-6 Offline.** No change adds a network call (constitution invariant 1).
- **FR-7 No silent fallback.** If config cannot be read when generating, the writer uses the documented defaults and says so visibly; it never writes a guessed or empty folder name.

## Acceptance Criteria

- [ ] **Moved folders honoured** - in a scaffold with `specsDir` and `decisionsDir` moved, none of the generated slash commands or the Cursor rules file name `specs/` or `docs/decisions/`; they name the configured folders. (FR-1)
- [ ] **Defaults stable** - a default-config scaffold's generated files match the pre-change bytes except where the Plan lists a justified difference. (FR-2)
- [ ] **Config change refreshes** - editing `specsDir` then refreshing updates the shim files; the consistency check fails beforehand. (FR-3)
- [ ] **Sweep fails closed** - adding a new literal `specs/` to a shipped template without an allow-list entry fails the check, with the file and line printed. (FR-4)
- [ ] **Role prompt honest** - `architect.md` no longer states `packages/`, `tests/` or `npm run validate` as facts about an adopter's project. (FR-5)
- [ ] **Offline** - no new network call. (FR-6)

## Invariants this must not break

- Constitution invariant 1 (offline) and invariant 3 (blast radius: only repos with `.minspec/` are touched).
- Invariant 2 (no silent gate): FR-4's sweep must fail visibly, and FR-7 forbids a swallowed config error.
- Managed-region byte stability for projects whose config is unchanged (FR-2).

## Costly to Refactor

1. **Managed-region contract (high).** Today a managed region is project-independent and pinned (`template-registry.ts:977-982`). Allowing project input changes the refresh/hash contract for every managed file. Check: how the harness-refresh manifest hashes a region that now varies by config.
2. **Role-prompt shipping boundary (medium).** Deciding that role prompts are or are not adopter-facing shapes the dispatch pipeline. Check: which consumers read `scripts/roles/` outside this repo.
3. Everything else - Low: string substitution inside generated text.

## Decisions needed (Clarify)

**D1 - How to make the text true for any config.**
- **(a) Thread config into the shim builders** `(rec)`: exact folder names appear, agents need no lookup. Cost: managed regions become config-dependent, so FR-3's refresh/drift rule is mandatory and the pinned-byte contract changes.
- **(b) Name folders by role** ("the specs directory in `.minspec/config.json`"): no contract change, never stale. Cost: one extra lookup by the agent, vaguer text, and an agent that skips the lookup falls back to guessing `specs/`.
- **(c) Both**: exact names plus a pointer to config. Cost: longest text, more tokens per command (tenet 2).

**D2 - Do `scripts/roles/*.md` ship to adopters?** If yes, FR-5 applies and the layout/script assumptions must go generic or config-sourced. If no (dev-time only for this monorepo, per CLAUDE.md "Agent Dispatch"), the fix is to mark them this-repo-only and exclude them from shipping, and `architect.md:18,30-32,39,53` are correct as written. Recommendation: confirm from the packaging manifest before choosing; cost of guessing wrong is either needless rewriting or a shipped false signpost. Which is true was not verified here.

**D3 - Allow-list granularity for the FR-4 sweep.** Per-file reason (rec, auditable, cost: churn when text moves) versus per-pattern (cheap, cost: hides new unintended hits).

## Out of scope

Other baked-in values in managed files beyond folder names and this-repo layout assumptions; they are tracked under #2675. The #1522 general class (shipped guidance true only under this repo's config) is covered here only for the named sites and the FR-4 sweep.
