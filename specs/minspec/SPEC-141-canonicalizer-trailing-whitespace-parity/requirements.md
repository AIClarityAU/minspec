# SPEC-141: The two canonicalizers strip exactly the same trailing characters, and a test proves it on input the corpus does not contain

Issue: [#1668](https://github.com/AIClarityAU/minspec/issues/1668). Siblings: #1669 (the Python
golden suite was not run by CI - now wired through `canonical-golden-python.test.ts`), #1481
(should `implements:` enter the hash - needs this parity to be real), #2404 / SPEC-095 (the
leading U+FEFF handling; see Boundaries).

## Context

The approval hash is computed twice: `packages/shared/src/canonical.ts` (extension) and
`scripts/hooks/canonical.py` (hook, also embedded in the extension). They must agree
byte-for-byte, or the hook and the extension disagree about whether an approval is fresh.

Step 6 of canonicalization strips per-line trailing whitespace with each language's native
definition: `ln.replace(/\s+$/, '')` (`canonical.ts:121`) and `ln.rstrip()`
(`canonical.py:79`). The sets differ by exactly four code points (issue measurement, with a
control; recomputing the set difference from the language definitions is AC-1):

| Code point | JS `\s` | Python `isspace()` |
|---|---|---|
| U+FEFF | strips | keeps |
| U+0085 | keeps | strips |
| U+001C, U+001F | keeps | strips |

(U+001D and U+001E are in Python's set too; the issue lists the range U+001C-U+001F. The
fixture work in FR-3 covers all four of U+001C-U+001F, not only the two the issue names.)

The comment at `canonical.ts:117-120` asserts "matches Python's `str.rstrip()` byte-for-byte".
That is false, and it is prose - model-trusted. The two tests that run in CI compare only over
`specs/**/*.md` (`canonical-parity.test.ts:73-82`) or check the embedded copy's freshness
(Rule 12, `validate-frontmatter.ts`), so neither can see a divergence no spec contains.

**Impact today: none (latent).** The issue scanned all 99 specs for the six code points: zero
hits. A stray trailing U+FEFF in a spec would make the hook and extension disagree.

## Requirements

- **FR-1 - One explicit trailing-whitespace set.** Step 6 in both twins MUST strip an explicit,
  enumerated set of code points, not the language-native `\s` / `isspace()`. The set is written
  once as data (a documented list of code points) and each twin implements exactly that list.
  Which members: see DQ-1.
- **FR-2 - Same end-of-text collapse.** The trailing newline-run collapse MUST be implemented so
  that it cannot differ between languages on `$` semantics. Either keep `\n*$` in both and prove
  equal by golden (FR-3), or replace with an explicit trailing-`\n` strip that does not use `$`.
  (My reading, unverified by execution: `\n*` is greedy so Python's `$`-before-final-newline
  match is consumed first, making the two equal; the issue says no input diverged.)
- **FR-3 - Pinned adversarial goldens.** Add `.input`/`.expected` pairs to
  `packages/minspec/tests/fixtures/canonical/` for: trailing U+FEFF, U+0085, U+001C, U+001D,
  U+001E, U+001F (one pair each, or a documented combined pair plus singles); a code point on
  each side of the boundary that both languages agree on (U+00A0, U+2028, U+3000 - strip) and
  one both keep (e.g. U+200B); the `$` case (multiple trailing newlines, a final line holding
  only whitespace, and an input with no trailing newline). `.expected` is hand-pinned, not
  generated by either twin. Both existing suites already read this directory.
- **FR-4 - Enumerated-set cross-check.** A test MUST iterate every code point U+0000-U+FFFF (or
  the full Unicode range, see DQ-3), run both twins on `"x" + cp`, and assert the output
  agrees. This is what closes the class: a fifth divergent code point fails without anyone
  having to think of it. The test fails closed if `python3` cannot run (constitution
  invariant 2; same posture as `canonical-golden-python.test.ts`), never skips.
- **FR-5 - Embedded copy regenerated.** `scripts/gen-ci-templates.mjs` embedded copy of
  `canonical.py` MUST be regenerated so Rule 12 stays green.
- **FR-6 - The false comment is replaced.** The comment at `canonical.ts:117-120` MUST state the
  true property and name the test that enforces it (FR-4). The `canonical.py:76-78` comment
  ("str.rstrip() == JS trimEnd") is also false and MUST be corrected in the same pass.
- **FR-7 - Hash-change disclosure.** Any input whose canonical form changes under FR-1 MUST be
  listed in the PR (expected: none in the corpus). A measured recomputation of `specHash` for
  every file under `specs/`, before and after, MUST show zero differences (AC-3), so no existing
  approval goes stale.

## Boundaries

- **Leading U+FEFF is out of scope.** SPEC-095 / #2404 own what the hash does with a *leading*
  mark. This spec concerns *trailing* characters per line only. If #2404 has landed or lands
  first, FR-3's FEFF goldens are written against the merged behaviour; the two must not
  contradict. Order: whichever merges second rebases the fixtures.
- **#1481 (`implements:` in the hash)** changes the strip list for frontmatter keys, not this
  step; it depends on this spec but is not absorbed.
- No change to which lines are stripped (frontmatter lifecycle keys), only to what counts as
  trailing whitespace.

## Decisions needed (Clarify)

- **DQ-1 - Which code points does the shared set contain?** The two native sets differ on four
  (FEFF; 0085, 001C-001F).
  - **Option A - the intersection (rec).** Strip only what both already strip. Fail-safe: the
    canonical form never hides a content change that either twin currently keeps; for a file
    that has one of the four, the twin that used to strip it now keeps it, so that file's hash
    moves on that side only. Cost: a trailing U+0085/001C-001F or U+FEFF now makes an
    otherwise-whitespace edit stale an approval (a harmless false "stale", and the corpus has
    zero such files, so no existing approval moves).
  - **Option B - the union.** Strip all four everywhere. Cost: widens the set of invisible edits
    that do NOT stale an approval (a trailing BOM or control character could be added to an
    approved spec unnoticed), and each twin's output changes for its currently-kept characters.
  - **Option C - Python's set minus the controls (keep 0085; drop 001C-001F and FEFF).** Not
    recommended: splits the difference with no principle.
- **DQ-2 - Share the set via a generated file, or just duplicate the list and test it?** The
  issue says "the definition lives in one place". The twins cannot import each other (one is
  embedded in the extension, one is a standalone hook). **Option A (rec):** each twin carries
  the literal list; FR-4's sweep is the shared enforcement. Cost: two copies to edit, caught by
  FR-4 if they drift. **Option B:** a generated constants file both read. Cost: a new generator
  and a new Rule-12-style freshness check - more machinery than the problem.
- **DQ-3 - Sweep range for FR-4.** **Option A (rec):** U+0000-U+FFFF (BMP), fast, covers every
  known whitespace code point. Cost: astral code points untested (none are whitespace).
  **Option B:** all of U+0000-U+10FFFF. Cost: ~1.1M spawns or one batched call; batching is
  needed either way.
