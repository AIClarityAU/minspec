# SPEC-130 - Tasks

The order below is the order of work. Each task is one agent run: one concern, a few files,
its own test, and green on landing, so no task leaves a red required check on `main`. The
plan is [design.md](design.md); the contract is [requirements.md](requirements.md).

Every backticked path in this file is a file this change edits or creates. Files it only
reads (the approval reader, the spec gate, the approval-integrity script, the generator
script, the Python golden suite) are named in prose, so the spec gate's ownership signal
stays as narrow as the change.

Common to every task:

- Tests run as `npx vitest run <file>`, the form CI uses, not only `npm test`.
- No hashing call site is in any allowlist (FR-4), and no approval sidecar is written
  (INV-7). If a task appears to need either, stop with `DEEPER:`.
- If the spec gate denies an edit because another, unapproved spec declares the file, stop
  with `DEEPER:`; never route around the gate.
- Nothing written may use the three words DR-087 (integrity words are claims) forbids, or
  describe a tick as checked by the tool (FR-10).
